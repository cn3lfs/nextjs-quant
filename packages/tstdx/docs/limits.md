# 实网边界

**实现了一个接口，不等于它在公网节点上可用。** 这一页记录实测状态，带日期。读的时候注意日期：公共节点的可用性会变，这里的结论不自动延期。

## 为什么要单列这一页

通达信的公共行情节点没有服务承诺。常见的失败形态是**握手成功但正文为空**：TCP 连上了、三帧握手过了、请求也发出去了，服务器回一个空正文。这类节点用 `pingAll` 测不出来，必须跑业务探测。

所以本包把三件事分开：

| 判断             | 方法                                        |
| ---------------- | ------------------------------------------- |
| 端口与握手可用   | `pingAll`                                   |
| 行情正文可用     | `probeHosts`（额外测证券数量、五档、日 K）  |
| 拿一个可用客户端 | `fromBestHost({ requireMarketData: true })` |

## 2026-09-15：握手帧修复

第三条握手帧（`0x0FDB`）末字节改回 `0x05` 后，43 个客户端主站的日 K 与五档恢复。同节点单变量实测：改成 `0x02` 时握手仍有应答，但 K 线与五档**没有正文**。该字段的正式语义未知。

在此之前记录的"K 线与五档失败"属于该 bug，不是协议变更。

## 2026-09-15：财务字段口径修正

与本地专业财务包 `gpcw*.dat` 交叉核对（sh600519 / sz000002 / sz300750 / sz000001）后修正：

- **金额字段单位是千元**，×1000 得元。20 个金额字段全部吻合到 float32 精度。此前按万元 ×10000 会整体**放大 10 倍**。
- 总股本与流通股本是万股，×10000 得股。
- 股本结构子项（国家股、发起人股、法人股、B 股、H 股、职工股）**语义已被复用或错位**：sh600519 的法人股大于总股本、sz000002 的发起人股为负、职工股槽位的值实际等于每股收益。一律保留协议原值不换算。
- `updatedDate` 是**快照更新日，不是报告期**（实测 20260815 / 20260828 / 20260829 / 20260914 均非季末），据此年化没有依据。

详见[字段与单位](./api/fields.md#财务快照-tdxfinance)。

> **升级提醒**：如果你缓存过修正前版本产出的金额，必须重算。

## 2026-09-14：接口可用性矩阵

基准节点 `180.153.18.170`、`124.71.187.122`、`115.238.56.198`，共 165 个调用样本：96 个非空/控制成功、51 个异常、12 个空、6 个批量失败对象。每节点分布均为 32/17/4/2。

### 节点之间会不一样

- `124.71.187.122` 的 F10 栏目正文 12796 字符，`115.238.56.198` 为 7961。
- 历史逐笔分别是 4262 / 4412 条。

这些数字是**该节点分页返回至空页的长度**，不是跨节点的全市场成交完整性认证。**不要把多个节点的结果悄悄合并成一条"权威序列"。**

### 已知的数据差异

宁德时代的当日分时与历史分时在午休交界处有两个点不同，Rust 直接接口同样如此。本包不混合这两种序列，也不做平滑。

## 使用建议

1. 启动时跑一次 `probeHosts`，把不可用节点排除掉，别等业务请求时才发现。
2. 把"抛错"和"返回空"分开处理。本包在协议异常时抛错、在服务器确实回空时返回空数组——这是两种不同的事实。
3. 盘后不要指望当日逐笔有数据。
4. 北交所走 `stocks("bj")` 时准备好超时。
5. 任何跨节点的数据拼接都要先想清楚完整性由谁保证。
