# 测试与验证入口

从仓库根目录运行命令；移动脚本不改变工作目录或其数据路径约束。

| 目录                     | 用途                                       | 运行方式与边界                                                                                                              |
| ------------------------ | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 各业务目录的 `*.test.ts` | 自动化契约、行为与回归测试                 | `pnpm test`；全套工程检查用 `pnpm check`                                                                                    |
| `helpers/`               | 自动化测试共用的输入生成器、断言和受控替身 | 由测试导入，不作为独立造数命令                                                                                              |
| `fixtures/`              | 固定输入文件                               | 保持原始字节，不格式化或刷新快照来消除失败                                                                                  |
| `fixtures/seed/`         | 生成隔离验收数据库或目录的脚本             | 按脚本要求设置隔离 `QUANT_DATA_DIR` 后从根目录用 `pnpm exec tsx tests/fixtures/seed/<文件>`；这是可执行代码，仍参与格式检查 |
| `perf/`                  | 查询、序列化、文件读取、HTTP 与内存测量    | 按单个脚本说明运行；HTTP 测量须先核验隔离服务，不能指向默认用户库或未知既有服务                                             |
| `manual/`                | 人工核对、完整性审计、负对照与专用清理工具 | 不是自动回归；部分工具依赖指定数据、端口或既有交付场景，运行前核对前置条件，禁止整目录批量执行                              |
| `browser/`               | 真实组件在浏览器中的行为验证               | `pnpm test:browser [name-filter]`；`browser/fixtures/` 仅供组件验收加载，不作为 runner 用例                                 |
| `e2e/`                   | 生产构建上的页面、API 和 worker 验收       | `pnpm e2e`、`pnpm e2e:p0`、`pnpm e2e:p1`、`pnpm e2e:visual`；先 `pnpm build` 与 `pnpm desktop:prepare`                      |

测试根目录只保留全局设置 `global-setup.ts`、`setup-data-dir.ts` 和本说明。新脚本按职责归位，不再放回根目录，也不保留旧路径转发文件。

`perf/` 脚本是测量工具，不是历史性能证据。移动文件本身不代表每个脚本已按当前业务重新验收；数据和负对照必须与具体测量结论对应。`e2e/perf-budgets.json` 保留已有预算，不为获得通过而放宽阈值；当前通过与失败以交付记录为准，通用 E2E 不代替全站视觉及桌面验收。

`pnpm e2e` 每次启动独立生产服务，不复用未知端口上的既有服务，也不需要人工准备账户库。工作负载由 `e2e/workbench-fixture.ts` 生成：6,154 个合成证券、通过现行导入器录入的 `big`（2,222 笔、20 只）和 `big10k`（9,418 笔、100 只）账户；图表设置另复用固定 `czsc-sse.json` 输入。三年因子预算按原全市场规模核验；生成器单元测试显式使用最小 100 只，只验证契约，不作为性能证据。合成交易不代表历史行情或策略业绩。执行质量用例只使用 `big10k`，避免预热 `big` 后把缓存读取误称为复盘计算耗时。公式用例跟踪页面 URL 中的本次任务 ID；空闲等待读取全部任务计数，接口失败立即报错。

通过 `E2E_DATA_DIR` 指定 `.test-data` 下的独立任务子目录（默认 `.test-data/workbench-acceptance`），`E2E_PORT` 指定端口。路径在 Playwright 清空结果目录前校验，拒绝越界和目录链接；该目录内保存固定输入说明、`report.json`、失败跟踪和结果。浏览器请求仅放行经核对的本地读取与计算，外部行情明确返回离线状态，未分类接口使测试失败；不发送真实通知、不交易、不调用模型。三个专项配置分别保留 core/pool 数据场景。

所有本次检查数据、日志和截图集中在一个 `.test-data` 任务目录；同时设置 `TEMP`、`TMP`、`TMPDIR` 可使使用系统临时目录的工具归入同一任务。脚本中的特定路径保护仍须满足，不能删除保护或以用户库验证。清理按用户要求提供精确范围、默认预演的手动脚本。
