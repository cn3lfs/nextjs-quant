# S 阶段：RPS 相对强度排名

生效日期：2026-09-10。来源：用户要求加入 RPS 排序，参考「陶博士 RPS」。

## 0. RPS 是什么

欧奈尔的 Relative Price Strength，陶博士引入 A 股并推广。**横截面排名指标**：

```
T = (复权收盘[d] / 复权收盘[d-N]) - 1        # 个股 N 日涨幅
对证券池内所有股票的 T 排序
RPS = (1 - 排名 / 总数) × 100
```

RPS = 90 表示涨幅超过池内 90% 的股票。

| 项 | 取值 | 依据 |
|---|---|---|
| 个股周期 | **5 / 10 / 20 / 50 / 120 / 250** 日 | 50/120/250 为陶博士 A 股口径；5/10/20 短期由用户追加 |
| 行业周期 | **5 / 10 / 20 / 50 / 120 / 250** 日 | 陶博士本人行业只用 20/50/120（认为行业 250 强时个股往往已涨完）；用户决定六周期全算，行业只有 132 个，多算成本可忽略 |
| 阈值 | **87**（陶博士股票池）/ **90**（实操门槛） | 欧奈尔统计：美股飞升前相对强度均值 87 |
| 共振 | RPS50、RPS120、RPS250 同时 > 90 | 常见主升浪特征 |

## 1. 架构决策（用户已确认，执行者不得更改）

### 1.1 必须复权，且必须是后复权

RPS 比较今天与 N 日前的价格。本项目行情**不复权**，一只股票窗口内 10 送 10
会被排到全市场最底部——**RPS 会把高送转的强势股判成最弱，而排名表看着完全正常**。

复用既有 `src/server/data-sources/tdx/tdx-gbbq.ts` 的复权因子（覆盖派现/配股/送转，
数据源 `T0002/hq_cache/gbbq`，只读）。

**必须用后复权。** 该文件的设计说明写明：后复权因子只增不减，
追加数据不改写历史；而前复权每次除权都会改写全部历史。
若用前复权，**历史 RPS 曲线会随每次除权静默漂移**，
直接违反 `invariants.md` 的「追加未来 bar 不改变历史输出」。

### 1.2 证券池定义

排名基数变了 RPS 就变了，因此池定义必须显式记录并随结果存储。

- **上市一年以上**（陶博士口径，且 RPS250 本就需要 250 日历史）
- **排除 ST / *ST**（游资炒作产生异常涨幅，会污染排名顶部）
- **排除长期停牌**（停牌期间价格不动，涨幅失真）
- **只沪深，排除北交所**（涨跌幅限制 30%、流动性不同，口径不齐）

阈值（停牌多少天算长期等）由执行者定，记入 `decisions.md` 并在界面可见。

### 1.3 RPS 是每日批处理产出的数据，不是按需计算的指标

算**一只**股票的 RPS 曲线，也需要**全市场每一天**的涨幅。
因此按需计算不可行。做法与信号台账相同：每交易日收盘后跑一次全市场，
把结果落库；图表与选股只做查询。

### 1.4 存储不得爆炸

6145 标的 × 3 周期 × 250 天 ≈ 460 万个值。不要naive 每值一行。
形态由执行者定，但必须同时满足：
- 单只标的的曲线查询要快（图表要用）
- 单日全市场排名查询要快（选股要用）
- 走既有增量迁移，不改既有表

### 1.5 回填的历史 RPS 带生存者偏差，必须标注

回填历史 RPS 用的是**今天存活的证券池**，已退市的标的不在其中，
因此历史排名基数偏小、幸存者偏强。这与信号台账「只向前积累」的理由相同。

**允许回填**（RPS 曲线没有回填就没有意义），但：
- 界面必须标注该段为回填、带生存者偏差
- 向前每日新增的部分与回填部分**分别标记**，不混为一谈

## 2. S1 — 计算与存储

1. 复权收益：接 `tdx-gbbq.ts` 因子，产出各标的的后复权收盘序列。
2. 证券池过滤：按 §1.2 四条，每条排除都要能说明原因并计数。
3. 每日全市场 RPS：50/120/250 三个周期，排名并列的处理方式需明确。
4. 存储与回填：按 §1.4、§1.5。
5. 在 worker 中运行，支持取消与进度，不阻塞 UI。

**验收（A 层）**

- 手算可验证的小样本：构造 10 只标的，人工算出排名与 RPS，写进测试。
- **含除权的标的**必须有专项用例：复权后排名正确，不复权则会被误判——
  两种口径都算一遍，证明差异存在且复权口径是对的。
- **追加未来 bar 不改变历史 RPS**，有测试覆盖。
- 证券池排除项各有用例（次新、ST、长期停牌、北交所）。
- 全市场单次运行 < 10 分钟（批处理标准，同 N1）。
- 实测输出：池内标的数、各排除项计数、三个周期的 RPS 分布。

## 3.6 陶博士原始资料的补充结论（2026-09-10 通读 xstarcd wiki）

来源：`https://xstarcd.github.io/wiki/stock/` 的 RPS 编制方法 FAQ、
量化选股公式集锦、我是这样选牛股的、价值+动量+趋势、月线反转 6.0/6.1。

### 3.6.1 印证了已定的两条

- **复权**：他在扩展数据管理器里明确勾选「**精确复权**」。
  本项目用 GBBQ 后复权与之同向，§1.1 无需修改。
- **证券池**：「上市一年以上」自定义板块，剔除新股（他当时 2,882 只）。
  与 §1.2 一致。

### 3.6.2 新增的实现细节

- **归一化用 0–1000**，公式里再 `/10` 显示成 0–100。
  本项目内部存 0–1000 整数可减少浮点噪音，展示时换算，与他一致。
- **阈值不是单一值**：原文「80 以上为可投资对象，90 以上为理想选择」，
  指标公式的 `M` 参数「可以根据自己的偏好设为 85–90，我个人偏好 90」。
  因此阈值应**可配置，默认 90**，而不是写死 87。
- **每日收盘后必须刷新全部扩展数据**。对应本项目的每日批处理，§1.3 一致。

### 3.6.3 修正：RPS 应该接进公式引擎（此前判断错误）

原 §4 写「不把 RPS 塞进通达信公式引擎，因为 RPS 是横截面，
硬塞会让未来函数门禁失去意义」。**这个推理是错的。**

陶博士的公式正是通过 `EXTDATA_USER(n,0)` 引用 RPS 的：

```
Z:=EXTDATA_USER(3,0); RPS50:=Z/10; D:=IF(RPS50<=85,0,1);
```

**一旦 RPS 由每日批处理算好并落库，它就是一条普通的逐标的时间序列**，
和收盘价没有区别：日期 d 的值只由截至 d 的数据算出，**不含前视**。
把它作为数据字段喂给公式引擎不会削弱未来函数门禁。

因此改为：**公式引擎新增 RPS 数据字段**（`RPS5/RPS10/RPS20/RPS50/RPS120/RPS250`），
取值来自 S1 的存储。前提是：

- 该日无 RPS（标的不在池内、数据不足、批处理未覆盖）→ 返回 `null`，不得填 0。
- **回填段带生存者偏差**，公式跑在回填区间上时结果同样带偏差，界面必须能看出来。

这一项归入 S3（选股接入）。

### 3.6.4 由此可直接实现的陶博士公式

RPS 进入公式引擎后，下面这些**除 RPS 外全部使用已支持的函数**
（`MA` / `HHV` / `COUNT` / `IF` / `REF`），可直接跑：

**月线反转 5.0**（五个条件）：

```
A:=C/MA(C,250)>1;                 {站上年线}
NH:=IF(H<HHV(H,50),0,1); B:=COUNT(NH,30);   {30 天内创 50 日新高}
D:=IF(RPS50<=85,0,1);             {RPS50 > 85}
NN:=IF(C>MA(C,250),1,0); AA:=COUNT(NN,30);  {站上年线 2~30 天}
AB:=HIGH/HHV(HIGH,120)>0.9;       {最高价距 120 日高点不超 10%}
A AND B AND D AND AA>2 AND AA<30 AND AB;
```

**接近一年新高**：`CLOSE/HHV(HIGH,250)>0.9;`
**一年新高**：`NH:IF(H<HHV(H,250),0,1);`

这三条作为 S3 的验收用例——**能跑通才算 RPS 真正接进了选股**。
