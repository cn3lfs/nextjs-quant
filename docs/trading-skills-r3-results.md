## 5. 成交机制根因（管理者核实，2026-09-17）

执行者提交过一份诊断，方向对但代码定位与归因有误。以下是**经管理者逐条核实**的版本。

### 5.1 已证实

- **入场等待期过短**：`entryMaxWait` 默认 **3**（`src/lib/strategy-research.ts:76`，`z.number().int().min(1).max(20).default(3)`）。对日线信号而言 3 个交易日偏短。
- **真实判定位置**：
  - `src/server/research-portfolio.ts:967` —— `index - signalIndex > spec.entryMaxWait` → 记为「入场等待期结束仍未成交」；
  - 同文件 **980** 行 —— 反向指标信号已确认或原突破三日内枢纽失守 → 取消未成交买入意图。
- **数量**：`boll-middle-cross` 开发期被拒 20205 次 = 13054（等待期结束）+ 7151（反向信号取消），成交 0。

### 5.2 已证伪（执行者的错误结论，不要沿用）

- **行号错误**：诊断称根因在 `research-portfolio.ts:744-745` 与 `760-761`。核实后 744-745 是**加仓**等待期（「加仓等待期结束，停止后续加仓」），760-761 是**连亏冷静期**（「连续三笔完整交易亏损，冷静期暂停买入」）。两处都与入场过期无关。
- **归因过度**：诊断称 `entryMaxWait` 「解释了 100% 的 0 成交策略（15 个有信号 + 237 个零信号）」。**不成立**：那 237 个策略 `events = 0`，500 只证券在**池层**即被全部排除，从未产生买入意图，`entryMaxWait` 无从生效。零信号与零成交是两个独立阻塞，不可合并归因。
- 另：`kdj-golden` 「31671 个信号 / 32877 次未成交」拒绝数大于信号数，诊断未标注该异常。合理解释是每个意图在等待期内逐日重试各记一次，但需实测确认而非默认。

### 5.3 管理者的设计裁定：量价路径也改用覆盖判定

计划 §4.2 的原意是**信号复权、成交原始价**，该原意对量价路径同样适用，因此量价的准入也从「窗口不含除权事件」改为**覆盖判定**。但量价比形态多一层要求：

- **价格复权覆盖**：同形态路径，要求 GBBQ 因子与每根日线逐条对齐。
- **成交量可比性覆盖**：除权改变股本，量能跨除权不可直接比较。旧代码的拒绝理由「量价窗口含除权事件，**未实现对应量调整**」说的正是这一点。GBBQ 已解析出带日期的 `floatSharesBefore` / `floatSharesAfter`（`src/server/tdx-gbbq.ts:101-103`），据此可做量的股本比例调整。
- **两项都覆盖才准入**；任一缺失保持 missing 并给原因，**不得用当前股本回算历史量**。

这条裁定解锁的是池层被排除的 193 个量价策略（占 237 个零信号策略的 81%），与 5.1 的成交机制问题**互相独立**，两者都修完才可能出现非零成交。

### 5.3.1 实施陷阱：量能比例必须是累计的（一次失败尝试的教训）

2026-09-17 用一个免费模型试做过量调整，实现被拒。核心错误值得记下来，避免重犯：

它对每根 K 线取的是「**最近一次**股本事件的 `floatSharesAfter / floatSharesBefore`」。正确做法是**相对参考日的累计比例**。反例：先 1:2 拆股、再 1:2 拆股，位于两次之前的 K 线其量能需乘 **4×** 才可比，该实现只给 **2×**。A 股长区间内多次股本变动的股票是多数，因此这个错误会污染绝大部分量价回测。

同批其他问题：函数签名带了未使用的 `factors` 参数；`byDate` 特判与游标循环重复；同时存在 `volumeShareRatio` 与 `applyVolumeRatios` 两套重叠实现；在 `bars.map` 内改游标却未断言 bars 按日期升序；`npx tsc --noEmit` 5 处报错（`floatSharesAfter` 可能为 undefined 等）说明未自验。

可保留的部分只有设计意图：`volumeCoverage` 的 `"covered" | "partial"` 三态，以及注释里明确的禁令「never back-filled from the current share count」。被拒补丁存于 `.codex-runs/dsh-r3b-rejected.patch` 备查，未进任何分支。

**实施要求**：累计比例、参考日显式、覆盖不足返回 missing 且不得用当前股本修补、bars 升序须断言、必须自跑 typecheck 与全量。

### 5.4 入场等待期按预先登记网格做敏感性

`entryMaxWait` 不直接改默认值，而按计划 §7 用**预先登记的小网格**（例如 3 / 5 / 10）做单因子敏感性，各档独立登记为候选试验。**不得只登记表现最好的那一档。**
