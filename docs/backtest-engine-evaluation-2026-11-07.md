# 回测引擎选型与两策略试验

2026-11-07 历史调研记录。用户随后明确改为自己的 TypeScript 回测框架、独立 workspace 包、旧策略统一弃用且只从一个双均线策略做基建。当前实现见 [quant-backtest](../packages/quant-backtest/README.md)及 [next-plan](next-plan.md)。本文保留原比较与性能证据；下文 Hikyuu 接入和两个策略方案已被替代，不再作为执行计划。

## 结论与范围

用户进一步明确担心自研遗漏，因此优先复用成熟引擎的订单、账户与费用模型，不继续建设新的完整 C 回测引擎。Python 可以保留为策略和编排接口，重计算由上游 Rust/C++ 内核执行。

当前建议先验证 **Hikyuu**，将 **VectorBT 官方 Rust 后端**作为快速研究候选，**NautilusTrader**作为完整事件驱动备选。排序是结合当前沪深、本地 LC5、Windows 和少量简单策略的工程判断，尚无本机框架对照成绩。先验证框架能否表达所需规则，不能因为它使用编译语言就宣称已解决交易正确性。

下一阶段只有两种纯价格策略，不启用原有复杂预设批量搜索。旧策略定义、历史结果和证据继续保留；应用入口如何切换在接入阶段实现，不删除旧数据或重解释旧结果。

## 当前仓库的实际问题

- `native/tdx-import/` 已有 C 解码、合并、探测与审计，`koffi` 和 clang 均已具备，不需要为了原生运算重搭工具链。
- 缠论已使用 `vendor/czsc/CZSC64.dll`，当前资产说明为 API v21；继续遵守宿主单一 DLL 子进程串行规则，不另做缠论移植或工作池。
- `src/server/backtest/quant.ts` 是既有模拟路径；`metrics` 除均线外还叠加收盘位置、涨幅和量比。研究目录里的 `ma-cross` 也是趋势持续匹配，**不等于金叉买、死叉卖**，不能改名字就当作简单交叉策略。
- `packages/trading-strategy-core/src/indicators.ts` 的 `maSeries` 逐窗口 slice/reduce；`research-signals.ts` 的均线分支还逐日期复制行情前缀。重复计算与对象分配应先消除，语言替换不是唯一加速来源。
- `readSnapshot` 全量读文件、`parseBars` 构造时间字符串与 Bar 对象，然后研究端再截区间。数据范围和批量复用值得先测。
- `assertGrowthIntradayWindow` 仍硬编码 2000-01-04 至 2022-11-30。新数据不会自动进入现有五分钟研究；应由真实覆盖清单取代旧上限，不能直接放开而不检查缺日、缺时段与价格状态。
- 本地导入文档明确有 311,161 条看图估算量，LC5 本身无标志。首轮价格策略不依赖量比、VWAP 或成交量占比，但停牌/成交资格仍需证据；不能以估算后的非零量证明可成交。

## 本轮实测：性能证据的边界

环境：Windows x64，Node 22.22.2、Python 3.12.6、clang 19.1.3。数据根 `E:/new_tdx64` 只读。设置独立 `QUANT_DATA_DIR`，没有打开应用生产数据库。未安装框架、下载行情或更新 release。

目录清点：沪深 `fzline` 共 38,186 个 LC5 文件、39,483,567,680 字节；按现有 A 股代码形状筛选有 5,689 个文件、26,395,468,160 字节。这是文件覆盖，不是时点正确的历史证券池。

六只样本为 sh600519、sz000001、sh600000、sz000002、sh600036、sz000333。全历史解析分别为 289,440、303,648、306,000、301,152、282,672、149,904 根，修复/丢弃计数均为零；样本尾部均为 2026-10-30 15:00。2020 年以来每只均 79,344 根、1,653 个有记录日期，各日期均为 48 根。未独立逐日比对交易日历、停牌和公司行动，48 根不等于真实成交或完整官方认证。

### 两个价格信号核（每只 79,344 根，毫秒）

C 原型用 clang `-O2 -fno-builtin -fno-stack-protector -fuse-ld=lld -shared -nostdlib` 和现有 koffi 调用，未使用 fast-math。预跑一次后计 9 次取中位数。每次 FFI 传整列数组，包含调用成本；解析、列转换与订单模拟不在信号核计时内。

| sh600519 |               29.08 |        0.348 |  0.281 |   6.558 |  1.145 |      24.84 |
| sz000001 |               28.58 |        0.309 |  0.264 |   5.892 |  1.145 |      23.88 |
| sh600000 |               28.80 |        0.310 |  0.257 |   5.414 |  1.072 |      24.31 |
| sz000002 |               28.38 |        0.305 |  0.254 |   6.047 |  1.100 |      24.40 |
| sh600036 |               30.35 |        0.304 |  0.256 |   6.348 |  1.192 |      27.05 |
| sz000333 |               29.84 |        0.308 |  0.254 |   6.331 |  1.231 |      27.07 |

交叉用滚动求和；通道两版都扫描之前 20 根高点、10 根低点，未使用单调队列。六只合计 476,064 根，两策略各逐根核对零差异；均线另与现有 core MA 比较。手算序列“20 根收盘 10，随后 11、1、20”两策略信号应为买、卖、买；随机 2,000 根通道与独立窗口参考对照通过；人为改坏一个信号的负对照被断言检出。

这些只证明所测有效价格输入的信号一致。未验证非法输入、任意 double 长历史滚动误差或所有交易语义；不是生产内核验收，更没有证明策略盈利。临时 DLL/源码在实验后清理，不进入 runtime。若后续需要保留原生路径，应将实现、测试和可复跑基准一起纳入正式工程。

据此不再推进“各部分全部 C 化”：均线改算法已大幅减耗，C 相对滚动 TS 收益小；通道约五倍仅是计算核成绩，列转换和解析可以掩盖收益。

## 下一阶段的最小试验

### 两个明确的策略

1. `simple-sma-cross-5-20-v1`：五分钟收盘 SMA5 从小于等于 SMA20 变成严格大于时买入，反向交叉退出；需有当前与上一根完整窗口。窗口单位是 K 线根数。和旧 `ma-cross` 分开标识。
2. `simple-donchian-20-10-v1`：当根收盘严格高于此前 20 根最高价时请求买入，严格低于此前 10 根最低价时请求退出；当根不参与通道，首 20 根不发信号。

只做多、单证券独立账户、固定参数、不加仓、不叠加选股/新闻/量能/缠论/复杂止损。首轮先用上述六只固定证券核对，不把它们称为无偏证券池。买入持有只作基准，不增加策略选择数量。

### 交易口径先验收，再看收益

信号在五分钟结束后可得，最早下一根 open 成交。LC5 时间戳是区间右端；首根 09:35 的 open 对应 09:30，午休跨越与 15:00 之后次日执行必须明确。不在同根 open 执行刚用该根 close 生成的信号。

单证券初始资金 100,000 元，按可用资金整 100 股买入；重复买入信号不累积；退出请求受 T+1 限制时保留到下一可卖交易日；资金不足、不符合交易资格要记录拒绝原因。期末持仓估值，不虚构最后一根清仓。

佣金、最低佣金、卖出费用、滑点均显式配置与回显，首先沿用固定实验参数以便对照，不宣称历史费率还原。用小额手算案例验证资金约束和费用。

需逐项验证框架的 T+1、整手、涨跌停/停牌、信号顺序、缺失价格、送转分红与复权支持。缺历史状态或公司行动证据时明确缩短/排除窗口或标记不可用，不把缺失当“无事件”。五分钟线不能证明挂单排队或价位上有足额成交。

### 实施顺序与完成标准

1. 在仓库隔离环境安装并锁定 Hikyuu，先查 API/样例与源码，关闭自动下载和交易；将现有只读 LC5 解析结果接成框架支持的输入。先测试 32 年日期回卷、时间戳、非法输入、单位与原始数据 hash，复用既有 parser，不另写无测试的新解析器。
2. 先跑手算的下一根成交、同日买入后退出受阻、跨日、资金不足、最低佣金、停牌/涨跌停拒绝、公司行动边界，再跑两策略的小样本。若必须自行重写大量账户/撮合状态才能通过，停止接入并比较备选，不把这部分变成另一个自研引擎。
3. 如需要 VectorBT 对照，锁定 Python/Rust 相同版本；显式使用 `engine="rust"`，不支持的自定义交易逻辑如实报告。对照信号和逐笔现金/持仓，先解释规则差异，再比较速度，不要求不同默认模型产生同一个收益数字。
4. 结果通过后，才将两个策略接入当前任务 worker、取消/进度与结果存储，默认入口仅显示两项。结果记录引擎版本、策略版本、来源 hash、范围、复权、费用和覆盖。旧策略与旧报告保留原版本。
5. 测 6/100 只证券和固定期间，分别计启动、读取、解析/转换、信号、撮合、统计、序列化、端到端与峰值 RSS；冷启动和暖运行分开。每批有资源上限和取消检查，避免一次把全市场 26GB 原始数据转成 JS 对象。只有实测热点才考虑原生解码或批量优化。

框架进程、Python 依赖、桌面交付方式属于架构接入决定，本轮没有自动修改。实施时先给出该阶段具体依赖与宿主边界；独立原型不阻塞。应用改动按 AGENTS 运行相关测试、typecheck、全量子任务检查及需要的 build/runtime；桌面打包另需明确授权。
