## 2. 集中实现的模块边界

- `quant-backtest`：已有共享资金账户与执行规则继续作为唯一实验账本；增加显式外部目标模式，经典因子合成与目标函数保持纯输入输出。经济收益归一化只保留一个实现源，技术面板与撮合侧不能复制出两种公司行动口径。
- `trading-strategy-core` / `tstdx`：调用既有指标、财务可见性、字段尺度、TTM/同比和本地文件解析。只有确证缺失的通用计算才补到其所属包；不在脚本重写FN/GP二进制或通用指标。
- 研究编排：读取/冻结/压缩、源版本、进度、取消/失败记录、矩阵运行及中文报告；提供Windows单命令入口与只使用冻结输入的重放入口。
- `quant-performance`：日净值、基准收益、年度/分段/滚动评价；不从评价模块改变成交、持仓和选择结果。

不先建设财务数据库、不加UI或worker注册、不购买新数据。若输出较大，采用压缩面板和复用同一价格快照，禁止每模型复制一份原始行情。原实验、用户其他模块修改、通达信与Blocks来源、受保护MCP文件保持原状。

## 3. 必需的行为验证

| 类别         | 有效用例与负对照                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 财务时点     | 公告当天不可见、公告后首个交易日可见；周末公告；无公告/日期异常/晚披露/过期；修改未来财报不改此前分数与目标                      |
| 跨期财务     | 年报与非年报TTM手算；缺同期不计算；CAGR要求连续年度与正端点；每个组成报告均可见；负利润不误判为低PE高分                          |
| 金融适用性   | 银行与未知行业不套用普通企业毛利/CFO/负债率；仍可通过通用ROE、ROA、E/P、B/P取得规定输入资格；未认证零值不补造                    |
| 估值与单位   | GP16万元转元恰好一次；同日多条/零/负/缺值不可用；不前填；改变未来市值不改变过去估值                                              |
| 排名与缺失   | 并列取平均；常数列得0且无排序能力；家族未达门槛为未知；13与16项数量不改变两支路50/50；同分次序稳定                               |
| 组合约束     | 单股目标≤15%、权重和≤100%、候选不足留现金；不同风险缩放仍按账户净资产限仓；无效日期、池外证券、NaN、负权重和超限目标拒绝         |
| 风险估计     | 60日日期对齐；组合风险包含相关性；完全相关与反向相关手算；输入不足转现金并记录；未来行情扰动不改变过去预算                       |
| 执行账本     | 同一资金账户、卖后买、现金不负、整手/T+1、最低佣金、费用日期边界、限价/滑点/容量、受阻卖单重试与重算；送配股同步目标，净权益守恒 |
| 因果性与比较 | 周末信号下一开盘执行；成交延迟真的改变执行日；任何远期标签不进入评分；共同窗口由覆盖确定而非收益决定；分段从前一真实权益起算     |
| 诊断与来源   | IC并列手算、正负方向、标签末尾缺口、非重叠子样本；目录所有ID有去向；输入或代码hash变化可检出；损坏冻结数据不生成成功报告         |

至少一个可预期错误的负对照必须实际失败，例如把未来公告提前、把万元当元、把15%改成更高权重，或原实现曾被上述用例检出；恢复后绿色才作为有效保护。测试不只断言函数自己生成的数据相等。

## 4. 运行与工程门禁

先在相关fixture上集中跑纯包与针对性测试，接口稳定后再运行仓库要求的`pnpm test`、`pnpm typecheck`、`pnpm build`。需要更新runtime构建时按根命令执行；本批无桌面分发，不擅自打包或替换release。每次可能打开数据库的验证先设置新的隔离`QUANT_DATA_DIR`，不用默认生产库。

本阶段D0只核查文档、事实与链接，不机械跑应用全量测试。后续D4记录真实命令、退出码、通过/跳过数量和失败原因；不能沿用上一轮的绿色输出证明新因子研发完成。单命令实源运行与冻结重放均须观察到最终结果，不能以进程已启动视作完成。

## 5. 交付审计与剩余风险

最终研究说明应逐项回答：哪些经典思路被实现，哪些只是近似；财务数据实际覆盖什么日期，哪些组合确实用了财务；共同窗口为何这样选；是否超过等权对照；是否达到30%回撤；加入风险层后是不是只有仓位降低；最差年份与成本/延迟是否失效；哪些缺口仍阻止实盘认证。

必须保留当前池、源修订、历史ST/限价、行业中性缺失和公司行动到账简化等限制；不以“站在巨人肩膀上”代替本地验证，也不以“数据有限”跳过已经可做的技术与财务组合实验。没有模型达标时如实完成失败研发结论，不无限追加模型、改窗口或只留下胜者。
