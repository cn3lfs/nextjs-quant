## 3. 接手需要知道的结构变化

- **页面模型**：只有 `/market`、`/screen`、`/backtest` 显式保留实例，在 `src/components/workbench/retained-routes.tsx` 单一注册；其余是常规路由。状态归属（URL / 具名 store / query cache / sessionStorage）见 [architecture](architecture.md#页面模型与状态归属)。
- **数据层**：业务读写走 `src/server/db/<kind>` 类型仓储。`scripts/audit-database-calls.ts` 盘点直接 SQLite 调用，ESLint 边界规则（`scripts/lib/sqlite-boundary-rule.mjs`）禁止已迁移范围在数据层外调用；剩余 25 处的原因见优化交付。schema 与 `user_version` 未变，旧 exe 可打开现有库。
- **共享技能耦合**：应用运行时读取 `~/.agent-skills/skills`（`QUANT_SKILLS_DIR` 可覆盖）中的交易技能原文。共享技能已按角色重组（trade-planner、technical-analyst、growth-stock-strategist、risk-manager、market-analyst、event-researcher、fundamental-analyst），应用通过 `skill-location.ts` 把稳定方法 ID 映射到新位置；`docs/trading-skills-source-lock.json` 是冻结快照，只用于来源追溯，**不要重新生成**。移动或改写技能前先搜本仓库引用、更新映射与测试夹具；改动双突破原文后需重新冻结 `packages/trading-strategies/src/research/breakout/breakout-method.json` 的哈希并重建包（仅限规则口径未变时）。
- **测试环境**：主工程测试不依赖系统 TEMP 位置；临时 worker/编译器夹具显式解析工作区依赖。`pnpm check` 会自行隔离数据库和 TEMP，日常完整验证优先用它。
