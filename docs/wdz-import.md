# 通达信五分钟导入

## 常规导入

三个入口独立使用，均在仓库根目录执行。首次使用或 C 源码变动后，先执行 `pnpm native:build`；需本机已有的 clang 和 x64 Windows，不新增依赖。

| 功能      | 命令                                                                             | 输出                             |
| --------- | -------------------------------------------------------------------------------- | -------------------------------- |
| WDZ → CSV | `pnpm wdz:extract --source "文件.wdz" --out "新目录"`                            | `SH/代码.csv`、`SZ/代码.csv`     |
| CSV → LC5 | `pnpm tdx:import --source "CSV目录" --tdx-root "E:\new_tdx64" --workers 4`       | 合并进通达信五分钟文件           |
| WDZ → LC5 | `pnpm wdz:import --source "WDZ文件或目录" --tdx-root "E:\new_tdx64" --workers 4` | 直接解码并合并，不生成或解析 CSV |

CSV 导入可选择含 SH/SZ 子目录的父目录。WDZ 直接导入会递归寻找 `.wdz`，按文件名日期顺序处理，包含可选数据；不同品种并发，同一品种跨块串行。CSV 导出要求输出目录尚不存在，同一品种跨块只保留一个表头。

## 写入规则

- 关闭通达信后执行。只写 `vipdoc/sh/fzline`、`vipdoc/sz/fzline` 中的 `.lc5`，不修改日线、终端配置或研究数据库。
- 不预检整批、不备份、不二次确认。新增日期追加；历史缺口按时间合并；相同时间保留旧记录。重复导入不添加重复记录。历史插入用同目录临时文件替换，单次追加失败回退到原长度；不承诺整个批次原子提交。
- SH/SZ 只代表交易所。指数（包括源文件的 SH999997/8/9 别名）保留源手数；SH204xxx、SZ1318xx 国债回购保留源面额量，两条实源回购样本的成交额/源量约为 1000。回购价格是利率，不能拿它套股票均价公式。这是本项目导入口径，不宣称已证明通达信所有历史包的官方单位。
- 股票、ETF 以股/份写入：按成交额÷换算后成交量是否落于该根价格区间，核验 ×100、×1、÷100 三种倍率。仅唯一匹配时采用；容差为 0.001 元加最高价的百万分之一，覆盖三位 CSV 价格和 Single 舍入。零量、零额、无匹配或多重匹配时，科创板默认源量为股，其余默认手数乘 100。逐根核验不读取全批，不增加用户配置。
- 使用无符号 32 位成交量：`0..4294967295` 可保存；超过该容量才置零并列出具体时间。旧 `zero-signed` 接口保留供历史预检批次使用，新直接导入统一为 `zero-unsigned`。588000 的实源 2,376,449,000 份不再因超过有符号上限而被置零。
- 所有品种在同一时间的前 24 字节完全匹配，且现存成交量精确等于源量乘 100 后按旧有符号阈值置零的结果，或现存量为零且来源提供有效非零量时，修正成交量。WDZ 的零量另允许前20字节相同、金额精确匹配原始Single表示；见下文v4说明。其他价格、金额或非零成交量冲突保留；保留原保留字段。C 同时输出排序去重后的旧规则量，CSV/WDZ 共用严格金额匹配路径，原始金额凭据仅由WDZ提供。
- 已齐全的时间段在 C 中先核对整个输入区间，再通过可写内存映射仅修改匹配记录的 4 字节成交量并刷新映射，无整份历史复制重写；存在缺口时仍走合并文件路径。不承诺断电或进程强杀时的整批事务。
- WDZ 原始价格、量额为 float32。直接导入复现原 VB6 CSV 的约七位有效数字及列小数位舍入，再在 C 中编码 LC5，保证与已有 CSV 导入结果一致；中间没有 CSV 文本或逐条 JS 行情对象。
- WDZ 内全零占位、OHLC 非法和非五分钟时间的记录不补入，记录其时间并继续处理该品种的有效行情。时间乱序在 C 中排序，完全重复的记录去重，源内同时间不同内容报错。非六位历史证券代码不推测映射，列明跳过。块损坏、记录截断或未知编码明确报错，不猜测修复。
- Ctrl+C 停止分配新写入并等待当前文件完成，已经成功写入的记录保留。

## 报告与续跑

全目录只读历史检查：`pnpm tdx:audit --tdx-root "E:\new_tdx64" --out "检查报告.json"`。C 扫描所有 LC5 记录的日期、顺序、OHLC、成交额以及有额零量；有额零量是待核验线索，不能直接当成错误。检查不打开研究数据库、不改行情。非法价格等记录只有存在明确有效源依据时才修复，不把合法不同报价当作错误。

导入开始即打印临时报告目录，其中 `summary.json` 为累计结果，`archives.ndjson` 为逐包统计，`details.ndjson` 记录冲突、超限时间、跳过项和错误。错误写入退出码为 1，不隐藏部分成功。

新报告标记 `volumePolicy: wdz-auto-v4-source-amount`；旧规则报告不能用于新规则的 `--resume-report`，否则会跳过尚未修复的已完成包。升级规则后首次完整运行不带续跑参数，重复执行幂等。C接口增加了原始金额元数据，源码更新后须重建 native/runtime，再使用当前脚本或应用。

### 已有历史的修复

1. 正常 `wdz:import` / `tdx:import` 自动处理旧倍率及可从同价格金额源恢复的零量。独立补零量脚本可只处理检查报告列出的候选品种：`pnpm tdx:repair-zero-volume --source "WDZ目录" --tdx-root "通达信目录" --audit-report "检查报告.json" --out "零量恢复报告.json"`。不会新增日期或覆盖非零量；若目标时间段不完整，计入 `uncoveredRanges`，不盲目写入。
2. 价格全零记录仅在 WDZ 也明确标为无效源时间时清理：`pnpm tdx:audit --tdx-root "通达信目录" --out "清理报告.json" --remove-zero-prices --source-issues "WDZ导入的details.ndjson" --price-report "检查报告.json"`。没有源依据的零价格保留待核验，不清理合法停牌缺口，不填充价格。`--price-report` 限定本次处理已查到的异常文件，省去重新全扫。保留其他记录原字节，全为空的旧文件保留为空文件。
3. 上述修复必须串行运行，关闭通达信和其他写入程序；清理阶段不能与导入同时写同一文件。完成后再运行只读全目录检查，确认结构与价格问题是否消除。有额零量仍是线索而不是自动判错依据，源量也为零或价格金额不同的记录不强行修改。

v4额外识别原始二进制成交额：时间及OHLC前20字节严格一致、现存量为零时，金额可与WDZ原始Single位模式精确匹配，不必只与CSV舍入后的金额匹配。原始金额元数据随C排序去重保持对齐，不写入LC5保留字段；仅恢复成交量，金额仍保留原字节。源量为零、原始与舍入金额均不匹配、价格不符时不修。若恢复后仍有金额表示差异，报告保留冲突计数；不能因成交量已恢复而声称全记录相同。

已知未确认源记录：SH520660 在 2024-07-10 09:35 的 OHLC 均为 0.970，源量 270000000、成交额 2627100；源量 ÷100 后均价为 0.973，超出该根价格及舍入容差。默认 ×100 又超过 uint32，普通导入因此保留零量并单列报告，不强制指定倍率。该记录后续按用户近似看图授权单独估算，仍不能视为源支持的准确修复。

```powershell
# 从已停止的报告续跑；完成且无错误的包不重做，最后未完成的包及错误包重试。
pnpm wdz:import --source "E:\BaiduNetdiskDownload\SHSZ_5Min_update" --tdx-root "E:\new_tdx64" --resume-report "报告目录\summary.json"

# 只重试一份明细中的错误包。
```

## 实现和格式边界

`native/tdx-import/wdz.c` 负责 XOR、紧凑行情解码、数值舍入和 CSV/LC5 编码；Node 复用自带的原生 MD5/zlib，并负责文件 I/O 和调度。`five-minute-native.ts` 是两种数据源共用的 LC5 写入器。已完整覆盖的输入时间段通过 C 二分查找定位后比较；只读映射用于核验，可写映射用于源支持的成交量修复。修复先核验整个输入区间，再仅改量字段并刷新映射；存在缺口时关闭映射，回到历史合并。不对整份多年历史反复复制。Windows接口见 [CreateFileMappingW](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-createfilemappingw)、[MapViewOfFile](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-mapviewoffile)。

目前支持已提供的沪深五分钟 `0x105` 格式。块头为两个 LE uint32 `n,m`，加密数据长 `n-4`，下一块位置为当前偏移加 `n+4`。文件尾 uint32 指向索引块；索引每项 32 字节，允许同一品种占多个块，通过“块位置＋块内位置”定位。种子 `WSTOCK`＋LE(n)＋LE(m)＋`.net`，分别在字节 6、8、10 依次累积改成 `X`，四次 MD5 的大写十六进制拼接成 128 字节循环 XOR 密钥，随后 zlib 解压。块长度、zlib 校验、元数据、索引与记录边界属于解析正确性检查。

## 看图成交量估算（独立脚本）

这是普通导入之外的离线工具，仅修改已有记录的零成交量。输入是审计明细或离线分析生成的计划CSV，不是原始行情CSV。三种模式必须且只能选择一个；通达信目录和新的执行报告目录均需指定。

```powershell
pnpm tdx:estimate-zero-volume --tdx-root "E:\new_tdx64" --remaining-report "remaining-zero-bars.csv" --out "新报告目录"
pnpm tdx:estimate-zero-volume --tdx-root "E:\new_tdx64" --calculation-plan "calculation-plan.csv" --out "新报告目录"
pnpm tdx:estimate-zero-volume --tdx-root "E:\new_tdx64" --visual-plan "visual-plan.csv" --out "新报告目录"
```

- `--remaining-report`：只处理`security-estimate`且属于股票/基金代码的记录，以`成交额 ÷ ((最高价＋最低价＋收盘价) / 3)`取整为股/份。时间、金额和高低价快照须一致；不足半单位、超uint32或非法价格不写。指数点位、回购利率不适用此公式。
- `--calculation-plan`：B股、债券和旧回购的局部校准候选。要求前后各至少20样本、匹配率至少95%、代码及类型符合白名单；金额和典型价快照一致，重算结果等于计划整数才写。公式与计划依据见[品种单位核验](deliveries/2026-11-05-tdx-instrument-units.md)。
- `--visual-plan`：用户接受较低精度的独立模式，可覆盖指数及历史代码，采用邻近量额比、同刻或邻近量插值等方法。要求原32字节精确匹配、正uint32及对应方法的最低样本数，不降低其他模式的门槛。计划生成方法、参考样本和限制见[放宽估算交付](deliveries/2026-11-05-tdx-visual-volume.md)。

关闭通达信和其他写入程序后执行。只写4字节成交量，不创建行情备份；逐文件完整读回确认其他字节与长度未变。输出`summary.json`和`estimates.jsonl`，日志包含品种、时间、偏移、原32字节、方法及建议量，并区分写前计划与写后核对状态。部分失败通过日志和退出码识别，不代表整批回滚。重跑使用新的报告目录，已有非零量不会再次改写。

这些值仅用于看图。LC5自身无估算标志，量化端也会读取估算值，必须保留外部逐条日志；普通导入不会自动识别现存非零量属于估算，未来真实来源替换需依据日志定位。原336,975条问题快照目前全部非零，其中311,161条是三轮估算；这不等于取得真实历史成交量。
