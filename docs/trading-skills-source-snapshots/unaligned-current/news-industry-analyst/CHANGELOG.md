# 更新日志 · 财联社新闻分析系统

> 本文档兼作"系统总览"：
> **上半部分**看 **当前怎么工作**（工作流程）；**下半部分**看 **功能怎么一步步演进**（迭代过程）。

---

## 一、当前架构与工作流程

### 三 skill 分工（各做一件事，互不牵连）
| skill | 版本 | 角色 |
|---|---|---|
| news-industry-analyst | v1.8.0 | 编排：串起整条流程 |
| news-industry-classifier | v1.2.0 | 分类：新闻 → 申万行业（34 标签）+ 缓存加速 |
| news-sector-analyzer | v1.12.0 | 分析：重点板块 → 机会/风险/验证信号 + 市场情绪温度（盘面硬数据）+ **板块估值实测（PE/PB/股息率+历史分位）** + **板块资金流实测（申万一级+二级细分主力净流入）** + 预期差八象限 v2（腾讯源价格+基准超额+量能，±3% 确定性分档，钝化降档，逐板块证伪条件） |

### 数据流
```
你说"分析近5天新闻"
   │
   ▼ ① cls-news 拉数据 ──────→ 原始新闻 JSON
   ▼ ② classifier 分类 ──────→ 34 标签（缓存命中即跳过 LLM）
   ▼ ③ sector-analyzer 分析 ─→ 宏观背景 + 市场情绪温度 + 板块估值实测 + 板块资金流实测 + Top板块五要素 + 跨板块主线 + 预期差八象限 + 附录
   ▼ ④ 报告落盘 ─────────────→ ~/documents/板块机会风险验证信号报告-YYYYMMDD.md
```

### 报告结构（6 部分）
1. **宏观背景与风险偏好**（外部货币/地缘/政策，2-3 条主线）
2. **市场情绪温度**（成交额/涨停/连板/大盘强弱 → 火热/偏热/中性/偏冷）
3. **重点板块**（Top7、每板块≥3条，新闻要点每条带 `[MM-DD HH:MM]` 时间前缀、涨跌幅等时点数据必须可对应到时间）：开头《板块估值实测》表（PE/PB/股息率+历史分位+估值读法+估值维度结论）与《板块资金流实测（含二级细分）》表（最新日/近5日/近10日/近20日主力净流入+二级吸金↔失血+资金读法+资金维度结论）；每板块 新闻要点 + 核心逻辑 + 机会 + 风险 + 验证信号（内嵌估值实测行与资金流实测行）+ 方向/信心
4. **跨板块主线**（1-3 条贯穿多板块的共性逻辑）
5. **预期差视角补充**（腾讯源拉板块近30日价格 → 消息×价格×扩散度八象限定位 + 扩散度判定 + 操作纪律）
6. **附录·分类清单**（全量新闻按行业列出，供溯源核对）

### 核心原则
**语义判断交给大模型（准、懂语境、零规则维护），确定性工作交给脚本（分批/校验/重试/缓存/聚合，可重现、可无人值守、可扩展）。**

## 二、功能迭代记录（按演进顺序：问题 → 改动）

> 主体发生在 2026-06-22 的一次深度重构中，2026-08-19 与 08-20 各有一次补充（见 ⑪⑫⑬⑭）。
> 记录"每个功能为什么加、改了什么"。

### ① 架构重构：关键词分类 → 三 skill + 大模型语义分类
- **问题**：原本单一臃肿 skill 用关键词硬匹配分类，误分 30-40%、优先级冲突无解、维护无底洞。
- **改动**：拆成三 skill；分类改为脚本程序化调用 DeepSeek 做语义分类。
- **否决的弯路**：① 继续打补丁调关键词（永远补不完）；② 让模型在对话里手写分类 json（脆弱、不可重现、不能无人值守）。

### ② 分类加速：md 缓存
- **问题**：每次都把全部新闻送 LLM，慢且费。
- **改动**：LLM 分类时顺带返回"决定性关键词"，沉淀到 `classify-cache.md`；下次标题命中即跳过 LLM。命中率从首次 ~37% 升到 ~70%、LLM 批次大减。歧义仍走 LLM、LLM 兜底，只加速不误分。

### ③ 分类提纯：市场情绪面剥离
- **问题**：成交额/涨停/IPO/并购等盘面新闻被错塞进"非银金融"，把券商保险板块搞乱。
- **改动**：新增"市场情绪面"标签（共 34 标签 = 申万31 + 宏观/市场情绪面/国际市场），盘面单独成类、不再污染行业板块。

### ④ 分析框架：机会/风险/验证信号
- **问题**：要的是能指导决策的判断，不是罗列新闻。
- **改动**：新建 news-sector-analyzer；对 Top 重点板块每个产出 核心逻辑/机会/风险/**验证信号**（催化日历+基本面+资金情绪）+ 方向/信心。验证信号让报告从"事后描述"变"前瞻可跟踪"。

### ⑤ 补事实层：新闻要点
- **问题**：分析太浓缩，丢了原始新闻细节，无法追溯。
- **改动**：每板块先列"新闻要点"（保留公司/数据/事件），再给判断。

### ⑥ 补溯源层：分类清单附录
- **问题**：想核对"分类分得对不对"。
- **改动**：报告末尾附"全量新闻按行业清单"，逐条可核对。

### ⑦ 质量打磨（最近一轮）
- **宏观压缩过度**：110 条曾被压成 1 条主线 → prompt 要求 **2-3 条**。
- **市场情绪被埋没**：盘面 28 条只当背景 → **独立成「市场情绪温度」小节**（火热/偏热/中性/偏冷 + 关键信号）。
- **瘦板块**：2 条的板块也挤进 Top7、分析偏薄 → 入选门槛 **2 → 3**。
- **缓存粒度**：'成交额突破1万亿/2万亿'各存一条 → prompt 要求关键词**不含数字**，提高复用。
- **Phase3 诚实化**：文档明确"基本面信号默认是模型定性观察点，实测需 Phase 3 hithink 手动补"。

### ⑧ 预期差视角固化（2026-07-14）
- **问题**：报告的"方向"只看消息面（业绩预增=偏多），但 2026-07 中报季出现"利好密集+板块普跌"的第4象限行情——消息面判断与价格背离，报告给不出仓位层级的应对。
- **改动**：analyze.py 新增固定章节「五、预期差视角补充」（排在附录之前）：脚本用 akshare 拉各重点板块申万一级指数近30个交易日价格（近30日/近5日涨跌幅、距高点回撤，确定性计算），再由 DeepSeek 按"消息×价格×扩散度"八象限框架逐板块定位、判定扩散度层级、给操作纪律。核心纪律：**利好不涨即利空；个股背离换股，板块/市场级背离降总仓位**。方法论出处：`~/documents/预期差交易讲义-20260713.md`。
- **容错**：akshare 为可选依赖，未安装/拉取失败时该章节降级为标注，不阻断报告；单板块价格失败仅跳过该板块。
- **弃用的路**：同花顺问财 API 查行业区间涨跌幅——多次改写查询均返回空字段，改用 akshare 申万宏源指数日线。

### ⑨ 预期差升级 v2：量化判定 + 确定性分档（2026-07-15）
- **问题**：v1 预期差三个缺陷——①价格"涨/跌"无量化阈值，超额 -2.2% 这类边界值被模型误判为"跌"；②消息×价格→象限的映射交给模型自由发挥，出现"消息偏多+价格涨"被标成第7象限并在输出里自我辩论；③板块分析偶发英文键（direction/confidence），下游读不到"方向"。
- **改动**（news-sector-analyzer v1.4.0，配合讲义 v2 `~/documents/预期差交易讲义-20260715.md`）：
  - **价格裁决量化**：新拉上证指数作市场基准，算近5日超额收益；脚本按 ±3% 阈值**确定性分档**（涨/跌/钝化）——钝化是 v2 新档：利好钝化偏空看、利空钝化偏多看，象限定位降档处理；
  - **量能佐证**：申万指数补量能比（近5日/前25日均量，>1.2 放量、<0.8 缩量），跌+缩量=惜售存疑等规则进 prompt；
  - **职责再划分**：价格档/量能档由脚本算好直接喂给模型（不得重判），prompt 写死消息×价格档→象限映射表，禁止疑问句与自我修正过程；
  - **证伪条件**：每个板块的象限判断必须附证伪条件（什么价格行为出现说明判断错了+对应动作）；
  - **象限迁移预判**：新增输出字段（当前格局最可能向哪个象限演化、盯什么信号）；
  - **键名归一化**：板块分析结果英文键自动映射回中文键。
- **容错**：基准指数拉取失败降级为绝对涨跌（阈值不变）；量能列缺失跳过量能档。
- **验证**：同批 372 条新闻重跑对比——电子/计算机/有色（超额 ±3% 内）从误判"跌"修正为"钝化降档"；通信正确归第1象限；基础化工方向恢复"偏多"；每板块均带证伪条件。

### ⑩ 预期差章节加"入门说明"（2026-07-28）
- **问题**：报告第五节直接抛出"第2象限（利好+涨+扩散大）""量能比 0.72""证伪条件"等术语，没读过预期差讲义的人不知道这节在干什么、也不知道看完该做什么，等于白写。
- **改动**（news-sector-analyzer v1.4.1）：第五节标题下新增固定的《这一节是什么（首次阅读先看这里）》小节，随后才是《定位结果》：
  - **一句话动机**：消息不是买卖依据，价格对消息的反应才是（利好已被买进去 → 价格不再涨）；
  - **三个维度白话解释**：消息（来自第三节）/ 价格（近5日超额 ±3% 分档 + 量能比）/ 扩散度（个股级还是板块级 → 决定换股还是调总仓位）；
  - **八象限速查表**：组合 → 含义 → 动作，一行一个象限；
  - **怎么用**：找板块 → 看象限 → 读"应对"和"证伪条件" → 最后看"操作纪律"总仓位约束；
  - **三个提醒**：价格截至上一交易日收盘（隔夜外围可推翻结论）、非个股买卖建议、判断错了按证伪条件立刻改。
- **验证**：186 条新闻（2026-07-23~07-28）重跑，新章节正常渲染在第五节顶部、原表格与分板块说明不受影响。

### 2026-08-19 补充（news-sector-analyzer v1.4.1 → v1.5.0）

### ⑪ 预期差章节修复：代理隔离 + 去掉过度限速
- **问题**：预期差章节长期降级为"数据不可用"（工作区 `n_analysis.json` 里 `prices: None`）。
  排查发现根因不是 akshare 本身——清空代理变量后 `ak.index_hist_sw` **1.0 秒正常返回**；
  是 `analyze.py` 缺少清代理逻辑（同目录的 `fetch_data.py` 有，这个脚本漏了）。
  叠加 `_ak_call` 每次请求前无条件 `sleep(2)`、失败退避 2→4→6 秒，
  11 次调用全失败要空等约 **132 秒** 才降级；即便全部成功也有 **≥22 秒**纯 sleep。
- **改动**：新增 `no_proxy()` 上下文管理器，**只在 akshare 调用期间**临时清空 6 个代理变量、
  退出即恢复（不全局清除，避免影响可能需要代理的 DeepSeek 调用）；
  `AK_INTERVAL` 2→1 且首次调用不等待。
- **效果**：全链路 **6.4 秒**，预期差章节从"降级标注"恢复为真实数据，
  板块与基准截止日对齐、超额收益/量能档/象限定位齐全。
- **否决的弯路**：在 `main()` 开头全局 pop 代理变量——会波及 DeepSeek 调用，风险不对称。

### ⑫ 板块相关个股标注（`scripts/stock_industry.py`）
- **问题**：报告里"验证信号-资金情绪"要跟踪龙头股，但此前只有大模型给的定性描述，没有代码可查。
- **改动**：用申万个股分类表预处理出 `references/stock-industry.json`（5182 条简称→代码/申万一二级/市场，
  含 A股/港股/美股），为每个重点板块标注新闻中出现的相关个股。
- **关键设计——实体查询 ≠ 分类**：实测发现纯查表做分类会系统性出错：
  "创业板指跌逾5%"命中个股简称`机器人`(300024)、"午评"会罗列一堆跨行业涨停股——
  这些本应归"市场情绪面"。因此只做实体标注、且只保留 `l1 == 板块名` 的命中，
  分类仍由 news-industry-classifier 的大模型负责。
- **三个踩过的坑**：
  1. 2 字简称（`柳工`/`李宁`/`微博`）误伤率高 → 只保留 ≥3 字，另设 `stock-blacklist.md`
     剔除 `机器人`/`航天工程`/`人民网` 这类通用词与信源名。
  2. 用"左右不邻汉字"做词边界是错的——中文无词间空格，`中芯国际跌超3%` 会被误拒；
     改用**长名优先 + 字符占位**，靠占位避免 `中国平安`/`平安银行` 子串重叠。
  3. 表里 47 个 `-U`/`-W` 后缀简称（`寒武纪-U`）多数已摘帽，新闻写`寒武纪`匹配不上 →
     同时注册去后缀别名。
- **数据局限（重要）**：底表 `最新个股申万行业分类(完整版-截至7月末).xlsx` 实为
  **2021年7月末**快照（文件名里的"最新"有误导性，文件日期 2021-09-09），
  同目录 `StockClassifyUse_stock.xls` 更新到 2022-09-29 但不含公司名称。
  即 2022年9月后的新股（如宇树科技）标不出来——属预期内降级，不影响分类。
  换新表后重新生成 JSON 即可，脚本无需改动。

### ⑬ 证伪条件可达性 + 日线缺口补齐（2026-08-20，v1.5.0 → v1.6.0）
- **问题1（证伪条件形同虚设）**：GAP_SYS 的示例写着"2日内放量收复前高"，模型逐板块照抄。
  但电子当时距30日高点回撤 **-24.3%**，收复前高需上涨 21.7%，两个交易日内物理上不可能——
  **永不触发的证伪条件等于没有证伪条件**，把"结论必须可证伪"这条框架灵魂彻底架空。
  同一板块距**近5日高点**只差 **+0.3%**，可触发概率差两个数量级。
- **改动1**：`fetch_prices` 增算四个短周期锚点（现价到近5日高点/近10日高点/5日均线/近5日低点
  的百分比距离），按 ≤5% 标注【够得着】/【太远】喂给模型；prompt 硬性规定：只能用【够得着】
  的锚点、**时间窗口一律「3个交易日内」**（用户要求统一口径，便于横向对比与到期核对）、
  证伪条件里必须写明锚点名与百分比距离；明确禁止"收复前高/回到30日高点"，
  并说明"距30日高点回撤"只是位置描述、不是可用锚点；若锚点全【太远】则改用非价位型条件
  （超额转正/放量且连续3日不创新低/量能比回到1.2以上）。
- **意外收获**：模型自行推出**方向对称**——上涨板块（第2象限）用向下锚点（跌破5日均线）证伪，
  钝化板块用向上锚点（突破高点）证伪。prompt 未教，因锚点数据同时给了上下两个方向。

- **问题2（数据静默倒退一天，更严重）**：8/20 盘中跑时，报告"数据截止 2026-08-18"——
  比前一天的报告还旧。根因是两个 bug 叠加：
  1. 申万日线 T+1 更新，8/20 上午日线仍止于 8/18，缺 8/19；
  2. `snapshot_date` 靠**价格数值**在**全序列**里找锚点（误差 ≤0.2%），震荡行情中同一价位
     会在多个日子重复出现——电子快照昨收 8677.26 被误匹配到 12 天前的 08-06，返回 sd=08-07；
     调用方 `if sd > d[-1]` 为假、`elif sd is None` 也为假，**两个分支都不进，快照被静默丢弃**。
  后果：用 8/18 的数据算出"电子近5日超额 +4.9%、第2象限、**持有、偏高仓位**"，
  完整错过 8/19 电子 -7.8% 的暴跌。金融场景下这是危险输出。
- **改动2**：`snapshot_date` 搜索范围限制在末尾 3 根（快照最多是最近一两个交易日的）；
  调用方 `elif sd is None` 改为 `else`，把"锚不上"和"误匹配到历史某天"合并处理：
  用快照「昨收」补出缺失那根、再接「最新」，仅在推算出的快照日 == 今天时补，
  否则打印 `⚠ 数据可能滞后` 告警。修复后 7 个板块全部拿到 08-20 数据。
- **评估过但未采用**：改用 tdx-finance MCP 取板块价格。实测 tdx 确实无 T+1 滞后
  （`CSSW电子 399811` 直接有 8/19、8/20 K线），但①口径不同（CSSW 8/19 跌 -8.10% vs
  申万 801080 跌 -7.77%，点位体系也不同），换源要重建 31 行业映射且历史不可比；
  ②MCP 只有对话层能调，脚本调不到，要用得逆向其 HTTP 端点与 token。
  而 T+1 这个唯一优势已被"快照补齐"解决，故维持 akshare，tdx 留作对话层交叉验证。

### ⑭ 「国际市场」过度吸收行业消息（2026-08-20，classifier v1.1.0 → v1.2.0）
- **问题**：用户发现重要行业消息被"国际市场"标签吞掉、不参与板块分析。219 条样本里

### ⑰ 八象限速查表补齐四要素 + 象限编号自洽校验（2026-09-02，sector-analyzer v1.9.0 → v1.10.0，analyst v1.5.0 → v1.6.0）

  "其余持仓不动"读作"其他板块不受牵连"），并把"处理对象由扩散度决定"改写为板块口径。

### ⑳ 新闻要点强制时间标注 + 资金流时点口径修正（2026-09-16，sector-analyzer v1.11.0 → v1.12.0，analyst v1.7.0 → v1.8.0）
- **问题**：要点里写着"港股存储芯片板块持续走低、南方两倍做多海力士跌超21%"，却不知道这是
  哪个时点的数字。**涨跌幅是时点数据**：盘中快照与收盘值能差几个百分点，同一天的"跌超21%"
  出现在 10:30 还是 15:00 收盘，交易含义完全不同；不标时间既无法复核，也无法判断该数字
  是否已被当天后续行情推翻。原先板块要点只到"2026-06-20："日期粒度，情绪一节干脆没有时间。
- **改动（prompt 层）**：新增三个 prompt 共用的 `TIME_RULE`（SECTOR/MACRO/SENTIMENT）：
  - 每条要点以 `[MM-DD HH:MM]` 开头，时间取所引新闻的发布时点（输入里本来就有，此前未要求使用）；
  - **凡写到涨跌幅/股价/点位/成交额/资金流，该数字必须能对应到时间**，数字时点与开头不同时
    在其后补 `（MM-DD HH:MM）`；**禁止出现无时间的涨跌幅**；
  - 情绪一节混用新闻与盘面硬数据，前缀分两类：`[MM-DD HH:MM]` 与
    `[硬数据·实时]`/`[硬数据·YYYY-MM-DD 收盘]`，且**只标一次**（首版实测出现开头标了、
    句尾又重复"（新闻，06-22 15:02）"的冗余，已在规则里禁掉）；
  - 指出新闻与硬数据冲突时**两边时点都要给**——实测很多"冲突"其实是 6 月盘中快照
    对 9 月收盘值的时点差，不标时间会被误判成数据错误。
- **顺带修正一个事实错误**：资金流表原注写"最新交易日为当日盘后初值，绝对值可能偏小"。
  实测同一天电子 09:30 拉到 **-4.0 亿**、14:44 拉到 **+196 亿** —— 那根不是盘后初值，
  是**当日盘中滚动累计值**。现在记录并展示**抓取时刻**（表头 `最新日（14:46滚动）`、
  内嵌行"截至 14:46 盘中滚动"），prompt 也禁止只凭最新日下"资金已回流"的结论。
- **顺带修一个稳定性问题**：`fund flow` 区间查询会**部分返回**——请求成功、只回一部分代码，
  `wd()` 的重试救不了（只在整批失败时重试）。改为按一级行业分批（每批 = 该一级 + 其二级）
  + 最多 3 轮按缺失代码补拉（末轮逐个单拉、只补一级）。盘中高峰前实测出现过一级 5/7、
  二级 24/35，加多轮后连测三次均为一级 7/7、二级 35/35，耗时 5~10s。
- **措辞纠偏**：二级全丢时原先输出"该行业二级细分腾讯源未编制指数"，把**临时丢批**
  说成了**源里没有**。现在分开写——真没有的才说未编制指数，丢批的写
  「本次未取到，应有 N 个二级，重跑可恢复」，并在表格里标 `本次取到 x/y 个二级，缺 …`。
