# 财联社新闻行业分析师

## 前置条件

- **必需**：CLS 新闻数据库 `E:/pythonPrj/cls_news_collector/cls_news.db` 存在且有数据
- **必需**：`cls-news/scripts/query_news.py` 可执行
- **必需**：`news-industry-classifier`（Phase 1 分类）、`news-sector-analyzer`（Phase 2 分析）skill 可用 + `DEEPSEEK_API_KEY` 环境变量已设置
- **必需**：`westock-data` skill + Node.js >= 18（Phase 2 的板块价格、估值、资金流与盘面硬数据经此获取）
- **可选**：`IWENCAI_API_KEY` 环境变量（用于 Phase 3 补个股级资金流/领涨股，无则跳过；**估值与板块资金流实测已由 Phase 2 自动出，不依赖它**）

## 输入解析

从 `$ARGUMENTS` 中解析用户时间意图：

| 用户表达 | 参数 |
|---------|------|
| "今天" / "今日" / 未指定 | `--today` |
| "昨天" / "昨日" | `--days 1`（需要调整：查昨天而非最近24h，用 `--from` + `--to` 精确到昨天日期） |
| "最近N天" / "近N天" | `--days N`（默认 N=1） |
| "本周" / "这周" | `--from {本周一} --to {今天+1}` |
| "上周" | `--from {上周一} --to {上周日+1}` |
| 指定日期范围 | `--from YYYY-MM-DD --to YYYY-MM-DD` |

## 分析逻辑（方法论）

本 skill 把"一堆新闻 → 板块投资判断"拆成 **分类 → 分析 → 报告** 三步，语义判断交给大模型、确定性工作交给脚本。

### 1. 分类逻辑（Phase 1）
把每条新闻归到 **34 个标签**：申万 31 个一级行业 + 3 个兜底类——
- **宏观**：货币/财政/地缘/政策等外部宏观，不指向单一行业
- **市场情绪面**：A股盘面/成交额/涨停/北向/IPO申购/并购统计等（**单独成类，不污染非银金融等行业板块**）
- **国际市场**：纯海外标的/市场
用大模型语义分类（非关键词），带 md 缓存加速（详见 news-industry-classifier）。

### 2. 板块分析逻辑（Phase 2）
- **筛重点板块**：行业类中新闻量 Top 7（排除宏观/市场情绪面/国际市场三个背景类）
- **每个板块五要素**：
  0. （实测硬数据，脚本自动内嵌）估值实测 + **资金流实测（含二级细分）**
  1. **新闻要点**（事实层）——保留原始新闻的公司/数据/事件，可追溯；
     每条以 `[MM-DD HH:MM]` 开头，**涨跌幅/股价/点位/成交额这类时点数据必须能对应到时间**
     （盘中快照与收盘值差别很大，不标时间无法复核、也无法判断是否已被后续行情推翻）
  2. **核心逻辑**——该板块当下为什么值得关注
  3. **机会**——具体受益方向/子环节
  4. **风险**——证伪点/隐患
  5. **验证信号**（框架灵魂）——下一步观察什么来确认/否定，必须可跟踪、可证伪：
     - 催化日历（即将发生的事件，带日期）
     - 基本面（价格/业绩/订单等硬数据；模型基于新闻给的是**定性观察点**，估值与资金流实测值由 Phase 2 自动内嵌，领涨股需 Phase 3 补）
     - 资金情绪（龙头股/成交/北向）+ **资金流实测**（主力净流入最新日/近5日/近20日 + 二级细分吸金↔失血，Phase 2 自动内嵌）
  · 附 **方向**（偏多/偏空/观望）+ **信心**（高/中/低）
- **宏观背景**：用宏观+市场情绪面+国际市场新闻，提炼风险偏好（外部宏观 + A股内部情绪）
- **跨板块主线**：1-3 条贯穿多板块的共性逻辑
- **板块估值实测**（第三节开头，脚本自动）：analyze.py 用腾讯源批量拉取各重点板块申万一级指数
  PE(TTM)/PB(LF)/股息率(TTM) 及三者**历史分位**，出实测表（含 DeepSeek 生成的逐板块"估值读法"）
  + "估值维度结论"，并在每个板块验证信号下内嵌一行实测值。**价格看"涨没涨"，估值看"贵不贵"**——
  同为消息偏多，低估值高股息（银行 PB 1.2% 分位）的风险收益比优于高估值分位（电子 PB 94.7% 分位）的"贵且不涨"。
  注意 prompt 已写死判读口径：股息率分位越高**反而越便宜**（模型极易搞反）
- **板块资金流实测**（第三节估值表之后，脚本自动）：analyze.py 用腾讯源批量拉取各重点板块
  申万一级行业指数**及其下全部二级细分**的主力资金净流入（最新日/近5日/近10日/近20日，亿元），
  出实测表（含 DeepSeek 生成的逐板块"资金读法"）+ "资金维度结论"，并在每个板块验证信号下内嵌实测行。
  **价格看"涨没涨"、估值看"贵不贵"、资金流看"谁在买"**——模型原有的"资金情绪"只是基于新闻的
  定性观察点，这一节是硬数据。**二级细分是关键**：一级加总会抹平内部分化（实测例：电子近5日
  整体 -192 亿，拆开是元件 +82 亿吸金、半导体 -153 亿失血）。申万三级腾讯源无资金流数据（恒为 0），
  故只到二级。取不到时同估值，写「本次不可得 + 原因」，不整节删除
- **预期差视角**（固定章节，排在附录之前）：analyze.py 用腾讯自选股源（westock-data skill）拉取各重点板块对应
  申万一级行业指数近 30 个交易日价格与量能（近30日/近5日涨跌幅、距高点回撤、量能比），
  并以上证指数为基准算近5日超额，按"消息×价格×扩散度"八象限框架（v2：±3%超额阈值、
  钝化档降档处理、量能佐证、逐板块证伪条件、象限迁移预判）定位象限——**利好不涨即利空，
  利空不跌即利多；个股背离换股，板块/市场级背离调总仓位**——用价格维度修正消息面判断并给操作纪律。
  方法论出处：`~/documents/预期差交易讲义-20260715.md`（v2）；行情源不可用时该章节降级标注，不阻断报告

### 3. 报告三层结构（Phase 4 产出）
- **事实层**：每板块的新闻要点 + 附录全量分类清单
- **判断层**：机会 / 风险 / 验证信号 / 方向 + 预期差象限定位（价格对消息面判断的修正）
- **溯源层**：附录按行业列出全部新闻，供核对分类对错
- 章节顺序：宏观背景 → 市场情绪 → **三、重点板块（开头含《板块估值实测》《板块资金流实测（含二级细分）》两张表）** → 跨板块主线 → **五、预期差视角补充** → 附录

### 设计原则
分类与分析都用"**脚本调 DeepSeek**"：大模型出语义判断（准、懂语境、零规则维护），脚本出分批/校验/重试/缓存/聚合（temperature=0 可重现、可无人值守、可扩展）。已否决两条弯路：关键词硬匹配（永远补不完、误分高）、让模型在对话里手写分类（脆弱、不可重现、不可扩展）。

按以下 5 个 Phase 顺序执行。每个 Phase 完成后输出简短进度信息给用户。

### Phase 0：数据获取

**目标**：从 CLS 数据库拉取新闻数据。

**步骤**：
1. 根据解析结果构造 cls-news 查询命令：
   ```bash
   python "$HOME/.agent-skills/skills/cls-news/scripts/query_news.py" {参数} > "<工作区>/news_raw.json"
   ```
2. 用 Read 工具读 `news_raw.json`
3. 解析 JSON：
   - 如含 `error` 字段 → 向用户报告错误并停止
   - 如 `count == 0` → 提示"指定时间范围内无CLS新闻数据"，停止
   - 如 `count > 500` → 提示用户"新闻量较大（{count}条），预计处理时间约X分钟"
4. `news_raw.json`（query 输出格式 `{count, items}`）供 Phase 1 直接读取

**输出**：工作区 `news_raw.json`，供 Phase 1 使用

### Phase 1：行业分类（调用 news-industry-classifier skill）

**目标**：把每条新闻分到 34 个标签（申万31一级 + 宏观/市场情绪面/国际市场）。

**方法**：本 skill **不自己做分类**，直接调用独立的 **news-industry-classifier** skill——它用大模型（DeepSeek）做语义分类，已内置分批/校验/重试，比关键词匹配准、零维护、可重现、可无人值守。

**步骤**：
1. 把 Phase 0 的新闻落盘为 JSON（query_news.py 输出格式 `{"items":[...]}`，如写到工作区 `news_raw.json`）。
2. 调用分类脚本：
   ```bash
   python "$HOME/.agent-skills/skills/news-industry-classifier/scripts/classify.py" "<工作区>/news_raw.json"
   ```
3. 用 Read 工具读取产出的 `news_raw_classified.json`，得到：
   - `distribution`：`{行业: 条数}`
   - `industries`：`{行业: [{id, title, time}]}`
4. 行业标签 = 申万31一级 + 三个兜底类：**宏观**、**市场情绪面**（盘面/成交额/涨停/IPO/并购统计，不归非银金融）、**国际市场**（纯海外）。详见上方《分析逻辑》。

**说明**：分类的准确性、分批、校验、重试、可重现性全部由 news-industry-classifier 负责，本 skill 直接使用其结果，**不再做关键词匹配或人工复判**。后续 Phase 2 的板块机会/风险/验证信号分析、Phase 4 报告均基于该 `industries` 结构。

---

### Phase 2：板块机会/风险/验证信号分析（调用 news-sector-analyzer skill）

**目标**：从分类后的新闻，对重点板块产出"机会 / 风险 / 验证信号"，并提炼宏观背景与跨板块主线。由独立的 **news-sector-analyzer** skill 完成——脚本调 DeepSeek，全自动、精简重点、可重现。

**步骤**：
1. 调用分析脚本（输入 Phase 0 原始新闻 + Phase 1 分类结果，`--out` 直接落盘到 documents）：
   ```bash
   python "$HOME/.agent-skills/skills/news-sector-analyzer/scripts/analyze.py" "<工作区>/news_raw.json" "<工作区>/news_raw_classified.json" --out "$HOME/documents/板块机会风险验证信号报告-{YYYYMMDD}.md"
   ```
2. 脚本自动完成（**无需人工逐行业分析**）：
   - **筛重点板块**：非背景类（排除"宏观"/"市场情绪面"/"国际市场"）中新闻量 Top 7（≥2条）
   - **每个重点板块**：新闻要点（原始新闻事实摘要，保留公司/数据/事件，每条带 `[MM-DD HH:MM]`
     时间前缀，涨跌幅等时点数据必须可对应到时间）/ 核心逻辑 / 机会 / 风险 / **验证信号**（催化日历带日期、基本面硬数据、资金情绪）+ 方向 + 信心
   - **宏观背景**：用"宏观"+"市场情绪面"+"国际市场"新闻提炼风险偏好（外部宏观 + A股内部情绪）
   - **跨板块主线**：1-3 条贯穿多板块的共性逻辑
   - **市场情绪温度**：除情绪面新闻外，另拉腾讯源盘面硬数据（全市场涨跌家数/涨停跌停/11档涨跌分布、两市成交额相对5/10/20/60日均值、三大指数涨跌、多周期新高新低），在报告第二节单列《盘面硬数据》表；prompt 规定硬数据优先于新闻转述，冲突时以硬数据为准
   - **板块估值实测**（第三节开头）：腾讯源批量拉取各重点板块申万一级指数 PE/PB/股息率及历史分位，出实测表 + 逐板块估值读法 + 估值维度结论，并在每个板块验证信号下内嵌实测行；**只认腾讯源，不降级到问财**（问财对措辞和行业个数敏感、会随机退化成个股返回，拿它顶数比缺数据更危险）；腾讯源返回 0 条时，脚本在该节原位输出「本次不可得 + 原因」的说明，**保留标题与原因，不得用其他口径或别的日期的数字顶替，也不得整节删除**
   - **板块资金流实测（含二级细分）**（第三节估值表之后）：腾讯源批量拉取各重点板块申万一级
     **及其下全部二级**行业指数的主力资金净流入（最新日/近5日/近10日/近20日，亿元；用历史序列
     逐日 `MainNetFlow` 自行累加，**不用**快照的 `MainNetFlow5D` —— 后者截止前一交易日、与当日值错位），
     出实测表 + 逐板块资金读法 + 资金维度结论，并在每个板块验证信号下内嵌实测行；
     申万三级腾讯源资金流字段恒为 0，**只到二级，不取三级**；取不到时同估值，原位写「本次不可得 + 原因」。
     ⚠️ **「最新日」是当日盘中滚动累计值**（同一天 09:30 与 14:44 拉到的数能差出两百亿），
     表头与内嵌行都带抓取时刻，判断方向以近5日/近20日为准
   - **预期差视角补充**（固定章节，排在附录之前）：腾讯源批量拉取各重点板块申万一级指数近30个交易日价格（近30日/近5日涨跌幅、距高点回撤），按"消息×价格×扩散度"八象限定位，用价格修正消息面方向判断，给扩散度判定、总体结论与操作纪律；章节开头固定输出《这一节是什么》入门说明（动机+三维度白话解释+**八象限速查表：每格给「机制｜仓位档｜具体动作｜绝对不做」四要素，仓位档带具体数字**+处理对象与口径转换+怎么用+风险提醒），供不熟悉预期差框架的读者上手；逐板块「应对」强制含仓位档+动作+禁令；象限编号与扩散度自洽由 prompt 硬约束 + `check_quadrant()` 脚本校验（不自洽则在该行追加 ⚠️ 标注）；行情源不可用时降级标注
3. 报告经 `--out` 落盘到 `~/documents/板块机会风险验证信号报告-{YYYYMMDD}.md`；另在工作区产出 `*_analysis.json`（结构化，含 `prices`/`gap`/`valuations`/`fund_flows`）。用 Read 工具确认。

**说明**：板块分析由独立的 **news-sector-analyzer** skill（脚本调 DeepSeek）完成，筛板块/分批/重试/组装由脚本负责，`temperature=0` 可重现、可无人值守。**验证信号是框架灵魂**——让报告从"事后描述"变成"前瞻可跟踪"（给出可证伪的观察对象）。**预期差章节是价格维度的裁决**——消息面判断（方向偏多/偏空）必须经过价格反应检验，利好不涨即利空。

### Phase 3：定量数据增强（可选）

**目标**：**估值实测（PE/PB/股息率+分位）与资金流实测（一级+二级细分主力净流入）都已由 Phase 2 自动完成，不要在这里重复做**。本阶段只补 Phase 2 没有的：**个股级**资金流与领涨领跌个股（板块级资金流走腾讯源，已覆盖到申万二级）。

**前提**：`IWENCAI_API_KEY` 已设置且用户需要定量增强；否则跳过（analyze 报告已自洽，不缺这步也完整）。

**步骤**：
1. 取 analyze 报告中的 Top 板块（来自 `news_raw_analysis.json`）
2. 对每个板块用 Skill 补充数据（参考 `references/hithink-queries.md`、`references/industry-etf.md`）：
   - **Skill(hithink-sector-selector, "{板块} 领涨股 领跌股")**
   - **Skill(hithink-industry-query, "{板块} 行业 ROE")**（**不要再查行业资金流向**——Phase 2 已给到申万二级）
3. 把实测数据回填到报告对应板块的"验证信号-资金情绪"下，标注实测值与日期；
   回填的是**个股级**信息，不要覆盖或改写 Phase 2 已内嵌的「资金流实测」行（口径不同，两者并列）

⚠️ **问财返回粒度的坑**：query 写"{板块}行业xxx"会被解析成申万行业指数（返回指数级数据）；写"电子 计算机 …… 主力资金净流入"会退化成**个股列表**（几百条），不是行业聚合值。要行业级聚合就明确写"行业"二字；要个股必须写"所属申万一级行业是X的股票"。行业级估值不要走问财——Phase 2 的腾讯源已经给全了

**错误处理**：API 失败则保留 analyze 原始信号，标注"数据待补充"，继续。

---

### Phase 4：报告确认与摘要

**步骤**：
1. 报告已由 Phase 2 的 `--out` 直接落盘到 `~/documents/板块机会风险验证信号报告-{YYYYMMDD}.md`（若做了 Phase 3，把实测数据回填进该文件；若文件已存在则改名加 `_v2`）。
2. 用 Read 工具确认落盘、字节数正常、内容完整（宏观背景 + 板块估值实测表 + 板块资金流实测表 + 各板块机会/风险/信号 + 跨板块主线 + 预期差视角补充在附录之前）。

## 错误处理速查

| 场景 | 行为 |
|------|------|
| DB文件不存在 | Phase 0 返回 error JSON → 提示用户检查采集器状态，停止 |
| 0条新闻 | 提示"指定时间范围无数据"，停止 |
| 分类脚本报错（DEEPSEEK_API_KEY未设/API失败） | 检查 key 与网络后重跑 classify.py，不要回退到关键词匹配 |
| IWENCAI_API_KEY 未设 | Phase 3 跳过，报告中标注，继续 |
| hithink API 报错 | 重试1次简化查询，仍失败则标注"数据暂不可用"，继续 |
| hithink 返回空 | 尝试别名查询，仍空则标注"数据不可用"，继续 |
| westock-data（腾讯源）报错/返回 0 条 | **行情源全挂也必须出文档**（新闻分析是报告主体，不依赖腾讯源）；**不降级到问财，改为「略过该部分 + 写明原因」**：估值、资金流、盘面硬数据、板块价格四处取不到时，脚本在原位输出「本次不可得／本次未取到——腾讯源 … 返回空，该路由 2026-09 起间歇性故障」，**标题保留**；Agent 不要另找接口凑数，**不得用别的时点或别的口径的数字顶替，也不得把整节删干净**——整节消失会让读者以为该维度正常无异常 |
| 新闻>500条 | 分批（每200条）处理 Phase 1，提示处理时间 |
| 分类结果分布明显失衡 | 检查 news-industry-classifier 输出，必要时重跑（temperature=0 可重现） |
