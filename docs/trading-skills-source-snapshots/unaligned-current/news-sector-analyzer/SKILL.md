# 板块机会/风险/验证信号分析器（news-sector-analyzer）

从已分类的新闻里，对重点板块产出"机会 / 风险 / 验证信号"，供投资研判。

## 设计理念
分析判断交给大模型（懂语境、会从新闻提炼逻辑），筛板块/分批/重试/组装报告交给脚本
（确定、可重现、temperature=0、可无人值守）。**验证信号是核心**——让报告从"事后描述"
变成"前瞻可跟踪"（给出可证伪的观察对象）。

## 用法
```bash
python scripts/analyze.py <news.json> <classified.json> [--out <报告路径>]
```
- `news.json`：cls-news `query_news.py` 输出（含 content）
- `classified.json`：news-industry-classifier 产出（`industries: {行业:[{id,title,time}]}`）
- `--out`：可选，报告输出路径（默认 `<news>_analysis.md`）；可直接指向 `~/documents/...`
- 另产出 `<news>_analysis.json`（结构化结果，供下游回填/二次加工）

## 分析框架
- **筛重点板块**：非背景类（排除"宏观"/"国际市场"）中新闻量 Top 7（≥2 条）
- **每板块**：**新闻要点**（保留原始新闻的公司/标的/数据/事件，事实层、可追溯）/ 核心逻辑 / 机会 / 风险 / **验证信号**（催化日历带日期 + 基本面硬数据 + 资金情绪）+ 方向 + 信心
- **宏观背景**：用"宏观"+"国际市场"新闻提炼 1-2 条决定风险偏好的主线
- **跨板块主线**：1-3 条贯穿多板块的共性逻辑
- **市场情绪温度**（第二节）：除盘面情绪新闻外，另拉腾讯源盘面硬数据喂给模型并在报告里单列
  《盘面硬数据》表——全市场涨跌家数/涨停跌停/11 档涨跌分布（当日实时）、两市成交额及其
  相对 5/10/20/60 日均值的百分比、三大指数涨跌、多周期新高新低家数（收盘统计口径）。
  prompt 规定硬数据优先级高于新闻转述，冲突时以硬数据为准并点明冲突，要点必须带具体数字。
  用途：新闻常说"成交活跃/情绪火热"，硬数据能直接证伪——如成交额只有 20 日均值的 79%、
  20 日新低多于新高，说明是缩量普涨而非全面转暖
- **板块估值实测**（第三节开头，固定章节）：用腾讯源批量拉取各重点板块申万一级行业指数的
  PE(TTM) / PB(LF) / 股息率(TTM) 及三者的**历史分位**，报告里出一张实测表（每板块一句"估值读法"
  由 DeepSeek 生成），并在每个板块的验证信号下内嵌一行估值实测值；另给"估值维度结论"把估值
  与消息面方向对照。判读口径写进 prompt：PE/PB 分位越高越贵，**股息率分位越高反而越便宜**
  （价格低才推高股息率，模型极易搞反）；PE 为负时不用 PE 判贵贱、改用 PB+股息率并点明盈利未修复。
  用途：与价格维度互补——价格看"涨没涨"，估值看"贵不贵"。同为消息偏多的板块，
  低估值+高股息（如银行 PB 1.2% 分位、股息率 96% 分位）的风险收益比明显优于
  高估值分位（如电子 PB 94.7% 分位）的"贵且不涨"。数据源失败时该章节整体跳过，不阻断报告
- **板块资金流实测**（第三节估值表之后，固定章节）：用腾讯源批量拉取各重点板块申万一级行业指数
  **及其下全部二级细分行业**的主力资金净流入（最新日 / 近5日 / 近10日 / 近20日，单位亿元），
  出一张实测表（每板块一句"资金读法"由 DeepSeek 生成）+ "资金维度结论"，并在每个板块的
  验证信号下内嵌一行资金流实测值（含二级"吸金 ↔ 失血"对照）。
  用途：价格看"涨没涨"、估值看"贵不贵"、**资金流看"谁在买"**——模型原有的"资金情绪"
  只是基于新闻的定性观察点，这一节是硬数据。
  **二级细分是本节的价值所在**：一级是加总值，会把内部分化抹平。实测例——电子近5日整体
  净流出 192 亿，但拆开看是元件 +82 亿逆势吸金、半导体 -153 亿 / 消费电子 -81 亿失血，
  "全面失血"与"结构性分化"的操作含义完全不同。
  口径（已写进代码与 prompt）：用历史序列逐日 `MainNetFlow` 自行累加算 1/5/10/20 日，
  **不用**实时快照里的 `MainNetFlow5D/10D/20D`——后者截止到前一交易日、与当日值错位，
  且快照的当日值与历史序列同日数值口径不一致（数量级偏小）。
  **申万三级（`pt0185xxxx`）腾讯源无资金流**（字段恒为 0，只有收盘价），故本节只到二级，
  代码表也不收三级——把 0 渲染成"零流入"会被读成"无资金动向"。
  数据源失败时按"宁缺勿替"写「本次不可得 + 原因」，不整节删除
- **预期差视角**（固定章节，排在附录之前）：用腾讯源拉取各重点板块对应申万一级行业指数
  近 30 个交易日价格与量能（近30日/近5日涨跌幅、距30日高点回撤、量能比=近5日/前25日均量），
  另拉上证指数作市场基准计算近5日超额收益（基准失败则降级为绝对涨跌），再由 DeepSeek 按
  "消息×价格×扩散度"八象限框架（v2）逐板块定位象限、判定扩散度层级、给应对与操作纪律。
  报告里的**八象限速查表按讲义补齐到四要素**——「市场在说什么（机制）｜仓位档｜具体动作｜绝对不做」，
  仓位档给具体数字（2=偏高档70%~90%、4=降至防守档≤30%~50%、6=总仓位≤30%杠杆清零、7=单笔≤10%试探、
  8=逐步回标准档50%→70%），禁令取自讲义各格的"常见错误"；prompt 同步要求逐板块「应对」必须含
  ①该象限仓位档（照抄不得自行发明数字）②具体动作 ③一条禁令，禁止只写"持有""观望"。
  v2 判定标准：近5日超额 ≥+3% 算涨、≤-3% 算跌、之间算"钝化"（降档处理，利好钝化偏空看、
  利空钝化偏多看）；量能佐证（涨+缩量=反抽存疑，跌+缩量=惜售存疑）；每个板块判断必须附
  证伪条件；输出含象限迁移预判。核心纪律双向对称：利好不涨即利空、利空不跌即利多；
  个股背离换股，板块/市场级背离调总仓位；回补只认价格信号（企稳+缩量+重新放量突破）。
  **象限编号与扩散度自洽是硬约束**：奇数号 1/3/5/7 只配"扩散小"、偶数号 2/4/6/8 只配"扩散大"。
  编号与仓位档硬绑定，错一位就会把"回避这个板块"升级成"清空全仓"（实测模型曾把单板块下跌
  写成「第6象限（利空+跌+扩散小）」并给出总仓位≤30%）。prompt 写死该约束并特别说明 5 与 6、
  3 与 4 的分界；`check_quadrant()` 再做脚本层校验——不改写模型判断，只在该行追加 ⚠️ 标注
  并打印告警，让读者知道该行不可信。另因本报告分析对象是板块，prompt 要求 1/3/5/7 格的
  措辞用"该板块"而非"该股"，报告表下附口径转换说明。
  方法论出处：`~/documents/预期差交易讲义-20260715.md`（v2，八象限逐条细化+量化判定标准）
- **相关个股**（每个板块小节内）：该板块新闻里出现的上市公司 + 股票代码，
  由 `scripts/stock_industry.py` 查申万个股分类表得到，**不参与分类判断**，
  只做实体标注，服务于"验证信号-资金情绪"的龙头股跟踪
- **附录**：全量新闻按行业分类清单（含宏观/国际/非重点板块，时间+标题），供溯源核对分类对错

## 机制
- 引擎 DeepSeek `deepseek-chat`，`temperature=0` 可重现
- 每板块一次调用；宏观、情绪、跨板块、估值读法、资金读法、预期差各一次；Top7 约 13 次调用，几分钟
- 每次调用重试 ≤2 次；失败板块跳过不影响其他
- **行情数据源**：全部走 westock-data skill 的 CLI（`node .../westock-data/scripts/index.js ... --raw`），
  由 `wd()` 统一封装，失败重试 2 次。路径默认 `~/.agent-skills/skills/westock-data/scripts/index.js`，
  可用环境变量 `WESTOCK_DATA_JS` 覆盖。拉取失败时预期差章节降级标注"数据不可用"，其余报告不受影响
- **批量拉取**：腾讯源支持逗号批量，7 个板块近 30 日日线**一次调用**拿完（实测 ~1s）；
  加上基准与情绪硬数据，整个数据层约 3s。
  ⚠️ **区间查询有隐性批量上限**：`fund flow --start/--end` 返回「代码×交易日」行，
  一次传 40+ 个代码会整批丢失（上游超时，返回空而非报错，表现为"部分板块无数据"）。
  `FLOW_BATCH=20`（约 480 行）实测稳定，7 个板块含二级共 ~55 个代码分 3 批、2.5s 拿完
- **无需代理切换**：腾讯接口直连走代理正常，不必像旧 akshare 路径那样临时清空代理环境变量
- **日线含当日**：腾讯源盘中/盘后即有当天这根，不存在 T+1 源"盘中跑会静默用上一交易日数据"
  的问题（旧 akshare 路径为此需要拉实时快照回补，已随换源一并移除）。
  ⚠️ 代价是盘中运行时最新一根是**盘中价**而非收盘价，报告已固定标注这一点
- **证伪条件必须够得着**：`fetch_prices` 额外算出现价到「近5日高点/近10日高点/5日均线/
  近5日低点」的百分比距离，标注【够得着】（≤5%）或【太远】，喂给模型；prompt 规定
  只能用【够得着】的锚点、时间窗口一律「3个交易日内」、并写明百分比距离。
  **严禁"收复前高"这类远端价位**——回撤 -23% 的板块三天内根本到不了，
  永不触发的条件等于没有条件，会架空整个证伪机制
- **个股标注只做实体查询，不做分类**：新闻提到某公司 ≠ 该新闻属于该行业
  （午评/竞价看龙头这类会罗列大量跨行业个股）。因此只保留 `l1 == 板块名` 的命中，
  分类始终由 news-industry-classifier 的大模型负责

## 依赖
- 环境变量 `DEEPSEEK_API_KEY`（未设置则报错停止）
- `westock-data` skill + Node.js >= 18（行情数据源：板块价格、板块估值分位、板块资金流、上证基准、盘面硬数据）
- `references/stock-industry.json`（可选，个股标注；缺失则跳过该行，不影响其余报告）
- `references/sw-sector-codes.json`（资金流的二级细分代码表；缺失则降级为只用内置一级代码）
- 其余仅 Python 标准库（urllib）

## 个股标注数据（references/stock-industry.json）
6295 条简称→`{code, l1, l2, l3, sw, mkt}`，含 A股/港股/美股。由 `scripts/build_stock_industry.py`
从三个底表生成（换表后重跑该脚本即可，`stock_industry.py` 无需改动）：

| 用途 | 底表 | 说明 |
|------|------|------|
| A股行业 | `<sw-dir>/StockClassifyUse_stock.xls` | 申万分类，一股多行历史沿革，取**计入日期最新**的一行 |
| 行业代码→名称 | 同目录 `SwClassCode_2021.xls` | 511 行 = 31 一级 + 134 二级 + 346 三级 |
| A股简称 | `<tdx>/T0002/hq_cache/infoharbor_ex.code` | 通达信本地数据（GBK，`代码\|简称\|别名`），随盘后数据更新 |

底表路径默认 `D:/2345Downloads/SwClass` 与 `E:/new_tdx64`，可用 `--sw-dir`/`--tdx`
或环境变量 `SW_CLASS_DIR`/`TDX_ROOT` 覆盖；缺文件立即报错退出，不会产出半张表。

**行业层级**：A股 5555 只**三级覆盖率 100%**。`sw` 是 6 位申万内部分类码
（如 730204），前 2 位定一级、前 4 位定二级 —— **与 `801xxx` 指数代码是两套编码，勿混用**
（指数代码见 `news-industry-analyst/references/shenwan-industries.md`）。
完整行业树用 `build_stock_industry.py --tree` 导出到 `references/sw-industry-tree.json`。
少量仍挂 2021 版之前旧三级码的标的 `l3` 为空（当前 66 只，均已退市），前缀能定到几级写几级，不猜。

- **A股 5555 只**，覆盖北交所与最新上市新股（信胜科技 920093、马矿股份 601123 等）。
  不用 tdxquant MCP 取名称：它需通达信客户端在运行且脚本层调不到，
  `infoharbor_ex.code` 是同一份本地数据的落盘产物，离线可读、可复现。
- **港股/美股 736 条沿用 2021 年旧表**（申万个股分类表不含），新标的可能漏标——
  漏标是预期内降级，分类由大模型兜底。

两条规避误匹配的规则（均由实测确定）：
- 只保留 **≥3 字**简称（`柳工`/`李宁`/`微博` 这类 2 字简称误伤率高）
- `references/stock-blacklist.md` 黑名单剔除通用词与信源名
  （`机器人`/`航天工程`/`人民网` 等本身是常用词的简称），该文件可直接编辑

匹配用**长名优先 + 字符占位**，不用"左右不邻汉字"做边界——中文无词间空格，
那样会把"中芯国际跌超3%"误拒。A股 `*ST`/`ST` 前缀同时注册去前缀别名；
港股旧表里带 `-U`/`-W`/`-SW` 后缀的（`宝尊电商-SW`）同时注册去后缀别名。

单独使用：
```bash
python scripts/stock_industry.py news.json              # 逐条列出命中个股
python scripts/stock_industry.py news.json --by-sector  # 按申万一级行业聚合
python scripts/stock_industry.py 中际旭创 --lookup      # 查个股 → 一/二/三级（也可传6位代码）
python scripts/stock_industry.py 光学元件 --list        # 列某行业全部个股（一/二/三级任意层级）
```

重建映射：
```bash
python scripts/build_stock_industry.py --tree
```

## 板块代码表（references/sw-sector-codes.json）
「申万一级/二级中文名 → 腾讯板块代码」，31 个一级 + 123 个二级（申万 134 个二级中，
林业Ⅱ/农业综合Ⅱ/其他家电Ⅱ/旅游零售Ⅱ/体育Ⅱ/本地生活服务Ⅱ/其他银行Ⅱ/综合Ⅱ/社交Ⅱ/
油气开采Ⅱ/医疗美容 共 11 个腾讯源未编制指数，表内缺失并在 `二级缺失` 字段标出）。

腾讯板块代码 = `pt01` + 申万指数码（如 电子 801080 → `pt01801080`），与个股映射表里的
6 位申万**分类码**（730204 那种）是两套编码，勿混用。

重建：
```bash
python scripts/build_sw_sector_codes.py
```
做法是**批量探测**——申万指数码集中在 801010~801999，但哪些码有效无公开规律，
而 `fund flow` 批量查询对无效码静默丢弃，返回的即为有效板块，再用 `sw-industry-tree.json`
的一级/二级中文名做归属匹配（腾讯名带「Ⅱ/Ⅲ」后缀，匹配前归一化）。申万调整行业后重跑。
