# 主流交易理论到伪代码研究计划

日期：2026-11-16，研究交付于 11-17。状态：S0–S5 本轮文档研究完成，18 章 228 张卡均有冻结初稿、来源状态、规则/伪代码与非作者审查。研究正文见[研究入口](theory-to-pseudocode/README.md)，原法来源与形式化留项见[覆盖表](theory-to-pseudocode/coverage.md)。

执行补充：用户要求“不深究实现细节”。本轮将相关方法的独立研究卡按 18 个家族编章，保留各自 ID、来源、规则、伪代码与反例，便于连续阅读；不把每个指标扩成工程规格。伪代码重点解释交易判断和失效路径，共同时间/风险约束集中引用。

## 1. 目标与本轮边界

围绕“当前系统缺少经充分验证、能够持续贡献收益的策略”，先形成可追溯、可证伪、可形式化的候选规则库。严格按 **模型知识初稿 → 权威原著核验与修订 → 规则定义 → 伪代码 → 独立反例审查** 推进。

本轮研究终点是理论报告与伪代码规格。策略实现、行情采集、数据库改动、参数优化、历史回测、纸面前推、实盘、通知和打包均不属于本计划的执行内容。研究可以讨论其他市场，但不扩大现有系统的市场、交易品种和账户授权。

“稳定赚钱”是后续需要验证的目标，不能由名著、逻辑自洽、多个 agent 达成一致或伪代码完成来证明。本轮只明确未来如何证伪和验证，不预先指定年收益、胜率或回撤承诺。

默认研究以沪深股票的适用性为重点，兼顾项目已有 BTC/ETH 现货范围；期货、外汇、期权、做市等纳入理论全景并标注接入条件。日线/周线先研究，盘中方法保留原频率要求，不能改成日线后仍冒称原法。

## 2. 已核对的项目起点

- [现有方法盘点](../strategy-inventory.md)记录 695 条方法，其中包含参数变体、评分分支、风控、指标和工具，不能当作 695 套独立策略；该文件是历史盘点，当前实现需按路径再核对。
- [最新 L3 成绩单](2026-11-lifecycle-scoreboard.md)中，数字货币波段 24 个配置完成计算而未通过晋级；A 股波段、低位与数字货币突破主要因来源和共同日期轴等证据不足未计算可信收益。两种结果必须分开。
- [路线图](../roadmap.md)、[当前计划](../next-plan.md)和[正确性约束](../invariants.md)已经定义策略、指标、撮合、绩效及原生缠论边界；研究只建立映射，不重做这些工程模块。
- 现有技能、方法 JSON、代码、历史报告都可作为检索与差异对照材料；它们不是原著，也不能用代码当前行为反向定义理论。

研究优先级依据理论清晰度、来源质量、数据可得性、交易可行性和与现有能力的距离确定，不依据已经看过的留出收益选理论。旧留出结果已知，未来不能因更换策略名称就将同一段历史重新称为未见样本。

“主流”没有有限且公认的全量集合。S1 用经典著作、原始研究、专业教材/课程和可追溯实务传播建立纳入理由；记录新增、别名合并与遗漏。目录版本冻结后才进入书籍核验，后续新增项使用新版本单独补齐全部阶段。

横向遗漏审查还需覆盖多空不对称、退出与再入场、状态切换、策略相关性/资金竞争，以及认知偏差、交易纪律和决策日志。心理纪律作为研究与执行约束记录，不捏造成自动交易信号。研究 ID 关联项目已有 `category / methodId / strategyId`；本目录的 18 个研究家族不要求把系统现有分类改成 18 类。

## 4. 多 agents 与 code-mode 工作方式

采用 **1 个统筹 agent + 最多 3 个并行执行 agent**，按阶段轮换角色，不假装同时运行超过可用并发数的团队。

| 角色             | 职责                                                    | 交付及约束                                         |
| ---------------- | ------------------------------------------------------- | -------------------------------------------------- |
| 统筹/主编        | 目录、分批、术语、冲突裁定、归并与验收                  | 唯一维护总目录和汇总；不以投票代替证据             |
| 理论研究员 A/B/C | S1 按理论家族并行写模型知识初稿                         | 每条有边界和反例；本阶段不先查书再倒写成模型初稿   |
| 来源研究员       | S2 查原著、版本、章节与原始论文                         | 指出初稿哪些正确、哪些遗漏、哪些错误、哪些尚未核验 |
| 形式化研究员     | S3 将核验后的规则拆成变量、状态、动作与伪代码           | 不补造原著没有的数值阈值；研究假设独立标注         |
| 独立审查员       | S4 专查反例、未来信息、可成交性、来源混用和伪代码闭合性 | 不由同一 agent 同时编写和最终验收同一条规则        |

来源、形式化和审查角色占用三个执行槽位，按批次流水推进；同一理论的依赖步骤串行。不同家族互相审查，主编处理跨族术语冲突。

code-mode 的用途：通过 `functions.exec` 批量并行只读目录/来源检索，结构化汇总来源状态和规则字段，检查 ID、别名、引用与相对链接，生成覆盖/缺口表。独立工具读取用 `Promise.allSettled`，逐个处理失败；依赖操作顺序执行，agent 调度使用独立 collaboration 工具。

本轮不运行策略、不搜索最优参数、不让工具自动执行生成的伪代码。数值手算案例仅解释状态与规则，不产生历史业绩结论。

## 5. 每个方法的固定研究卡

每个独立方法一张卡，指标工具可共用定义并通过 ID 引用，不能让某个家族的一篇泛论代替全部方法的规则说明。

1. **身份**：稳定 ID、别名、主家族、条目类型、原始市场/频率、项目适用范围、旧目录映射。
2. **模型初稿 v0**：理论核心、收益机制假说、关键概念、典型交易链、适用/失效环境、模型不确定点。原样保留以便比较。
3. **原著修订 v1**：作者、原书名、版本/年份、章节/页码或段落、网址、访问日期、实际可读范围；逐条记录“保留/纠正/补充/未核验”。
4. **证据与争议**：原作者主张、独立实证、反证、后人改编各自列明。原著是定义来源，不自动证明收益有效。
5. **数据合同**：字段、单位、频率、复权、预热、证券池时点、首次公开/可用时间、缺失处理、交易制度与成本输入。
6. **规则合同**：环境、选池、排序/并列处理、入场、仓位、加减仓、止损/止盈、时间退出、撤单/过期、冷却、组合冲突、停用与恢复。
7. **参数表**：符号、意义、单位、允许范围、原著值/项目适配/研究假设、敏感方向；暂缺来源的值保持符号化，不编一个数字。
8. **形式化与伪代码 v2**：必要谓词的计算、状态转移、确认时点、输出原因、缺失和异常分支；按市场写适配差异。
9. **逐步示例**：至少正常成立、失败/退出、缺数据/尚未确认各一例；主观图形再增加歧义或反事实例，组合方法增加并发冲突例。
10. **审查结论**：规则可直接形式化 / 明确假设下可形式化 / 依赖人工判断 / 证据不足；现有能力映射、未决问题及未来验证命题。

每条交易规则必须能反查到来源或明确标注的研究假设，链路为 `methodId → claimId → sourceId → ruleId → pseudocodeStep → exampleId`。概念出处与实现假设不能合并成一个“参考书目”段落敷衍。

## 6. 原著与来源协议

优先次序为原作者著作/原文/原始论文，随后是作者机构与出版社的合法节选、可靠学术或专业解释，最后才是二手总结。已有本地技能只作导航与待审查摘要。

访问状态与证据强度分开记录：`full-text`、`excerpt`、`toc`、`bibliography-only`、`unavailable`。看到书名或目录只能确认书目或研究定位，不能写“已经结合原著完善所有细节”。查不到章节则明确缺口；不编造页码，不用模型记忆冒充实时查阅，不以付费墙为由擅自购买。

书籍总结采用自己的语言，以规则和差异为中心，必要时短引文，不能复制整章。书籍译名不一致时保留英文原名。作者不同版本、课程更新和 A 股适配分别编号。

重点处理：CANSLIM 与 SEPA 原法和本地技能门槛可能不同；缠论按课号核验正文并分离后续解释和 DLL 算法；龙头战法按可追溯流派拆分，找不到单一权威书就如实记录，不能套用某位知名游资的名义；马丁按资金递推和概率条件讨论，不寻找“保证回本”的权威背书。

## 7. 伪代码的统一交付要求

用接近 TypeScript 的语言无关伪代码，保留领域公式；不直接接入项目 API。每张卡展开自己的关键谓词，不能只写 `if 是龙头 / 出现三买 / 形成五浪 then buy`。

统一至少表达 `OBSERVE → SETUP → ARMED → ORDER_INTENT → HOLD → EXIT_INTENT → COOLDOWN`，允许简单方法合并状态；多腿、网格、组合等使用适合自己的子状态。决策意图不等于成交，仓位只随实际成交事件变更。

以下只是规格示意，不是某理论的已完成策略：

```text
每个决策时刻 t：
    只读取在 t 已公开的信息及已完成的相应周期行情
    根据已确认成交更新实际持仓；交易意图不当作成交
    先按该卡明示的保护、逻辑失效和时间条件判断退出
    若需要退出：保留 EXIT_INTENT，不能成交时仍保留持仓与风险
    若关键证据缺失、退出待处理或交易前提不成立：停止增加风险

    对已有候选先检查失效和到期，再判断是否触发
    依据该卡展开的结构/财务/事件条件形成候选
    未确认的笔、浪、极值和未完成周线不能当作确定输入
    条件确认且允许新仓时：
        用预登记资金、单笔风险和总库存上限限制数量
        若资金及可成交条件允许：产生 ENTER_INTENT
        收盘确认的信号只能在其后的合规机会尝试成交
    否则 WAIT；不重复消费同一信号

    成交确认后才进入 HOLD；退出成交后才进入冷却/新一轮观察
    保留当时依据，后来的结构变化不能重写已作出的判断
```

逐项规定原始数据事件时间、首次可用时间、结构确认时间、决策时间与最早成交时间。用收盘价确认的信号不能回填当根低点成交；盘中触发必须有相应频率证据。高周期未收线、财务后来修订、今日成分回填历史、全样本归一化和未来标签都需显式排除。

逐前缀审查的对象是当时输入可见性和已作出的决策。未确认的笔、浪、结构可以变化，但变化不能改写先前决策；原理论确实依赖事后解释时，保留该边界，不把它包装成实时信号。

理论通用层与市场适配层分开：A 股的可卖时点、涨跌停/停牌、不同板块规则、数量单位等交给注明适用日期的市场合同；做空、杠杆、多腿或盘口缺失时返回“不具备交易前提”。具体交易规则在编写该卡时查询交易所当期原文，本计划不硬编码旧制度。

马丁/网格要列初始资金、每层数量、累计库存、最大层数、停止/退出、追加资金来源与不利路径。倍增示例在等额赔率等明确假设下才可用几何级数计算资金需求；加仓本身不建立价格预测优势，止损也不保证跳空时按指定价成交。

一个执行任务限定为一个家族的初稿、一组来源核验或约 3–6 张简单规则卡的形式化/审查；波浪、缠论、龙头按概念和交易链拆小。完成一个批次后报告已完成条目、来源缺口、规则争议和下一批；不以没有依据的固定工期保证全面完成。

最终验收口径：所有目录项均有初稿、来源状态、规则规格和审查结论；可形式化项有完整伪代码；依赖人工/证据不足项仍交付可确定部分的伪代码以及明确的 `UNRESOLVED/NO_DECISION` 分支，单列未解决数，不能计为可执行策略完成。计划完成、理论完成、书籍核验完成、规则完成与收益验证完成是不同状态。

## 9. 文档组织与收尾

研究在 `docs/research/theory-to-pseudocode/` 集中存放 `catalog.md`、`sources.md`、18 个家族章节内的独立方法卡和 `review.md`，并在 roadmap/next-plan 建立入口。先复用现有目录及原文索引，不预建大量空文件，不复制整套技能/书籍库。

每张方法卡保留 v0 初稿、v1 修订差异、v2 规则和审查记录，避免重复维护多份同内容长文。最终综述按“理论机制 → 规则 → 伪代码 → 局限 → 后续验证”连续阅读，横向表只负责导航与比较。

纯文档检查：内容、相对链接、ID/覆盖和 `git diff --check`；不运行应用测试、构建或数据库初始化。本轮不创建临时工作树/构建/行情副本，不提交、不推送。后续如需临时检索产物，集中到一个明确任务目录并在交付时清理。

后续验证计划应包含费用后收益、基准、样本外稳定性、参数邻域、回撤/尾部、容量、多重检验及自然时间前推；这些属于后续实现与实验。本轮只写预期检验命题。多次尝试与选择性报告会夸大绩效的依据见 Bailey 与 López de Prado 的 [Deflated Sharpe Ratio 原论文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)，本轮已读取论文摘要及相关正文，不据此替代各交易体系的实证检验。
