# 缠论原生结构扩展计划（B4 挂起 9 项）

日期：2026-09-17。用户已授权单独拟定计划并拉分支实施。分支：`chan-native`。

对应 [B4 批次](trading-skills-execution-optimization.md) 挂起的 9 项：`CH06`、`CH07`、`CH08`、`CH09`、`CH10`、`CH11`、`CH12`、`CH13`、`CH18-small-to-large`。这 9 项在 B4 中被逐项登记为原生结构缺口或历史输入缺口，未用 kind 标签或趋势方向销账，也未自造近似冒充原文方法。

## 1. 调研结论（只读核查，已完成）

### 1.1 缺口不是算法缺失，是投影面缺失

| 事实                                                    | 证据                                                                                                                                                                           |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DLL 为第三方 GPL v3 作品，但**源码在本机且可重建**      | `vendor/czsc/README.md`：来源 `D:\github\czsc-tdx` commit `b67f3c6`，848,571 字节，SHA-256 `c0ac4c51…`，2026-09-09 由管理者用 WSL Ubuntu-22.04 + MinGW-w64 `make mingw64` 重建 |
| 构建工具链可用                                          | `wsl -l -q` 返回 Ubuntu-22.04                                                                                                                                                  |
| 候选、中枢和走势成员集合已在 C++ 内存中（完成证据不在） | `src/CzscTdxExports.cpp:821/826/845` 的 `ApplyTradingSignal*(nCount, pOut, An.Candidates, An.Centers)`——`An.Candidates`、`An.Centers` 是完整集合                               |
| 现有输出只投影**胜出候选**的属性，且每根 K 线一个 float | `czsc-worker.ts` 的 `CzscCalc(int n, float *out, …)`；`czsc.ts` 校验 `output <= 58`                                                                                            |
| 因此拿不到"走势成员列表""高级别候选表"这类数组          | 9 项缺口登记逐条指向这一点，例如 CH06「trendId 不是可访问的走势数组」、CH07「缺 output50 索引的完整高级别 Candidates 表」                                                      |

**原调研结论（C1 核查已修正，见 §5.1）**：这 7 项原生缺口的正确解法是**在 C++ 侧新增只读投影并重建 DLL**，把已算好的结构以"每根 K 线一个标量"的形式暴露出来。这不违反既有不变量——不在 TS 移植算法、不并发进 DLL、仍是宿主内单一串行所有者。

### 1.2 依赖收敛：3 个原生能力解锁 7 个方法

### 1.3 另两项不是 DLL 问题

- **CH13 月线底部**：`src/server/monthly-bars.ts` 的 `monthlyBars()` **已存在**，B4 当时被禁止新增通道才登记为缺口。实际只需把它接入缠论研究路径，加上 N1 的趋势成员证明。**周线不得代替月线**这条继续有效。
- **CH11 均线轮动板块强弱**：唯一真正的数据阻塞。需要**时点板块成分**与各板块同窗均线/强弱排序。`industry-blocks.ts` / `rps-block-source.ts` 提供的是**当前**成分名单（带 hash 与 mtime），不是历史成分。现有双基准 RS 不是板块轮动，不得冒充。

## 3. 硬约束

- **不在 TS 移植缠论算法**；新增能力一律走原生投影。不并发进 DLL，宿主内单一串行所有者、整任务原子排队不变。
- **重建必须先证明无回归**：`make sse-result-check` 与现有 golden 比对通过，且新 DLL 对既有输出逐根一致，才允许替换 `vendor/czsc/CZSC64.dll`。替换时同步更新 README 的 hash、commit 与构建方式。
- **GPL v3**：源码与 DLL 为 Martin Tang 的 GPL v3 作品，修改版仍受 GPL。本计划只做本机研究用途；**对外分发与捆绑许可由用户决定**，不得因已有 exe 就认为许可已确认（沿用架构不变量）。
- 不把 DLL 的 `kind=1/2/3` 自动宣称原文全覆盖；仍不能由输出证明的方法继续标结构缺口，不自造近似。
- 月线/板块输入遵守时点纪律：报告期不是披露日、当前成分不回溯、`availableAt` 缺失即 missing。
- 提交与推送由管理者统一做；分支合并前跑一次完整 L3。

## 5. C1 只读投影规格与构建交接（2026-09-17）

### 5.1 核查纠正与实际交付边界

`include/CzscTypes.h::TrendStructure` 只有 `nType/nStart/nEnd/nFirstCenter/nLastCenter`。
`BuildTrendStructures` 只按相邻中枢关系分组，未保存完成状态、完成确认时点、理论级别或连接边界。
因此不能从“已有 Structures 数组”推出 N1/N3 所需证据全部存在。`nEnd` 是末成员中枢的终点；后面有另一组，也不是原文已完成走势的证明。

- N1：已交付完整成员的闭区间及数量、逐根所属编号、类型、起止；完成与理论级别明确未知。构件层级独立暴露，不冒充理论级别。
- N2：已交付全量候选行的身份和下表字段（不是完整 C++ struct 内存序列化）；同根任意多行在可表示范围内均可枚举，包含一/二/三类，不经胜出 signals 过滤。
- N3：只新增证据不可用输出 92；**没有实现已完成序列、连接边界及级别**。93–99 暂不分配，不以全零假装已知空序列。
- 在“只读投影、不改算法”约束下不补造完成判据。CH06/CH08 及传递依赖保持缺口；需要管理者明确原生完成/级别/连接的证据及是否授权算法扩展。本轮新方法 0，C1 整批未完成。

### 5.2 ABI、槽位与整数精度

仍使用 Func30，`mode = config * 1000 + output * 10`，0–58 case 内容与原有单个 mode float 调用保持不变。
**调用新输出 59–91 时，第三输入必须分配 nCount 个 float32：`pTime[0]=mode`，`pTime[1]=slot`（nCount>1），其余为 0。**
`slot` 是每根 K 线内按原始数组顺序排列的零起始槽位；nCount=1 固定槽位 0。旧版 TS worker 的单元素数组不能直接用于这些新输出，C2 必须先改调用方缓冲区契约。
92 只需 mode，不读取槽位。ABI 不能探知裸指针缓冲区长度，调用方必须遵守；普通常量 mode 的 TDX 公式不能直接当作槽位输入使用。

先读 59/70 的逐根行数，再枚举 `slot=0..max(count)-1`；某根不足该槽位返回 0。
59 忽略槽位对所有覆盖该 K 线的走势计数，70 对该 K 线的候选计数；两者仍要求槽位参数合法。
每个字段一个输出号，没有把多个标志打包进浮点数。先读 60/71 判断该槽位有无行，再解释允许为 0 的类型、质量和布尔列。

所有索引输出是 **原生零基索引 + 1**，0 为无行或原生 -1 引用；可精确表示域为 1..16777216，计数为 0..16777216。
先在整数域检查，再转 float32。索引 16777215 映射为 16777216；索引 16777216 及更大值返回 -1，不允许舍入碰撞。
槽位只接受精确整数 0..16777215；小数、NaN、无穷和越界输入返回整列 -1。
结构/候选行数量或 nCount 超过 16777216、无法定位的成员区间/候选 K 线返回整列 -1；单字段的非法引用返回 -1。
-1 是错误/未知状态，不是合法 ID；类型输出 63 的 -1 本身也代表下跌，须结合行数/ID列判断错误。原生缺失引用与非法引用不混淆。

N1 输出依赖请求 config。N2 一律使用 output50 同样的 `DefaultConfig + segment + feature`（1100）。
不能把 N2 的走势/中枢 ID 与 config=0 的 N1 混连；应读 config=1100 的 N1。
output50 的值是 71 的外键，但 50 位于低级别信号 K 线、71 位于高级别候选 K 线，须按 ID 建表关联，不能假定两者在同一根。

### 6.3 完成证据：可派生观测事件，不足以补齐原文完成序列

**结论：三者不能作为一套原文完成证据仅由现有投影确定性导出。** §5.1“不保存字段”不是充分论证；本轮按实际算法重新核实，分别结论如下。

1. **后继出现可以派生。** 同一前缀、同一config中，按成员顺序存在下一Structures行，可以确定“后一中枢分组已出现”。逐前缀首见时刻也可冻结为工程观察事件。因此无需为了这个事件改C++。但若把它定义为“前走势完成”，那是 `successor-group-observed-v1` 的工程定义；并不能同时证明下一走势已按理论确立、前走势真实终点在哪里，或取得完成早于后继确立的时点。此定义使完成与后继确立在同一观察时刻，CH10需要的中阴区间会退化为零，不能借此销账。
2. **成员边界可得，唯一连接点不可得。** `CzscCenter.cpp::MakeTrendStructure`直接令nStart=首中枢nStart、nEnd=末中枢nEnd。`BuildTrendStructures`按关系分组后令i=nLast+1，两个组不共享成员。这些是中枢包络边界，不是覆盖所有连接段的走势端点。例：成员区间结束在K20，下一组开始K30，只能得到待解析区间[20,30]，不能决定转折连接在20、25还是30；重叠区间也同样不能唯一选点。前后成员闭区间、类型、N2候选都没有指定哪个端点拥有连接权。不能取末中枢终点或下一首中枢起点冒充理论连接点。
3. **理论级别不可得。** `nCenterUnit=1/2`仅笔/线段构件，既无递归子走势树、基础级别锚定，也无升阶证明。即使后继分组与完整成员都存在，仍不能唯一确定理论级别。输出69=null/unknown保持；不把1100、线段或日线标签当作理论级别。

N2也不能填平这些缺口：只有满足一二三买卖条件的候选，不是每一走势都必有一个候选；quality是候选质量，Divergence.Current和前接段属于候选，不标识走势连接边界。因此本轮完成CH07/CH12，CH06/CH08/CH09/CH10/CH18仍保留缺口，不自行扩展算法。可派生的后继观察事实不伪称理论完成证据。

## 7. 缠论规则方案（2026-09-17，用户已授权扩展，规则待用户裁定）

### 7.1 原文依据（逐字引述，标课文编号）

- **走势终完美（第17课）**：「任何级别的任何走势类型终要完成」；双重含义之二「一旦某种类型的走势完成以后，就会转化为其他类型的走势」。
- **基本原理二（第17课）**：「任何级别任何**完成的**走势类型，必然包含一个以上的缠中说禅走势中枢」。
- **中枢递归定义（第17课）**：「某级别走势类型中，被至少三个连续次级别走势类型所重叠的部分」。
- **递归末端处理（第17课）**：「对最后不能分解的级别，其走势中枢……定义为**至少三个该级别单位K线重叠部分**」。
- **递归体系（第17课）**：「如果我们首先确立了显微镜的倍数（例如1分钟图为最基本图），那么就可以开始定义分型、笔、线段……然后按照递归的方法，可以逐步定义5分钟、30分钟、日、周、月……」。
- **级别与图无必然关系（第18课）**：「什么级别的图和什么级别的中枢没有任何必然关系」。
- **走势多义性（第33课）**：「走势的多义性，是客观存在的。但多义性不是含糊性，分多解的一个前提是，这些分解都符合理论，而且分解之间并不相互矛盾」，核心是结合律。
- **中阴阶段定义（第89课）**：一个走势类型**完成后**、下一个走势类型**确立前**的过渡阶段。
- **中阴结束辅助判断（第90课）**：「利用布林带（BOLL）的收口和放大来判断中阴阶段的结束」。

### 7.2 两条对 §6.3 结论的修正

1. **「唯一连接点不可得」不是阻塞项。** 第33课明确走势多义性客观存在且合法，只要分解符合理论、彼此不矛盾（结合律）。因此不应追求唯一连接点，而应**登记一个具名分解规则**并声明其为多解之一。§6.3 把多解当作不可实现的理由，这一点按原文纠正。
2. **不能把「后继分组出现」定义为「前走势完成」。** 第89课把中阴定义为「完成后、确立前」，即完成**必然早于**后继确立。执行者指出该定义会使中阴退化为零，与原文矛盾——这一点执行者是对的，`successor-group-observed-v1` 不能作为完成证据的主版本。
