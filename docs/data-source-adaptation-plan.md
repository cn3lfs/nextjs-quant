# 数据源适配与验收计划

2026-09-15。S1–S6 的本轮适配和可执行验收已实施；外部未知字段、真实特殊样本及多时段观察单列，不能视为全能力通过。完成范围、实测数和剩余项见[执行记录](2026-09-15/02-data-source-execution.md)。入口与历史要求见 [next-plan](next-plan.md)、[数据源验收要求](data-source-requirements.md)。

## 目标与现状

四个图表源均有调用路径，目标是补齐适配契约、字段正确性和真实应用验收，而非重新实现已有能力。

| 来源 | 已有基础 | 本计划的缺口 |
| --- | --- | --- |
| tstdx | 独立包、adapter、图表接入；提交 eb53365，握手恢复 | ETF 精度、指数成交量、快照时间与完整矩阵 |
| 东方财富 HTTP | onlinePeriodHistory 图表调用 | 独立 adapter、能力映射、请求边界与完整矩阵 |
| 本地 vipdoc | 文件解析、名称、快照、缓存及周期读取 | 统一结果契约、真实文件覆盖及异常验收 |
| westock-data | CLI adapter、批量补查和品种矩阵 | 单位核验、板块页面接入与特殊样本 |
| mx-ds-mcp | 独立自然语言查询与 11 类路由 | 其余工具实网和页面验收，不纳入图表 |

tdx-finance MCP 继续停用。真实客户端、CLI/HTTP 原始调用、包、adapter、应用 API、页面分层验收，不能以某一层成功替代其余层。

## 阶段与完成条件

### S1：tstdx 字段正确性收尾

- 对 ETF 分时、成交及报价价格缩放逐项取证，核对品种精度字段；覆盖沪深 ETF、普通股票与指数，避免统一除数造成回归。
- 核验股票、ETF、指数在 K 线、分时、成交及五档中的量额含义；只有证据充分时转换单位，否则保留源单位及不可比较标记。
- 对照官方客户端和原始报文核验快照时间，覆盖两种编码候选、非法值、午休与收盘；无日期字段时继续保留日期未知。
- 修复落在独立包内，adapter 只做契约转换。增加固定公开行情 fixture、非法/截断输入与边界测试；不保存客户端身份信息。
- 复跑各品种日/周/5 分钟及受影响接口，旧握手作为负对照保留。节点验证分别记录握手、有效行情、时效、耗时，不能只按连接速度判断可用性。

完成条件：三个已知问题逐项有结论；可修复项有真实对照和回归，无法确认项显式标记且不冒充标准字段。需要客户端辅助时提前说明品种、周期、操作与采集目的。

### S2：东方财富 HTTP adapter

- 抽取现有 HTTP 请求和解析，复用已有能力；梳理所有调用方，避免新增 adapter 后保留两套不同规则。
- 明确股票、北交所、指数、ETF、板块的代码映射。板块先使用该源目录确认身份，不直接把腾讯 pt 或通达信板块代码换前缀。
- 对齐逐项状态、日期/数量/周期/复权、取消、超时、空响应、限流、响应上限及历史截断说明；请求参数与来源版本可追踪。
- 检验 lmt 实际行为及日期截断，确保调用者请求数量与最终返回数量一致；不以请求成功推断历史完整。
- 先独立调用公共接口，再测 adapter 和应用图表；不使用 mx-ds-mcp 返回文本填补图表。

完成条件：最低品种矩阵有逐项结果；支持项通过原始接口及应用验证，不支持项明确返回；手动选择失败不静默换源。

### S3：本地 vipdoc 契约与验收

- 复用现有读取器、快照和缓存，不重复编写解析器。仅在调用边界确有差异时增加薄 adapter。
- 核对沪深北、指数、ETF、板块文件的实际存在性、名称和格式；缺文件与不支持分别记录。
- 验证日/周/月与各分钟周期的来源、聚合边界、末根日期、形成中状态、量额单位及复权语义。
- 覆盖损坏/截断文件、空文件、重复或非法时间、源文件更新后的缓存失效、读取期间文件变化与过期数据。
- 使用真实文件的隔离副本和固定 fixture；通达信目录只读，不触发下载。保持 RPS、研究快照及数据时点约束。

完成条件：已有研究读取行为无非预期改变；缺失/过期数据不会被视为最新，支持矩阵和来源指纹可复核。

### S4：westock-data 剩余适配

- 单独运行本地 CLI，对照 adapter，核验股票、指数、板块和 ETF 的量额单位、复权及日期范围；保留原始参数和差异。
- 梳理通用页面 symbolSchema、API、缓存/快照与图表对板块身份的约束，完成受影响链路后再开放 pt 图表入口。
- 保留北交所、指数、板块分钟的已知限制；只有新的原始 CLI 证据支持时更新能力声明。
- 增补停牌、新股、除权、退市/代码变更、批量遗漏、最大数量、取消与结构化错误样本；不要求供应商不支持的能力通过。

完成条件：单位结论可追踪，板块图表可达或有明确阻断原因；原始 CLI 与程序责任可区分，现有混合查询补查不回归。

### S5：mx-ds-mcp 独立查询验收

- 依据本地 skill 和实际工具清单，为 11 类工具逐项指定最小有效样本，补测先前未覆盖类别。
- 核对身份、时间、单位、提示及原表展示；覆盖无数据、错误、取消和授权失效，不把取整数值还原为精确行情。
- 验证查询入口、工具选择、结果和错误显示。继续独立于图表、RPS、历史拼接和策略计算。

完成条件：11 类逐项记录通过、不支持、失败或未测及原因；凭证不进入日志/报告。未经明确交接不修改用户维护的 src/server/mcp.ts 及其 UI 文案。

### S6：四源应用验收与优先级

- 对四源逐一验证选源、默认设置、跨证券/周期保持、来源和时间提示、错误重试、快照/缓存；API 验证和真实页面点击分别记录。
- 对照同一证券、日期、周期、复权及量额单位，分别解释价格/量额差异；单位未确认的数据不拼接。
- 在线源按有效数据覆盖、时效、错误率及耗时比较，包含多时段采样；不以一次测速或 43 个节点一次成功推断长期稳定。
- 按用户最新指定：本地 → tstdx → 东方财富 HTTP → westock-data。代码、UI 文案、测试和文档同步，手动选择始终不隐式回退；顺序不代表长期可靠性排名。
- 汇总能力矩阵与未解决项，修正文档中已过期的“不可用/未提交”现状描述，保留带日期的历史证据。

完成条件：每个支持项有分层证据，自动回退可见且不混淆实际来源；真实 UI 未能操作时标记未验收，不以构建代替。

## 统一验收与执行规则

- 顺序为 S1 → S2 → S3 → S4 → S5 → S6。每阶段先核实已有实现，完成必要检查后报告，再进入下一阶段；有外部阻碍时先记录并继续不依赖它的工作。
- 最低沿用八类品种日/周/5 分钟矩阵，补深市 ETF、深市指数和各源原生板块样本。增加周期边界、上市/停牌/除权/退市、分页、批量、取消、超时、缓存及交易时点样本。
- 对外部数据分别记录：通过、明确不支持、请求失败、数据错误、未测；缺失不可填零，自动回退结果不能计作被选源通过。
- 每个结果记录样本、请求参数、采集时间、实际数据时间、来源/版本、复权、单位、差异及复现方式；原始临时产物留隔离目录，持久测试放 tests/ 或包既有测试目录。
- 改动运行相关测试和 typecheck；阶段完成运行 pnpm test；有意义的应用交付运行 pnpm build，涉及 runtime 重建 worker。验证先设置隔离 QUANT_DATA_DIR。纯文档只检查内容、链接与 diff。
- 每阶段保持可独立提交的差异，报告实际测试数和剩余边界。提交需用户授权，不自动推送、发布或打包；不修改生产库及通达信源文件。

当前执行状态与逐项证据见[执行记录](2026-09-15/02-data-source-execution.md)。此前已提交的 adapter 与握手修复作为基线，不重复计作本计划的新交付。未确认的时间编码、指数单位、真实特殊证券样本和多时段可用性继续保留，不阻止已有保护下的其他源使用。
