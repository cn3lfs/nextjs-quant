# 回测研究假设（2026-11-22 冻结）

> 本文件冻结当前策略诊断的研究口径。它约束“怎么跑、怎么报”，不产生策略结论，也不改变生产默认。

上一阶段的 36 格五标的矩阵与 180 格执行/容量敏感性见[五标的诊断](2026-11-22-five-symbol-diagnostic.md)和[执行与容量敏感性](2026-11-23-execution-sensitivity.md)。本文件把那些实验里被验证有用的档位固化为后续批次（量价、威科夫、数据硬化）的默认对照方式。

## 1. 执行假设

| 项目                     | 取值                                    | 说明                                          |
| ------------------------ | --------------------------------------- | --------------------------------------------- |
| 信号时点                 | 完成 bar 收盘确认                       | 不使用未完成 bar，不做盘中预览                |
| 成交时点                 | 次根 bar 开盘                           | 信号日与成交日分离，避免同 bar 前视           |
| 滑点基线 `strict`        | 5bp；越出当日可观察 high/low 则拒绝     | 研究默认；拒绝率高，但最不容易高估可成交性    |
| 强制敏感性 `clamp`       | 5bp；越界按当日 high/low 成交           | 每份策略报告至少并列 strict 与 clamp          |
| 零滑点情景 `no-slippage` | 按 open 成交                            | 只作情景，不当作可成交上界                    |
| 容量基线                 | 关闭                                    | 引擎默认；组合研究沿用                        |
| 单标的全历史容量         | `maxParticipation 0.5%` + `clip`        | 成交额参与率上限，作用于 `bar.amount > 0`     |
| 组合（2018+）容量        | 关闭                                    | 当前 5 标的组合规模下不绑定，开启只会增加噪音 |
| 涨跌停/一字/停牌/缺 bar  | 始终拒绝                                | 不因滑点 profile 或容量策略放宽               |
| 交收                     | A 股 T+1；100 股整手（科创板 200 股起） | 卖出以可卖持仓为上限                          |

`strict`、`clamp`、`no-slippage` 都保留同一套交易状态拒绝；差异只在“滑点后价格是否可成交”。容量 `clip` 只裁剪数量，不改变成交价口径：卖出剩余和带目标权重订单的差额按 pending 逐日重试，普通买入被裁剪后直接按已成交量完成、不重试。后者是当前引擎语义，报告必须用 `capacityClipped` 成交数披露，不能当作“订单已全部成交”。

## 2. 费用

`base` 情景（`researchExecutionCosts`）：

| 项目   | 数值                     |
| ------ | ------------------------ |
| 佣金   | 3bp，单笔最低 5 元       |
| 印花税 | 卖方 5bp，按历史调整日程 |
| 过户费 | 0.01‰（0.1bp）           |
| 滑点   | 5bp                      |

`double-cost` 把佣金、最低佣金、印花税、过户费和滑点同时乘 2，作为成本敏感性档；`fixed` 只是与旧结果对比的固定情景，不作为新研究的默认。

## 3. 数据口径

- 行情来自 `E:/new_tdx64`，只读；日线截止 2026-11-20。
- 信号价使用逐 bar 因果复权（GBBQ），首根保留原价作为固定锚；锚点被删除时拒绝该单元。
- GBBQ 未识别记录在诊断模式按 `record-only` 记录并披露，不静默补造；`formingDates` 始终拒绝。
- 交易日历以 `sh000001` 为准；小集合（阈值 `max(20, 0.5%)`）的日历外 bar 删除并披露，大集合阻断。
- 缺失成交额时引擎不施加参与率上限；缺失不能补造。
- 复权、公司行动与成交价必须来自同一因果序列；公司行动单独对账。

## 4. 样本与窗口

- 首批样本：`sh600519, sz000001, sh601318, sz000333, sz300750`，见[五标的选样](2026-11-22-five-symbol-selection.md)。
- 单标的窗口：各自首根日线 + 策略预热；组合窗口：最晚上市成员首根日线（当前为 2018-06-11）。
- 当前样本只覆盖存续标的，存在幸存者偏差；结论不外推到全市场。
- 预热 bar 不参与评分，但保留在序列中供规则计算。

## 5. 报告口径

1. 每份策略诊断并列 `fills`、成交额、费用、拒绝尝试数、`capacityClipped` 成交数；不只报收益。
2. 不做策略间收益排名，不把 `strict` 的收益单独当作可执行结论；执行假设敏感的策略标为“执行敏感”。
3. `fills` 不能直接跨档比较：容量裁剪会把大单拆成多日分笔。成交额、费用和仓位路径才是有效口径。
4. 流程诊断与策略业绩分开验收；亏损或样本不足不触发工程返工。

## 6. 变更规则

- 修改本文件任一默认档，必须在新记录中说明改了什么、旧结果为何不可直接比较。
- 不引入代码 hash、构建 hash 或审批哈希作为研究回测门槛；paper/sim 成交对账身份保持不变。
- 生产默认（引擎 `slippagePolicy` 默认 `reject`、容量默认关闭）不由研究口径改变。
