# E5 真实交易复盘：调研与设计

2026-09-11。用户授权新增「复盘」能力：行情复用、交割单导入（同花顺 / 东方财富）、
买卖点分析、盈亏比、最大回撤、夏普及扩充指标。本文是实施前的设计与分批，
范围口径以 [roadmap](roadmap.md) 为准，正确性约束以 [invariants](invariants.md) 为准。

本阶段的事实基础是**用户真实成交**，与 `signal_ledger`（市场观察）、
`strategy-research`（合成/历史模拟）是三种不同事实，不得互相冒充。

## 1. 现状核实（已读代码，非推测）

| 已有能力                                  | 位置                                      | 对本阶段的作用                               |
| ----------------------------------------- | ----------------------------------------- | -------------------------------------------- |

指标数学基本不用重写。

## 2. 已定决策（用户 2026-09-11 确认）

1. **导入数据入新表 `trade_fills`**，不复用 `trade_ledger`。
   理由：`trade_ledger` 的校验（当日涨跌停带、方法出处、T+1 可卖、日历内）
   是为**前瞻性手工记录**设计的不变量，历史交割单无法提供这些依据；
   为导入开豁免通道等于削弱已验证的不变量。两套并存，口径在 UI 显式标注。
2. **资金曲线 = 期初资金 + 资金流水重建的现金 + 当日持仓收盘市值**。
   资金流水从交割单的银证转账/利息/红利入账行提取。缺口不补零：
   覆盖不全的区间净值为空，该区间不出夏普/回撤。
3. **两家券商都提供真实导出文件**，解析器按真实列头编写，脱敏样本入
   `tests/fixtures/`，配非法输入测试（本仓对新解析器的硬性要求）。

## 3. 数据模型（迁移 #10，已落地）

以 `src/server/db/migrations.ts` 第 10 条为准。相对本节初稿的两处修订：
`trade_fills.symbol` **可空**（非沪深北品种无归属）并另设 `code` 列；
`import_batches` 增 `file_name` 与 `UNIQUE(account,file_hash)`。

```sql
CREATE TABLE import_batches (
  id TEXT PRIMARY KEY, account TEXT NOT NULL, source TEXT NOT NULL,
  file_hash TEXT NOT NULL, file_name TEXT NOT NULL,
  imported_at INTEGER NOT NULL, payload TEXT NOT NULL);
CREATE UNIQUE INDEX import_batches_file ON import_batches(account,file_hash);

CREATE TABLE trade_fills (
  id TEXT PRIMARY KEY,          -- 指纹 hash，保证幂等
  account TEXT NOT NULL,        -- 账户别名，不存真实账号
  symbol TEXT,                  -- 可空：可转债/ETF/逆回购无 sh|sz|bj 归属
  code TEXT NOT NULL,
  trade_date TEXT NOT NULL,
  batch_id TEXT NOT NULL REFERENCES import_batches(id),
  payload TEXT NOT NULL);

CREATE TABLE cash_flows (
  id TEXT PRIMARY KEY, account TEXT NOT NULL, flow_date TEXT NOT NULL,
  batch_id TEXT NOT NULL REFERENCES import_batches(id), payload TEXT NOT NULL);
```

- **幂等指纹**：优先 `sha256(account|券商成交编号)`；无成交编号时用
  `sha256(account|日期|代码|方向|价|量|合同编号|组内出现次序)`。
  **不得含行号**——同一笔成交在不同区间的导出里行号不同，含行号会让重叠导入
  重复入库、持仓翻倍（该缺陷已于 2026-09-11 修复，见 decisions）。
  同指纹内容不一致 → **整批回滚**并报错，沿用 `trade_ledger`
  的「编号已用于不同内容」语义，不静默覆盖、也不跳过冲突行继续写。
- **同 `account`+`fileHash` 重复导入**：不新建批次，返回既有 `batchId`
  并置 `alreadyImported`，保证撤销语义可预期。
- `import_batches.payload` 保留原始行、列映射、解析统计与跳过原因，
  支持**按批次整体撤销**（用户显式清理，不静默删除）。
- 复盘结果**不落表**，每次按快照现算并可导出 JSON；避免再造一套需要
  失效管理的派生表。

## 4. 导入层（R1 已交付，2026-09-11）

### 4.1 格式调研结论

各家终端只是**壳**，列名真正来自背后的柜台（恒生 / 顶点 / 金证）。
PTrade 的 `get_deliver` 返回柜台原生字段，是这批中文列名的语义来源：

| 柜台字段                                                  | 中文导出列                     | 说明                                                           |
| --------------------------------------------------------- | ------------------------------ | -------------------------------------------------------------- |
| `init_date` / `date_back`                                 | 成交日期 / 交收日期            | 两者可能同时存在                                               |
| `stock_code` / `stock_name`                               | 证券代码 / 证券名称            | 前导零易被 Excel 吃掉，导出常写 `="000001"`                    |
| `entrust_bs`                                              | 买卖标志                       | `1` 买 `2` 卖；无摘要列时才作判据                              |
| `business_price` / `business_amount` / `business_balance` | 成交价格 / 成交数量 / 成交金额 |                                                                |
| `occur_balance` / `clear_balance`                         | 发生金额                       | **带符号**，买入为负、卖出为正，已扣费                         |
| `post_amount` / `post_balance`                            | 股份余额 / 资金余额            | 重建每日现金的关键列                                           |
| `fare0` / `fare1` / `exchange_fare*`                      | 佣金 / 印花税 / 过户费·规费    | 「手续费」在部分柜台是费用合计，口径必须核对                   |
| `business_flag`                                           | 业务标志                       | 数字码（如 2041 银行转存），各柜台不一致，**只留证据不作判据** |

因此实现按**列别名字典 + 摘要词表**驱动，而不是按券商写三份解析器：
同一券商换柜台就会换列名，按券商分支必然失效。

三种文件形态均已支持：CSV / TSV（含 `.txt`）、UTF-16 的伪 `.xls`、
HTML `<table>` 的伪 `.xls`。编码按 BOM → 严格 UTF-8 → GB18030 顺序探测
（严格 UTF-8 必须先试：GB18030 解码器几乎接受任意字节，先试它会把正常
UTF-8 静默变成乱码）。真 `.xlsx` 需新增依赖，到时单独申请。

### 4.2 已实现文件

- `src/lib/delivery-table.ts` — 解码、分隔符探测、HTML 表格提取、
  表头行定位（跳过券商标题/账号/日期区间等前导行）、重复表头与汇总行剔除。
- `src/lib/delivery-import.ts` — 列映射、业务类型判定、字段规范化、
  一致性核对、指纹来源串、账号脱敏。纯函数，不做 hash 与 IO。
- `tests/delivery-import.test.ts` — 35 个用例；样本见
  `tests/fixtures/delivery/`（**当前为合成样本**，真实导出到手后替换）。

### 4.3 已固化的行为

- **未知摘要不猜**：`场外协议过户` 这类无法归类的行进入 `unresolved`
  并保留原始行，不按买卖处理，也不丢弃。
- **非成交行分流**：红利入账、银证转存/转取、利息归本、新股申购/配号
  进 `cashFlows`；方向明确的类型强制定号，新股类保留柜台原符号。
- **非股票品种**（可转债 11x/12x、ETF 15x/51x、逆回购 131/204）按代码前缀
  判定市场与品种：**计入资金曲线，不进个股买卖点分析**，不扩大 symbol 语义。
  沪深共用的 `1`/`2` 开头由完整前缀区分，无法归类的返回 `market: null`。
- **一致性核对**：成交金额 vs 价×量、费用合计 vs 分项之和、
  发生金额 vs 成交金额±费用及其符号，容差 `max(0.01元, 万分之一)`。
  不符的**标注 anomalies 但不丢弃**——真实交割单确实存在这类差异，
  丢弃等于篡改账本。
- **账号脱敏**：账号列只用于识别并替换为 `***`，真实账号不入库。
- **缺列即报错**：缺日期/数量/价格，或既无摘要又无买卖方向，直接拒绝导入
  并列出已识别列，不带着残缺映射往下走。

## 5. 复盘引擎 `src/lib/trade-review.ts`（纯函数，可手算验证）

### 5.1 回合配对

按时间重放 fills，输出 round-trip：开仓日、平仓日、持有交易日数、买均价、
卖均价、数量、总费用、净收益、收益率、是否跨除权。
默认**移动加权**（与 `positionFor` 一致），**FIFO 作为可选列**同时给出，
两者差异在页面显示。跨除权回合的收益率标注「未复权，不代表经济收益」。
未平仓持仓单列，绝不按零收益计入胜率分母。

### 5.2 买卖点分析（核心增量）

对每笔成交，用未复权日线计算：

- **日内位置**：成交价在当日 (low, high) 中的百分位 → 买在高位还是低位。
- **区间位置**：成交价相对前 20/60/250 日高低点的位置。
- **MFE / MAE**：买入后至平仓（或至今）的最大有利/最大不利偏移。
  这是判断「止损太浅/止盈太早」最直接的量。
- **卖后走势**：卖出后 T+1/5/10/20 的价格变化 → 量化「卖飞」与「躲过」。
- **入场时机**：买入日该股的 RPS 分档（复用 `rps_values` 历史）、
  是否处在双突破/缠论信号日（复用 `signal_ledger`，有则关联无则留空）。
- **纪律核对**：若该标的在 `trade_ledger` 有计划止损，比对实际卖出价与计划止损。

### 5.3 盈亏与风险统计

- 复用 `researchTradeStatistics`：笔数、胜/负/平、胜率、平均盈亏、
  **盈亏比**、期望、分布分位数。无亏损样本时盈亏比不可估，不填无穷（已有语义）。
- 新增：**profit factor**（总盈利/总亏损绝对值）、连续盈亏串、单笔最大盈亏、
  费用占毛利比（A 股高频摩擦成本很容易吃掉正期望，值得单列）。
- 复用 `researchNavStatistics`：**最大回撤**、总收益、**夏普**（252 年化、
  显式无风险利率）。
- 新增净值派生：回撤区间明细（峰值日/谷底日/恢复日/水下天数）、
  **Sortino**、**Calmar**、月度收益表、
  **基准对比**（本地 sh000300 / sh000001 日线）→ 超额收益与相对回撤。
- **硬约束**：任何一天净值不可得 → 该段不计夏普/回撤，页面说明原因。
  沿用已有口径「没有每日净值就不计算夏普」。

### 5.4 归因分组

按标的、行业、概念、持有期分桶、买入日 RPS 分档、是否关联信号、
星期几、单笔仓位占比分档。每组给 5.3 的核心统计。
分组是**描述性**的，不声称因果，不等同因子分析（沿用 N1 的既有措辞）。

## 6. 服务与页面

- `src/server/trade-review-*.ts`：导入服务、快照组装、导出、按批次清理。
- tRPC 路由挂 `api/root.ts`，新入口 `/trade-review`。
- 页面分区：**导入向导**（选文件 → 列映射预览 → 冲突/异常行报告 → 确认写入）、
  成交明细、回合表、买卖点分析、资金曲线与回撤、归因、导出、批次管理。
- 导入向导必须在写库前完整展示：将写入 N 行、跳过 M 行及原因、
  重复 K 行（幂等命中）、异常 J 行。不做「先写了再说」。

## 8. 风险与明确不做

- **交割单不是完整账本**：券商导出通常只保留近 1–3 年，且分红入账、
  融资融券、新股中签的表现形式各异。覆盖不全直接体现为净值缺口，
  不用估算填补。首版**不支持两融账户**。
- **未复权价格**：买卖点分析与市值口径均为未复权，跨公司行动的比较
  一律标注不可比，不悄悄换算。
- **不自动下单、不外发**。导入文件含真实交易信息，只落本地库，
  账号一律存别名，原始行中的账号字段在写库前脱敏。
- **本阶段不做**：多账户合并归因、税务报表、组合优化、
  把复盘结论自动回灌成策略参数。软件算得对不等于交易做得对。

## 9. 开始前需要用户提供

1. 同花顺与东方财富各一份**真实导出文件**（可脱敏账号，保留列头与全部行类型，
   最好覆盖买卖、分红入账、银证转账、费用行）。放到仓库外任一路径告知即可，
   脱敏后才入 `tests/fixtures/`。
2. **期初日期与期初资金**（或最早一笔银证转账之前的账户总资产），
   否则净值曲线只能从首次入金起算。
3. 无风险利率取值（默认 2%，可改）。
