# 执行者常备说明（每轮派单只写增量，这里是不变部分）

管理分工：管理者定批次、验收门槛与进度核对；执行者实现与验证。**每轮派单只给"本轮目标 + 上轮结论 + 特殊约束"，其余一律以本文件为准。**

本文件**与具体执行工具无关**。无论执行者是哪个 CLI，纪律、验证分层与不变量均以本文件为准；调用参数、沙箱范围、会话恢复等属工具细节，由管理者在派单时处理，不写进本文件。运行目录沿用历史名称 `.codex-runs/`（已在 gitignore 内），不因更换工具而改名。

必读：`AGENTS.md`、[优化方案](trading-skills-execution-optimization.md)、[原计划](trading-skills-strategy-plan.md) §1/§6/§7、[契约清单](trading-skills-contract-checks.md)。

## 1. 交付形态：共享引擎 + 具名方法表

**这是本项目最重要的一条效率规则。** 剩余方法绝大多数是同一计算的维度展开，不是各自独立的功能：

- 量价九宫格 = 涨跌 × 量能 × 位置的表格行；
- 技术指标子方法 = 同一指标引擎的参数与方向组合；
- RK 波动率族 = 一个跟踪止损引擎 + 各家公式的参数集；
- 开盘剧本 = 剧本 × 高开低开档位的表格行；
- 威科夫事件 = 一个事件状态机 + 各类 VSA 判据。

因此：**一个家族实现一个共享引擎，具名方法以声明式表格行注册**，不要为每个 ID 写独立模块与独立测试文件。历史证据：用共享 `indicators.ts` + 规则表的那一批一次交付 14 个预设；逐个手写的批次只有 8–11 个。

这不等于暴力排列组合：只登记来源中真实具名的方法，不自造成千上万的组合。

## 2. 测试：不要逐方法重测契约类

注册驱动的契约套件已对**每个**已注册预设自动跑 12 类断言：完整历史前缀一致、追加未来不改过去、缺日、零量、非法 OHLC、下一可成交时点、T+1 分批、受阻重试且已确认退出不撤销、公司行动证明、卖出数量/步长/尾仓、资金守恒、稳定排序。

**禁止**在单方法测试里重复这些。单方法测试只写：

1. 该算法的正例与反例（含边界等号）；
2. 真实原文冲突分支的各具名版本；
3. 该方法特有的不可用路径（例如它依赖的输入缺失）。

新预设未注册进契约套件时套件会报缺失，这就是覆盖保证。

## 3. 记录：清单是唯一进度源，不写长篇散文

- `docs/trading-skills-method-map.json`：唯一进度源。每项的 `status`/`implementation`/`tests`/`boundary` 由 `scripts/audit-trading-methods.ts --write` 回填。
- `docs/decisions.md`：**只写真实的原文冲突与工程裁定**，一个冲突一条，不是一个方法一条。同族多个方法共用同一裁定就写一条并列出适用 ID。
- `docs/trading-skills-execution.md`：**每批一条、六行以内**，不是每轮一篇。段落写不下就说明信息该进 method-map 或 decisions.md。
- 计数一律取审计脚本输出，不手工推算。区分 `implemented` 与 `implemented-variant`，不要混为一谈。

## 4. 每轮必须产出 `.codex-runs/delivery.json`（运行目录，名称沿用历史）

**边做边写，每完成一个子任务就更新**——会话被中止过两次，其中一次已完成的工作因为没写记录而需要管理者逐项反查。格式：

```json
{
  "batch": "B3",
  "subtask": "volume-price-nine-grid",
  "newMethods": { "implemented": [], "variant": ["VP01", "VP02"] },
  "stillPlanned": 160,
  "counts": { "total": 695, "implemented": 22, "variant": 176, "planned": 497 },
  "gates": { "verifySpot": 0, "typecheck": 0, "familyTests": 0, "audit": 0 },
  "l3": {
    "ran": false,
    "verifyBatch": null,
    "playwright": null,
    "fullSuite": null
  },
  "conflicts": ["原文 §x 与 §y 的冲突及采用的具名版本"],
  "dataGaps": ["缺失字段与覆盖区间"],
  "costNotes": "本轮实际拖慢进度的具体原因",
  "nextStart": "下一个子任务的确切起点"
}
```

管理者按这个文件验收，不再逐轮重跑全量。所以 `gates` 与 `l3` 里的数字必须是命令的真实退出码与真实计数，不得凭印象填写；填错比不填严重。

## 5. 分层验证

| 层级 | 时机                 | 执行                                                                   | 不执行                  |
| ---- | -------------------- | ---------------------------------------------------------------------- | ----------------------- |
| L1   | 每次改动             | `pnpm verify:spot <相关测试文件>`                                      | 全量、build、Playwright |
| L2   | 每个子任务收口       | typecheck + 该家族全部测试 + `audit-trading-methods.ts --write`        | 全量、Playwright        |
| L3   | **每批一次**（批末） | `pnpm verify:batch` + Playwright 一次（只走本批新增交互）+ format/diff | —                       |

例外全量：改动触及 `research-execution.ts`、`research-portfolio.ts`、注册聚合器、`indicators.ts` 或新增数据库迁移时，同一会话内连续触及同一共享执行器的多个子任务，合并为会话收尾前的一次全量；不按子任务计次。任何一次全量失败，修正后**在会话结束前再跑一次**，使最后记录的全量为零失败。

`pnpm test` 不接受 `--outputFile=` 之类参数透传，用 `pnpm run test` 或重定向输出。收尾前跑一次 `pnpm normalize:eol`，否则残留 CRLF 会让 `git diff --check` 失败。

## 6. 会话纪律

- **只做方法实现。不做基建、不建新文档、不改验证门禁。** 认为需要基建就在 `decisions.md` 记一句，继续做方法。零产出的轮次全部源于基建挤占预算。
- 会话到上限时停在最后一个**完整**的方法，更新 `delivery.json` 的 `nextStart`，不留半成品。
- 宁可少做方法，不要把方法做成半成品。

## 6.5 结论的可核查要求（每条结论都要能被机械复核）

管理者会逐条核实结论，**核实不过的结论按错误处理**。因此：

- **引用代码位置必须连内容一起引**：写行号时同时粘贴该行的实际文本。只写行号、不贴内容的定位视为未证实。曾出现一份诊断把三处行号全部引错（引到了「加仓等待期」和「连亏冷静期」，而真正的判定在另一处）。
- **不得对零样本对象归因**：某项的事件数或样本数为 0 时，**不能把任何"执行阶段"的原因归给它**——没有样本就没有执行。归因前先报出该项的事件数。
- **禁止无逐项证据的百分比断言**：不得写「解释了 100% 的失败」之类；要么给出逐项清单，要么写明覆盖了其中哪几项、剩下的未证实。
- **数字自相矛盾时必须标注**：例如拒绝次数大于信号次数、覆盖率大于 1、子集大于全集，要么给出解释并证实，要么明确标为待查，不得原样陈述。
- **改动既有断言必须逐条给理由**：说明原断言保护的是什么属性、新语义为何不削弱它。只为让测试变绿而改断言是不可接受的。
- **区分"已证实"与"推测"**，两者分节写，推测不得进结论段。

## 7. 不变量（不得妥协）

- 任何可能打开数据库的验证先设隔离 `QUANT_DATA_DIR`；不碰默认生产库，不删库、不降 user_version。
- 通达信目录与外部 Blocks 只读；不执行全局 skills 目录的脚本；不更新来源锁定 hash；不改 `docs/trading-skills-source-snapshots/` 下的快照字节。
- 不自动下单、不外发消息、不连付费数据。**不提交、不推送、不打包**（提交由管理者统一做）。
- 原文模糊或矛盾处登记明确版本或两个具名版本，**不暗中改规则**。亏损、零信号、不好用的策略一律保留，效果留到回测判断。
- 缺数据按原计划 §1 的"待数据策略"交付：规则与可执行适配完成、固定输入可验证、明确列出缺失字段与补齐任务。**缺数据不是不实现的理由。**
- "已接入报告"不等于策略完成；纯价量对照不得冒充完整体系。
- 固定输入测试通过只是程序证据，不是盈利证据，不得表述为策略业绩。
- 财务、机构、催化、RS 各有可用时点；报告期不是披露日，今天修订的值不冒充过去值。
- 分钟级策略窗口为 **2000-01-04 至 2022-11-30**（已实测），不得延伸至 2023 年后，不得与延伸至今的日线区间静默混用。无 `.lc1`、无竞价历史，不得用第一根 5 分钟收盘价冒充 9:30 已知条件。
