# 发送队列的订阅版本校验

2026-09-09，接续 `monitor-run-verification.md` 的发送阶段缺口。

## 行为

新信号保存产生时的订阅创建时间和 revision。自动投递通过原信号追溯订阅版本，不能用发送时的新版本重新绑定旧通知。停止/删除、重新保存/启停、证券或渠道移出、关闭 AI 解读时，相应自动投递转为 `cancelled`，页面显示“已取消”及原因。缺少原订阅版本的旧自动队列项也取消，历史记录仍保留。

发送领取在事务内重新读取当前投递并核对订阅，领取前取消不增加发送尝试数。尚在退避中的旧版本也可立即取消；恢复中断发送时同样校验，避免恢复后重试旧订阅。

默认发送函数在异步读取凭证之后、发出 HTTP 之前再次核对订阅和渠道启用状态，并检查到期时间，覆盖读取凭证期间发生的停用/重启。

测试通知与用户显式“手动重发历史通知”是单独动作。手动重发生成新记录并标记 `manualRetry`，清除旧 remoteId/error，原取消记录不变；不会自动重发已取消记录。普通手动重发仍受渠道启用和新到期时间约束。

## 验证

- 修改前两个用例确实调用了模拟发送：停用订阅、重启订阅各 1 次；修改后均为 0 次，状态为已取消，尝试数为 0。
- 13 项队列专项：有效版本一次发送；停用/重启；证券/渠道移出；关闭解读；旧版本缺失；退避中取消；中断恢复；显式测试/手动动作；读取凭证期间版本或渠道改变时不调用 HTTP。
- 原有多渠道失败隔离、到期、重试次数和不确定恢复测试补齐有效订阅关联后仍通过，没有跳过授权以让测试通过。
- 实际 API caller 验证手动重发生成独立显式记录并保留旧取消记录；监控集成进一步验证新信号确实保存 monitorRun。
- 全量 147 文件 724 测试、类型检查、runtime/生产构建、桌面准备和冒烟通过。之后补充信号 monitorRun 断言并复验 34 项专项通过。桌面临时库 `quant-desktop-DhlNZd`，行情源不变。
- 隔离库 `quant-delivery-cancel-ui-rO5Wnc` 用模拟发送运行真实 drain：三种取消原因、模拟发送 0 次。打开页面前所有订阅均停用，队列没有待发送项。
- 页面 `output/playwright/delivery-cancel-results.txt` 显示三个已取消状态及原因，未点击手动重发。`output/delivery-cancel-http-verification.json` 确认 3 记录不变、尝试数 0、报告 0、启用订阅 0。
