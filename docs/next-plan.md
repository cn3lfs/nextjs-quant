2026-09-10。用户已授权扩充及修改原冻结模块，要求建立 goal 有序执行。本计划替代原 next-plan 的待办顺序；历史交付仍见 roadmap、invariants 和 decisions。

## 1. 每日工作流

盘前观点 → 沪深/A500/行业概念浏览 → RPS强势候选池 → 午尾盘预选 → 收盘确认 → 样本验证。

- 盘前读取现有财联社 Windows 任务完成产物，固定观点、证据与样本；过期/失败明确提示。
- 盘中浏览股票与板块、点击切图，用上一完成交易日的 RPS 缩小两策略候选。
- 用户原句暂按“临近午盘和尾盘”理解，用户已跳过时段确认；暂保留可配置的 11:20、14:40 默认建议，不作为 E1 的前置条件。预选不是日线确认。
- 收盘行情齐备后更新 RPS、确认信号、验证新闻样本。15:05 仅是最早检查时刻，不是行情已更新证明。
- 研究时选择区间、策略版本、买卖规则与成本，对比未过滤/RPS过滤组，输出统计及偏差。

### E3 策略样本研究

当前：E3首版开发交付（2026-09-11）。`/research` 已接入参数、后台执行、取消、原快照重跑、导出与清理；结果分开发期和保留验证期，展示事件观察、交易模拟、收益分布、持有期、成交受阻和每日净值。`tests/research-worker.test.ts` 贯通隔离日线采集、真实双突破计算、宿主缠论DLL队列、重复结果哈希与取消。页面完成创建、上传历史条件、结果自动刷新、导出385根合成日线、重跑同hash与单条清理验证，样本生成器为 `tests/e3-browser-fixture.ts`。数据准备及限制见 `/research/data-guide`。本阶段无新增迁移，未打包发布。下一阶段E4。

交付边界：当前模拟只允许有历史交易限制及无公司行动覆盖证据的股票；有除权事件的样本不参与成交统计，完整分红送转结算及外部历史数据自动适配尚未交付。当前成分回溯偏差、外部条件未经独立核验在页面明示；已验证的是软件链路与合成案例，不是可信历史策略业绩或盈利能力。

首批仅双突破和缠论；其他已有交易skill逐个提炼确定性规则、参数、版本与证据后接入，不让LLM临时决定不同买卖规则。

冻结实验的证券池、区间、复权、确认时间、入场/退出、仓位与资金分配、成本、基准。默认收盘信号下一可成交日尝试入场；处理T+1、停牌、涨跌停与未成交；日线不知同日止盈止损先后时采用有记录的保守规则或标记不确定。

先交付本地事件研究与规格导出，再做交易模拟。旧自检可评估改造，不把未验证输出当可信业绩；优先用聚宽历史验证并与本地逐项对齐。引入其他引擎/付费数据前明确覆盖、成本、维护和许可，不预装大型平台。

统计：

- 有效、排除、未平仓数量；已平仓净收益>0为胜，零收益单列。
- 平均盈利/平均亏损绝对值为平均盈亏比；无亏损时不可估，不填无穷。
- 净收益期望、分布、持有期、最大回撤。
- 夏普来自受同一资金约束的每日净值收益，明确无风险利率与年化因子；没有每日净值就不计算夏普。
- 小样本可显示明细与描述统计，注明不稳定；不硬等20天，也不以小样本宣称有效。

验收：手算费用/收益/胜率/回撤；未来bar不改历史确认；当前成分不能冒充历史成分；重复运行一致；调参与保留验证期分开；未成熟样本不计亏损。无历史成分则明确生存者偏差，与向前样本分组。

### E4 财联社观点与样本复盘

当前：E4首版开发交付（2026-09-11）。入口 `/cls-review`，支持Markdown原文预览、幂等版本导入、盘前固定样本、T+0/1/5/10价格观察、跨日命中率、独立事实核对、完整导出与显式清理。每日检查默认关闭，应用运行时可配置报告目录；不改Windows任务。清理后保留日期占位，不能删除后同日换股。`tests/cls-review-integration.test.ts` 覆盖隔离报告/名单/RPS/日线的选样至核对链路；`tests/e4-browser-fixture.ts` 提供页面样本。已验证页面导入、事实核对、导出与清理；阶段回归、最终构建与桌面资源准备已完成。明确推荐不依赖板块/RPS，板块候选要求上一交易日RPS；缺基准价格不顺延观察日。

当前事实限制：旧报告格式未必包含明确日期、方向、代码或推荐栏目，缺失时保留待核对/无法匹配，不推测成推荐。自动读取选择当日且停止修改一分钟的最新文件，稳定文件不等于上游任务完整成功。样本按系统实际固定时刻判定盘前，不能回填旧报告的历史盘前记录。价格观察为未复权，跨公司行动时不能视为经济收益；事实核对属于用户依据记录，不声称自动完成新闻真实性核验。

只读导入既有报告，保存原始观点、证据、时间、完成状态、hash和版本。Markdown先做校验与导入预览；需要上游JSON时再改契约，不擅改Windows任务或重跑新闻分析。

每天盘前固定一只主样本：优先报告中可唯一识别的最高优先级沪深股；只有板块时，用上一完成日RPS排序该板块候选，同分按代码，保存规则版本和完整候选。无法匹配则无样本；禁止收盘后择优补选。

默认观察当日开盘至收盘方向及相对基准收益，另追踪T+1/5/10。开盘后才完成的报告不得算盘前预测。事实正确性、方向命中率、超额收益、策略成交业绩分别展示。停牌/缺价/延迟/未成熟单列；A股开收收益是观点观察，不冒充可实现的T+0交易。

验收：幂等导入、更新留版本、过期不算当天成功、未成熟不进入命中率分母、缺价不补零、选样早于验证区间、基准可对账。

## 7. V 系列：研究可信度（2026-09-13 立项）

依据 [个人量化软件调研](personal-quant-survey.md) 的差距对照立项。调研把本仓库的缺口排成四类：
多重检验修正、信号有效性评价、证券池时点、留出集治理。**本系列只补这四类，
不碰组合仓位、实盘执行与多品种**——按调研结论，那三项应当在策略被证明之后才做，
现在做等于给一个尚未证伪的东西加装配件。

### 立项依据（已核实，不是推测）

- `walkForward` 每个 fold 在训练段评估 `walkForwardCandidates()` 的 N 个候选、取训练净收益
  第一名，再报告其测试段收益。`summary` 只有 folds / positiveFolds / average / median /
  worst / worstDrawdown。**从 N 个里挑最优这个动作抬高了被选中者的表现，现有输出没有任何
  一项对此做修正**，只在 `assumptions` 末尾写了一句"人工反复修改参数仍可能对整个历史过拟合"。
  一句文字提示不是量化。
- 信号台账 `LedgerSignal` 已有连续 `score` 与 T+5/10/20 `outcomes.returnPct`，
  `aggregateLedger` 只做了分组中位数/胜率/盈亏比。**评分与后续收益之间有没有单调关系，
  现在答不出来**——而这正是"这个信号到底有没有信息"的核心问题。
- A500 用当前名单，`roadmap` 已要求提示生存者偏差，但**提示是文案，没有可核对的数字**：
  区间起点尚未上市、区间内退市、区间内代码变更各有多少只，现在无处可查。
- 没有任何机制记录"同一段数据被研究过多少次"。留出集无从谈起。

### 本系列的固定边界

- **不新增依赖**（正态分布 CDF/逆 CDF 自实现并对照已知分位点落测）。
- **不新增数据库迁移**，除非 V5 确实无法复用既有 records 表——真需要则先报告，
  说明旧 exe 的影响后再做。
- 只增不改：接入既有结构一律新增字段，现有计算路径一行不动，并用特征化快照护栏
  断言既有数值不漂（U1/U11 已验证有效的做法）。
- 缺数据一律 `null` + reason，不 clamp、不补零（`invariants.md §5`）。
- 每批交付后本地提交、不推送；不打包、不接触生产库、不外发。
- **所有结论文案必须带出处与局限**。尤其 DSR 与 PBO：它们修正的是"本系统记录到的
  试验次数"，人工反复调参不可观测，任何情况下都不能把修正后的数字说成"已验证有效"。
