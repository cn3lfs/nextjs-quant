## N2 — 聚宽验证（在 N1 有了初步分布之后）

只有当 N1 的经验分布显示某个策略**看起来有用**时，才值得去聚宽做历史验证。
反过来做（先花大力气回测、再上线）容易掉进过拟合。

1. 把 `StrategySpec` 导出为聚宽 Python 策略骨架。
2. **双系统对齐校验**：同一交易日、同一 spec，本地候选集合 vs 聚宽筛选结果，
   差异必须逐项归因（不复权、数据时点、停牌口径、证券池）。
   没有这一步，聚宽的回测结论不描述本地实际在跑的东西。
3. 出 `docs/strategy-scorecard.md`：每个策略给 **保留 / 降级为研究解读 / 淘汰**。

## P3 — 信号质量的因子分析

**借鉴**：[Alphalens](https://github.com/cloudQuant/alphalens) 的 IC / 分组收益 / 衰减分析。

**要解决的问题**：台账攒了数据但没有分析工具，答不了
「质量 5/5 真的比 3/5 好吗」。若两者的 T+N 收益无差别，评分体系就是装饰。

**交付**：把信号维度（质量分、量比、位置、中枢关系）当因子，
计算 IC 及其均值/标准差、分组 T+N 收益差、衰减曲线、换手率。

**前置**：依赖 N1 台账积累足够样本（约 20 个交易日）。
**样本不足时必须明确拒绝出图，不得用小样本给结论。**

**排期**：等台账数据成熟后再启动，与 N2 聚宽验证同期。

## 明确不做（延续 roadmap §2）

- 不自建回测引擎，不把现有规则自检称为正式策略业绩。
- 不解冻八条流派线，不接其余未接入技能，不做性能优化。
- 不做组合/风控/归因，不扩展 ETF/港美股/期货/可转债。
- 不做实盘自动下单（easytrader/miniQMT），不做 ML 因子挖掘（Qlib）。
- 不另建 LLM 每日报告，不做历史回放生成信号台账，不自动调参。
- 不在没有 N1 证据时增加新策略。
- 公式不支持即时 L2 行情（115项）、关联/专业财务（108项）、板块字符/资金流向/指数标的（80项）、账户/交易信号/绘图/线形资源（116项）；这是原范围分类，不是新增函数待办。
- 不支持的函数明确报名称与行号，不静默跳过，不用近似替代。
