3. 原生缠论使用 CZSC API v22，koffi 绑定、36 字节配置；每个宿主只有一个专用串行子进程。DLL/配置及历史起点冻结，不替换为 TS 近似或并行 DLL 池。来源与分发约束见 [vendor](../vendor/czsc/README.md) 和 [第三方声明](../THIRD_PARTY_NOTICES.md)。
4. 扫描（包含行情/筛选）与回测显式保留页面实例，其余使用常规 Next 路由。URL、具名内存会话、浏览器会话及服务端事实各有所有者，具体生命周期见 [页面状态表](architecture.md#页面模型与状态归属)。
5. SQLite 查询进入类型仓储，分页有稳定唯一排序键；完整遍历与导出明确事务和载荷边界。物理表迁移由实测需求驱动，本轮仓储整理不改 schema，不降低 user_version，不提供旧 exe 绕过版本检查。
6. 数据来源、时间、证券池、复权和交易规则明确；原始值、未知与有效零分开。历史研究不能使用后来披露的财务信息。旧回测只能作为规则自检；缺少历史证券池、公司行动或可成交证据时，不能称为可信策略业绩。详细要求见 [invariants](invariants.md)。
7. 模型只解释有校验的证据，不执行生成代码，不自动下单。通知需要启用订阅；真实测试需要明确请求与目的地，凭证使用仓库外 DPAPI。

## 执行与验收

按可验收的小阶段核实并复用已有能力。局部命名、签名和边界自行处理；未授权范围、付费来源、重大架构取舍和不可逆操作提出具体方案。性能优化由可复现瓶颈和当前验收驱动。

代码改动执行相关 Vitest、typecheck，子任务执行完整测试；应用交付执行 build，涉及 runtime 重建 worker，桌面资源准备执行 desktop:prepare。本轮完整门禁使用 pnpm check --build 的隔离目录；文档检查内容、相对链接与 diff。提交、推送、正式打包及用户库操作分别需要对应授权。任务产物集中管理并在收尾核对，不重建 output 或一次性档案库。
