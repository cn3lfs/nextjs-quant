# 两项前置排查（2026-09-13）

在决定"下一步研究什么"之前做的两项只读排查。结论都改变了下一步的判断。

## 一、信号台账为什么是 0 条

**不是故障，是运行时机从没满足过。**

`runtime.ts:499` 每 60 秒调一次 `scheduleSignalLedger`，但 `runSignalLedger`
（`signal-ledger-job.ts:84`）第一道门就是：

```ts
if (local.slice(11, 16) < "15:05") return;
```

第二道是 `calendar.days.includes(today)`，第三道是当天已有 run 记录就跳过。
`signal_ledger_runs` 表 0 行说明**从来没有一次调用越过前两道门**——
即应用从未在交易日 15:05 之后处于运行状态。

可执行结论：**下一个交易日 15:05 之后让应用开着，台账就会开始积累**，
不需要任何开发。这件事的价值完全取决于开始得多早，因为它是前向记录、无法追补
（`invariants` 明确台账不做历史回放）。

一个顺带发现的隐患：`signal-ledger-client.ts:77` 是
`void scope.ledgerWorker.run(now).catch(() => {})`，**所有异常被静默吞掉**。
如果将来 worker 真的在收盘后失败，界面上不会有任何迹象，
表现和"时机没到"完全一样。这次能定位到原因是因为守卫逻辑简单，
下次未必。建议后续把这个 catch 至少降级为一条日志。

## 二、峰度 93.6 的来源：确认是除权跳空

上一轮滚动检验（sh600000）报出策略净值偏度 −2.55、峰度 **93.62**，
远超真实股票日收益通常的 5–15。核对结果：

- 该标的价格序列自身峰度 **27.07**，GBBQ 记录 88 次事件
- 绝对值最大的 20 个日收益里，**7 个落在 GBBQ 除权日**
- **最极端的 5 个全部是除权日**：−33.10%（2002-08-22）、−30.30%（2009-06-09）、
  −25.95%（2010-06-10）、−23.62%（2011-06-03）、−16.42%（2017-05-25）
- 其余极值全部是 ±10.0x% 的涨跌停，属于真实行情

**判定依据不需要统计推断**：A 股主板日跌幅上限 10%，
−33% / −30% / −26% / −24% 在物理上不可能是市场波动，只能是除权。

### 后果比"收益不可比"更广

`README` 与 `backtest` 的 assumptions 早就写了"不复权、跨除权事件不能用于
正式收益评价"。但那句话描述的是**收益偏差**，这次暴露的是它还会污染
**风险与统计量**：

- 除权日的假暴跌进入净值序列 → 最大回撤被高估
- 进入日收益的三阶四阶矩 → 偏度、峰度严重失真
- 而峰度直接进 PSR 的分母 `1 − γ₃·SR̂ + (γ₄−1)/4·SR̂²`
  ——**V1 刚建的紧缩夏普会被不复权数据污染**
- 持仓期越长的策略吃到越多次除权，与买入持有的比较因此不对等

也就是说：上一轮那份读数里，除了"策略跑输买入持有"这个方向性结论
（两边都吃跳空，但次数不同，方向仍需保留怀疑），
**其余统计量的绝对水平都不该当真**。

### 能力已经在，缺的是口径决策

`tdx-gbbq.ts` 已经有 `adjustmentFactors` / `applyAdjustment`，
支持显式 `none` / `forward` / `backward`，GBBQ 解析也是现成的
（本次核对就是用它做的）。缺的不是功能，是一个决定：
研究路径用哪种复权、成交价用不复权、两者如何在同一次回测里共存
（`cash-adjusted-signals.ts` 在纯现金分红实验里已经有"信号用调整价、
成交与估值用原始价"的先例，可以沿用）。

## 对下一步的影响

原本的建议顺序（先积累台账、再研究策略）需要插入一项：
**在不复权数据上研究任何策略，都是在研究除权噪声。**
复权口径应当排在策略研究之前。
