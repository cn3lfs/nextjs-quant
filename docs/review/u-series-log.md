### 已关闭：`format:check` 基线（`f463e7d` / `144b83c`）

原以为是 37 个历史文件的风格债，实际是**根因误诊**：
`core.autocrlf=true` 在用户全局 `.gitconfig`，仓库无 `.gitattributes`，
git 每次 checkout 转 CRLF，而 prettier 默认 `endOfLine: "lf"` ——
**凡被 git 重写过的文件一律判红**。37 个里 30 个只是行尾。

`conventions.md §9.6` 表格第 2 条记的就是这件事，当时归因为
「定规则前没验证现状」，只对了一半：真正的问题是根因认错，
于是开的药（`prettier --write` 53 个文件）注定无效——
write 修好内容，git 下次 checkout 又加回 CR。红文件数在 37–44 之间漂
也是这个原因（取决于 git 刚好动过哪些文件）。

修法：`.prettierrc.json` 设 `endOfLine: "auto"`；`.prettierignore` 排除
`tests/fixtures/`（fixture 是数据，`ths-statement.html` 供 `fingerprintSource`
断言，重排 JSON 会让 R2/R2c 的文件 hash 失效）。剩余 5 个真实风格差异已格式化。
**`pnpm format:check` 现在真的通过。**

1. `/trade-review` 打开真实账户 → 准入卡片 → 导出 JSON
