## 一处必须记下的调用教训

首次调用我把沪深300 从 2005 年起的全部日历传了进去，结果 TWR 报 4154 条
"期初净值非正（0）"。**这是我的调用错误，不是系统缺陷**——系统正确拒绝了在
净值为 0 时计算收益率。收窄到账户生命周期后降到 250 条。

剩下的 250 条里有 168 条是"期初净值非正（**负值**）"：现金最低到 **−12.6 万**。
净入金 22.8 万却出现负现金，唯一解释是**交割单起点不是开户日**，
账户在 2021-01 之前已有资产。按通用做法从"现金不得为负"反推期初资金下界
`openingCash = 126200`（真实下界 126150.68），中断降到 **74 条**，
最低现金变为 +49.32。

**这个 12.62 万是反推的下界，不是真实期初资金。** 要准确只能补更早的对账单。

**这里有一个百分比与金额不一致的信号，值得单独看。**
按百分比算期望只有 −0.14%，看起来接近打平；但利润因子 **0.53** 意味着
**总亏损金额几乎是总盈利金额的两倍**。最大单笔亏损 −3.2 万、最大单笔盈利 +0.73 万，
相差 4.4 倍，也指向同一件事：

> 亏损的那些交易上投入了更大的仓位。

百分比口径看是"小幅负期望"，金额口径看是"明显亏损"。两者差异不是计算错误，
而是**仓位与胜负的相关性**——这正是 U11 持仓集中度那批想回答的问题，
现在有真实数据可以接着往下查了。

### 执行质量（2543 个买卖点，成交额 4269.6 万）

| 指标 | 值 |
| --- | --- |
| 佣金 | 4,229.53 元 |
| 印花税 | 13,791.81 元 |
| 过户费 | **留空**（2543 笔全部不可得） |
| 费用合计 | 18,021.34 元 |
| 滑点成本 | **−144,657.33 元** |
| 平均滑点 | **−33.88 BP** |
| 总成本 | −126,635.99 元 |

符号定义已核对（`execution-quality.ts:69`）：买入 `(price−vwap)/vwap`、
卖出 `(vwap−price)/vwap`，**正 = 不利，负 = 优于 VWAP**。
所以 −33.88 BP 表示成交价平均比当日 VWAP 好 **0.34%**，累计相当于 14.47 万。

**但这个数字不能直接当成"赚了 14.47 万"**，三条限制：

1. 基准是**当日 VWAP**（成交额÷成交量），不是"本该成交的价格"。
   如果交易习惯集中在某个时段，而该时段系统性偏离全天均价，就会产生稳定偏差
2. **执行损耗（反事实重放）留空**，原因是"实际与 VWAP 反事实的收益分段边界不一致"。
   也就是说 U4 那条"这个执行优势有没有转化成净值"的链路**没算出来**
3. 过户费全部缺失（交割单该列不可得），量级约 4269 万 × 0.001% ≈ 427 元，影响小但确实缺

## 三条结论

1. **工具链路通了。** 2871 行真实交割单零未解析、零冲突，逆回购自动豁免、
   作废流水自动排除、账号自动脱敏，785 个回合完整配对且无未平仓残留。
   R/U 系列的实现在真实数据上没有崩，这一点已经验证。

2. **账户本身是负期望的。** 胜率约五成，但盈亏比 0.89、利润因子 0.53。
   **最值得追的是"百分比小亏、金额大亏"这个背离**——它指向仓位管理而非选股。

3. **两个已知缺口需要用户决定要不要补**：
   - TWR 因 70 笔出入金缺前值估值而无法整体计算。通用解法是把非交易日的
     出入金归到下一个交易日（Modified Dietz 实务做法），但这要改 R 系列实现，
     不是调参能解决的
   - 执行损耗的反事实链路因分段边界不一致而留空，
     导致"比 VWAP 好 0.34%"无法确认是否转化为净值

按 A/B 分层，本次仍是 A 层：数字是程序算出来的，**未经人工复核**。
尤其那个 −33.88 BP 的执行优势，建议按 U 系列早就写好的办法抽 3 笔成交，
用「成交额÷成交量」手算 VWAP 与滑点复核一遍再采信。

## 追查：「百分比小亏、金额大亏」的来源（同日）

用同一份复盘数据接着查了两步，结论比上面那段更具体。

### 第一步：亏损交易的仓位系统性更大

| | 盈利回合（399） | 亏损回合（385） | 差 |
| --- | --- | --- | --- |
| 投入均值 | 24,039 | **30,811** | +28% |
| 投入中位 | 9,960 | **12,978** | +30% |
| 投入 p90 | 56,696 | 70,400 | +24% |
| 投入最大 | 288,902 | **820,162** | +184% |
| 盈亏金额均值 | 663 | **−1,287** | 1.94 倍 |
| 盈亏金额最大 | 7,349 | **−32,157** | 4.4 倍 |
| 合计 | +264,596 | **−495,433** | **净 −230,837** |

**不是个别极端值，是整条分布的一致偏移**——均值、中位、p90、最大值四个分位上，
亏损回合的投入全都更高。

### 第二步：不是加仓摊平造成的

原以为大仓位来自"亏了以后加仓摊平"。**这个猜测是错的**：

| | 盈利回合 | 亏损回合 |
| --- | --- | --- |
| 每回合成交笔数（均值 / 中位 / p90 / 最大） | 3 / 2 / 5 / 24 | 3 / 2 / 6 / 36 |
| **持有交易日**（均值 / 中位 / p90 / 最大） | 3 / 1 / 8 / 80 | **5** / 1 / **12** / 110 |

成交笔数几乎相同，说明**大仓位是开仓时就下的，不是逐步加出来的**。
真正有差异的是持有时间：**亏损交易平均多拿 67%，p90 多拿 50%**。

### 结论：两个独立的负面模式叠加

1. **开仓即重仓**：亏损交易在开仓那一刻投入就比盈利交易多三成，
   与后续走势无关——这是下单时的决策，不是持有中的反应
2. **处置效应**：盈利中位持有 1 天就兑现，亏损却拖到均值 5 天、p90 12 天。
   赚了跑得快、亏了拿得久

胜率 50.89% 说明**信号本身接近五五开，不算特别差**；
真正的亏损来自"输的时候输得更多"，而这由上面两个行为模式造成，**不是选股问题**。

顺带一个观察：785 个回合、5 年、**中位持有 1 个交易日**——这是高频次的超短线交易，
2543 个买卖点、4269 万成交额，费用 1.8 万 + 印花税已计入上表的净额。

### 这条证据改变了一项优先级判断

[调研报告](../personal-quant-survey.md) §4 当时把"组合、仓位与风控层"排在 P3，
理由是"策略被证明之后再做"。**现在有真实数据反对这个排序**：

这个账户的主要亏损来源是仓位大小与持有纪律，**不在信号层**。
再多的信号研究、再准的紧缩夏普，都不会改善一个"开仓即重仓、亏损硬扛"的执行习惯。
按证据，独立的仓位与风控层应当提前。

不过这仍是**单账户、单样本的观察**，不构成普遍结论，也不是自动交易的理由。
下一步若要做，最小可行的是把"开仓仓位上限"和"持有期止损"变成可回测的规则，
用同一份历史成交做反事实对照——而不是直接上线一套风控。
