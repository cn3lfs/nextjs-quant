# 本地财务模块优化与完整解析计划

> 状态：计划已制定，未实施。日期：2026-11-07。
> 用户范围确认：先完成详细计划。目标是充分利用已经下载的通达信数据，优化财务模块并覆盖各部分解析；本文件不表示业务代码已经交付。

## 1. 交付目标

用户可以离线查看单证券完整财务内容、多期变化、股东机构与相关股票序列；可以批量筛选财务条件，与已有技术条件组合，并追溯每一个数值的来源、时间、单位及计算依据。

完成标准分成三层，分别验收：

1. **文件解析完整**：本地每个文件有类别、解析状态和来源指纹，原始记录与未知槽位均保留；不静默丢弃尚未解释的数据。
2. **语义解析完整**：每个已确认字段有官方编号、物理位置、名称、单位、适用证券、时点和零值语义；保留项、未下载项、未核验项有独立清单与数量。不能把“658 个槽位读出来”称为“658 个财务指标均已核验”。
3. **产品使用完整**：三表、每股、质量成长、单季/TTM、股东机构、预告快报、股票/板块/市场序列都能查询、展示或给出具体不可用原因，支持同版本导出和批量筛选。严格历史业绩认证单独列出证据边界。

本次围绕已有工作台增量实现，不新增实盘能力、付费数据或 Python 宿主，不重做交易引擎。全面兼容通达信公式语言的 FINVALUE/FINONE 等函数不作为本模块前置条件。

## 4. 先统一的正确性契约

### 4.1 字段、单位与缺失

- 常规已核验 FN 编号与 `values[ID-1]` 对应；扩展逻辑编号与物理槽位必须显式映射，不能一律相减。例如官方另列 FN5651–5658，本地尾部 651–658 槽有数值，但这只是映射候选，须通过同证券同报告期对照核实。
- 注册表记录逻辑编号、物理位置、中文名称、分组、原始/统一单位、倍率、累计/时点/事件语义、合并/归母主体、行业适用性、证据和映射版本。
- 原值、标准化值、派生值分别保留。金额可统一到元，股数统一到股，计算内部比例与展示百分数明确转换；不能把所有新增科目都当作元。
- 状态区分有效、来源零但有效性不明、不适用、字段缺失、日期缺失、未知映射及文件损坏。官方会将某些空值显示为零，源文件若无法区分，应用必须保留不确定性；不全局把零转成 null，也不全局认证零为有效。
- 纠正长期负债/少数股东权益、主营利润/营业成本、总权益/归母权益、合并/归母净利润混用。负债率取总负债/总资产；ROE、利润率及现金含量明确分子分母主体。
- 市值优先使用已验证 GP 市值或对应时点股本与未复权价格。PB/PE 的每股或总额口径保持一致，亏损或非正权益输出原因；不把价格复权倍数施加到财报金额。

### 4.2 时间与版本

- 财报报告期、财报公告日、预告公告日、快报公告日、事件发生日、实际可见日、采集时间分别保存。不同数据类型不共享一个默认生效日期。
- 公告只有日期时，严格研究默认下一交易日起可见；财报日期缺失或可疑时不能按固定披露天数补造。GP 日终数据在当日日内不可提前使用；股东人数等滞后披露数据无公开时点证据时只用于当前分析。
- 官方说明部分预告/快报字段对应未来一个报告期，不能继承包头报告期和财报公告日。目标期推导必须有来源规则，否则标未知并禁用于严格历史条件。
- 每个字段随来源 SHA-256、文件内位置、映射版本、计算版本、报告期/事件期和可用性说明返回；复现用的快照另保存实际输入和涉及的来源版本。
- 当前历史包可能已被修订；先交付“当前下载版本、按已知日期约束的研究”，不称为首次披露版本。未来采集保存版本不能逆向恢复从未留存的过去版本。
- 同一证券同一报告期或同一事件组同日存在重复时，保留原记录序号并报告冲突；没有规则依据不得任意取最后一条。日期为 0 的记录单独分类，不能因为一条异常拒绝全部有效序列，也不能静默吞掉异常。

首先采用按包批量读取、按需投影和有上限的内存缓存。9,331 个文件约 1.68 GB，不得每次切证券、改筛选条件或刷新页面重读全目录；按文件/证券和用户操作读取必要范围，重扫描与批量分析进入可取消任务。

暂不先建全量财务数据库。只有实测查询、离线档案和历史版本需求证明需要时才增加索引表，并在实施该阶段前列清表结构、迁移和旧 exe 影响；验证必须使用隔离 QUANT_DATA_DIR。旧年度档案的内容/哈希/ID 不改，新增来源使用新版本并维持旧档案读取。

## 6. 产品交互与使用闭环

单股入口保留行情页财务摘要，详情按“概览、三张报表、质量成长、股本机构、预告快报、股票序列、板块市场、来源诊断”组织；按证券类型显示适用内容，股票与板块/市场间沿用现有导航。

2026-11-13 优化：完整财务工作台移入行情页“财务资料”子视图（`/market?symbol=…&view=financial`），默认图表不挂载财务详情。两子视图首次进入后保留局部状态，换证券重置财务草稿；隐藏时暂停查询与轮询，已提交任务继续执行。F10 从图表切到财务资料。

- 共享查询条件：证券、报告期或日期区间；财报支持年度/季度、累计/单季/TTM。显示最近 12 期并允许继续加载，不能沿用最近 8 期服务限制截断可查询历史。
- 摘要先展示报告期、公告日、当前来源、数据更新时间/覆盖和关键缺失，再展示业务指标；本地数据可离线使用，协议快照只作为有标注的独立叠加。
- 三表和指标可切换金额显示单位；资产负债类不提供无意义的“累计转单季”。多期趋势和同比的缺口留空，提供原值、公式及组成期数下钻。
- 预告/快报显示目标报告期、区间、公告日、后续正式报告状态；不以区间中点冒充实际盈利。股票序列按事件、日频与统计分类，查看各自覆盖起止。
- 质量成长档案可明确选择“本地财报”生成，不默认发起在线查询；在线来源保留为显式可选补充，展示字段冲突且不静默混算。
- 批量筛选复用现有证券池和行业分类，服务端筛选/排序/分页；可选财务条件与已有技术/RPS 条件，逐条件显示值、报告期、缺失原因和匹配结果。
- 导出包括业务表、原值与标准化值、计算依据、字段版本、源指纹、排除原因和查询条件；页面、历史档案、导出属于同一版本，源文件更新不得改变已保存报告。
- 空目录、空占位、未覆盖证券、非适用证券、损坏文件、旧报告、取消和失败分别显示。无本地数据的类别直接说明文件或字段缺口，不能显示空白页或补造模拟数字。

组件使用现有 DataTable、UI 组件及样式 token。实施 UI 前读取项目当前 Next.js 本地指南，并按受影响交互验收桌面、窄屏、键盘、刷新恢复和加载失败。

## 8. 验证、性能与数据生命周期

### 8.1 必须覆盖的验证

1. 结构：包头、版本、日期、字段长度、索引越界/重叠、重复代码、ZIP CRC/解压容量和异常文件；序列尾部残缺、未知组号、两值字段、乱序、同日多条和日期 0。空占位是单独状态，不能放宽损坏校验。
2. 字段：常规编号与下标、防止特殊编号错位；元/万元、股/万股、比例/百分数、日期/时间/枚举；旧误标回归以独立字段定义断言，不能只测试“与旧协议值相等”。
3. 业务：会计恒等式及可解释的源差异；单季、跨年 TTM、ROE 主体与加权差异、负利润/零分母；预告和快报独立目标期；金融类零与不适用。
4. 时点：周末/节假日公告、下一交易日、分钟日内不可见、缺公告日、晚披露、修订、统计日期、日终 GP 数据；不同数据源不能共享错误的可见日。
5. 兼容：现有行情财务摘要、快照报告期反查、档案哈希/导出及相关基本面研究；一次更新不改历史结果。
6. 全量：持久审计脚本输出文件/记录/字段/类别覆盖与失败；代表选主板、创业板、科创板、银行/保险/券商、亏损企业、板块及全市场，北交所仅验解析能力，不擅自扩充沪深交易池。

持久测试放 `tests/` 或现有 package 测试入口；新增纯解析/计算用例对应固定输入和独立预期。改动级相关 Vitest/typecheck，阶段子任务 `pnpm test`；有意义的应用交付 `pnpm build`，runtime 改动重建 worker，桌面交付前 `pnpm desktop:prepare`。只写计划不运行应用全套测试。

### 8.2 性能与持久物

- F0 记录实际样本规模，F1/F3/F4 分别测冷读与热读、单股 12 期、板块/市场序列及全沪深财务筛选，报告机器、数据版本、耗时和峰值内存。
- 热读取不得重复全目录解码；输入较大或跨证券的扫描必须有进度和取消，取消后不得保存成功档案或半成品覆盖旧结果。
- 缓存按内容/文件版本和映射版本失效，设条目/字节上限，异常不能污染缓存；保留读取期间源变动检测。不预设没有测量依据的性能收益。
- 临时目录由任务创建、finally 清理，异常退出由隔离缓存启动清理兜底；清理失败只报告路径和原因，不扩大删除范围。计算缓存可重建，研究档案由用户删除，不自动淘汰；持久源快照按档案引用管理，禁止无限复制整套 1.68 GB 文件。
- 测试、浏览器和应用验证先设置隔离 QUANT_DATA_DIR；通达信、Blocks 与正式库保持原状。不存在本任务附带的正式数据重算、迁移、推送或打包授权；用户随后已明确授权本地提交。
