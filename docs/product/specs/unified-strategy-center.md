# 统一策略中心产品与模块规格

日期：2026-11-10。用户授权：全部已有策略纳入整理；公开国内外基础策略按现有数据集成；本期沪深市场；直接采用新结构，不保留旧接口兼容层；实施由多 Agent 分工，独立 Agent 验收。

## 使用目标与信息架构

用户从「策略中心」寻找一个方法，读懂规则与数据缺口，选择参数，运行其实际支持的筛选或回测，再查看同口径历史结果。单页连续阅读，不让用户在目录、说明和执行页面之间反复跳转。目录不以历史收益排名作为默认推荐。

实施前文本设计稿：

```text
策略中心                         [搜索名称 / 来源 / 规则]
全部 N   可执行 N   研究方法 N   存在缺口 N
[类别] [频率] [实现状态] [运行方式] [清除筛选]
┌策略列表────────────────┬策略详情────────────────────────┐
│名称 / 类别             │名称 · 规则版本                  │
│实现 · 数据 · 验证      │规则与适用范围                   │
│支持筛选 / 信号 / 权重  │来源链接、本地改编、参数与预热   │
│选中项保持醒目          │依赖数据、可用性、具体缺口       │
│                        │[运行支持的动作] [相关研究入口]  │
└────────────────────────┴────────────────────────────────┘
运行配置：标的或证券池 / 日期 / 参数 / 费用与成交假设
运行进度 / 失败原因 / 取消
历史结果：版本、输入证据、验证等级、绩效与完整导出
```

首屏默认列全目录，按类别和名称稳定排序；选择第一条可见项。搜索与筛选后已选项不在结果中时，选择新的第一项；无结果显示清空筛选操作。窄屏先列表后详情。列表数量是规则/方法条目数，不声称是独立 alpha 个数。缺数据动作给具体原因，不使用一个含糊的「未开放」。

## 能力和状态

- 分类采用收益逻辑，来源国家/频率/资产/持有期作为标签，不维护两套国内外重复实现。
- 同一规则的均线周期、分档阈值等是参数预设。风控、配置、执行算法和研究工具不计为独立买入策略。
- 实现状态、输入是否齐备、验证等级独立呈现。实现存在不表示正式任务可执行，规则自检不表示可信业绩。
- 输出区分筛选、评分、交易信号和目标权重；有定性解释但无确定性规则的方法标「研究方法」。
- 目录新增接口只读返回定义；可用性检查必须结合本次输入/证券池/时间范围。未做运行级检查时显示「需检查输入」，不能标「数据完整」。

## 目标职责与接口

`trading-strategies` 负责定义、来源、参数、依赖、纯信号/评分/目标权重及策略专属规则；`trading-strategy-core` 和 `quant-rps` 保留共享计算；`quant-backtest` 只负责撮合、资金、费用和回放；`quant-performance` 独立派生评价。应用承担取数、快照、任务、存储、原生 DLL 和 API。

定义接口包含稳定 ID、版本、主分类、规则、来源、参数、预热、输入依赖及运行能力。实例冻结定义版本和参数。上下文只提供决策时刻已可见输入。可用性返回逐项缺口，未知不能默认为可用。运行结果冻结输入摘要、证券池、复权、费用和执行假设。

旧调用方同批迁移到新接口，删除被替代活动入口，不加 re-export 兼容壳。历史记录保留原始格式及哈希，历史读取属于证据访问，不要求为旧配置保留新执行能力。

## 验收

1. 已有方法清单逐项有归属，参数预设与完整策略分开。
2. 每个策略可查看规则、来源、参数、依赖和实际支持动作；不存在把研究条目直接送进交易执行器的兜底。
3. 固定输入可复现，追加未来数据不改变历史信号；缺失、预热和财务公告可见时间有用例。
4. UI 检查搜索、组合筛选、空结果、切换详情、运行入口和缺口说明；同口径比较复用现有年/季/月评价。
5. 完成与未完成分别登记；本规格是目标与设计稿，不能替代代码、测试或真实数据验收。
