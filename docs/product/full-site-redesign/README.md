# 观澜全站浅色重设计 · 产品交付

日期：2026-11-12。规模 L；使用 product-delivery 与 ui-design-system，调用 Google Stitch。设计阶段已按次数上限封板；用户2026-11-13追加授权立即开发，实际进度见[开发覆盖](development-coverage.md)。设计画板不等于应用已实现。

## 用户与目标

面向个人沪深量化研究者，兼顾独立数字货币模拟与期货行情浏览。首屏应回答“当前看什么、数据是否可靠、下一步做什么”。
Must：24个入口逐一覆盖；每页规格、主稿、关键状态、审阅记录可追溯。Must：浅色与清晰正文；历史事实、数据时点与能力边界不丢失。
Should：同一对象跨页延续与返回定位。Later：服务能力补齐和实际运行验收。前端实施与静态检查见[开发交付](../../shared-ui/2026-11-13-full-site-light-redesign.md)。

## 导航

保留现有URL，以任务重新分组：今日（总览、盘中预选、财联社复盘）；发现（行情、选股、打板情绪）；研究（策略中心、策略实验、样本研究、证据分析、新闻、档案）；追踪（信号通知、信号台账、交易日志、交割复盘）；其他市场（数字货币、资源期货）；系统（数据与连接、RPS管理、任务中心）。
研究指南由研究页进入；报告详情从档案进入；组件参考不列业务导航。导航可折叠分组并提供名称搜索，不把全部入口同时挤进首屏。
顶栏“搜索页面”仅按已有导航名称/标题/路由检索页面，Ctrl+K聚焦、方向键选择、Enter进入；不新增跨业务内容搜索。已有部分设计稿占位文案过宽，最终统一收口时纠正。

## 五条端到端流程

```mermaid
flowchart LR
 A[数据与连接] --> B[诊断与覆盖]
 B --> C[RPS计算 / 任务]
 C --> D[行情 / 筛选]
 D --> E[候选与图表]
 E --> F[策略中心 / 证据分析]
 F --> G[实验 / 样本研究]
 G --> H[任务结果 / 研究档案]
 H --> I[信号 / 复盘 / 台账]
 I --> E
```

新闻→原文→冻结范围分析→主题/档案→财联社预测复盘独立于当前检索。
数字货币行情、策略模拟账本、平台账户查询三域分开；期货只浏览。图中箭头表达产品任务关系，不代表新增API或自动执行。

## 公共交互契约

查询草稿与已提交条件分离；运行输入与旧报告冻结身份分离；列表范围与全样本范围分离。
选择对象→查看详情→跨页查看→返回时恢复过滤、页码、排序、选中对象和滚动位置。首次直达没有来源则回所属列表。
长任务提交后提供任务ID和结果位置，可离开；失败保留输入。重试是否复用任务依据现有服务，不新增盲目重放。
新鲜度在数据标题旁显示，数据缺失用“— / 缺失原因”，不填0、不补造图表。错误局部恢复；加载时不能把旧对象数据标成新对象。

## 接口与能力边界

设计阶段没有公共API、类型、数据库或应用变更；当前已进入授权的界面开发，不变更金融计算/交易数据契约。导航重组、分区标签和状态恢复为后续前端设计目标，尚未实现。
缺口：每页拟议布局需后续对接现有查询；现有接口无法支持的汇总或联动，先展示来源入口，不造能力。页面规格的主流程不自动授权实际交易、通知或付费调用。

## 设计次数限制

用户2026-11-13要求停止循环修图，现按[硬上限](design-limits.md)执行：每页最多3次Stitch调用，状态与修订计入同页；现有L01–L21冻结，只收在途；L22–L24各3次。未修问题如实交接，不再无限返工。

## 验收与任务

T1→R1：完成[24页规格](pages.md)与[覆盖数据](pages.json)；R1每页任务、分支、返回规则明确。
T2→R2：统一[浅色规范](../../../DESIGN.md)；R2正文、重点、操作与状态有明确层级。
T3→R3：逐页Stitch生成、补关键状态、审阅修订；R3记录screen ID及缺口，未审稿不得称完成。
T4→R4：语法/链接静态检查与交接；R4覆盖矩阵无遗漏。仅静态检查，不运行测试与构建。
