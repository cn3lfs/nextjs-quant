# 任务书 R13：复盘页面的规模与可读性（最后一批）

复盘的**正确性已经全部验收通过**（真实账户净值 1265/1265 可得、残差 295.90、
最大回撤 30.16%、日收益极值 11.95%、缺行情 0）。剩下的是页面本身不可用。

管理者用真实账户在浏览器实测，页面无障碍树 **22,070 行**，
滚到净值曲线要经过两万行表格。

## 1. 表格必须分页

`conventions.md` §4 明确要求：**表格一律用 `DataTable`，
它只接收服务端已排序、已分页的数据；禁止客户端全量加载或客户端重排。**

当前回合表与买卖点是全量渲染的（真实账户 785 个回合、2543 条买卖点）。

### 要求

- 回合表、买卖点表、归因分组表改用 `DataTable`，
  分页与排序参数走 tRPC（新增分页入参），**不要**把整份快照塞给组件再前端切片。
- 保留移动加权 / FIFO 两套口径的切换，切换时分页重置到第一页。
- 缺行情清单、待核对行、作废流水这些列表如果可能很长，同样分页或折叠。

## 2. 超长诊断文本要折叠

TWR 不可得的原因目前是**几百条拼成的一个字符串**，
真实账户里这一条就有上万字符，页面上是一大坨无法阅读的文字：

```
TWR：不可得：2021-01-25 期初净值非正（0），收益率无定义；2021-01-27 净值或TWR分母非正；
2021-02-05 资金流水 4 缺少出入金前账户估值；…（继续几百条）
```

### 要求

- 这类多条原因**改为结构化列表**（日期 + 原因），不要在数据层拼成一个长字符串。
  数据结构变更要同步 `trade-review-nav.ts` 的返回类型与既有测试。
- 页面上默认只显示前若干条 + 「共 N 条，展开查看」（用 `ui/collapsible`）。
- 同类原因（如「期初净值非正」出现上百次）**归并计数**再展示，
  例如「期初净值非正：87 天（2025-09-25 至 2025-12-24 等）」。
- 归并只影响展示，**导出 JSON 仍保留完整明细**。

## 3. 不要动的

- 所有已验收的口径与数字：残差独立展示不平账、`openingUnknown` 收益留空、
  作废流水笔数与金额、逆回购本金按面值、费用来源标注。
- 净值曲线「缺失处不补零、不跨缺口连线」的既有行为。
- 解析层、存储层、复盘引擎的计算逻辑——本任务只改**呈现与分页**，
  以及为分页所需的接口形状。

## 4. 验收

- 页面首屏无障碍树规模**降到千行以内**（当前 22070 行）；
- 回合表、买卖点表分页可用，翻页正确；
- TWR / 夏普不可得的原因可读：默认摘要 + 可展开；
- 导出 JSON 内容不因展示归并而丢失。
