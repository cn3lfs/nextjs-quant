# 任务书 W4：出入金前估值与 TWR

W 系列第 4 批。触发依据：[W2 复盘](../review/w2-real-account-review-2026-09-13.md)
里 TWR 整体留空，74 条中断里 70 条是「资金流水 N 缺少出入金前账户估值」。

## 1. 先说清楚根因，它和最初的猜测不同

管理者最初判断是"出入金发生在非交易日"，**核实后这个判断是错的**：
70 条中断**全部发生在交易日**（用沪深300 日历逐条比对），
所以"把非交易日出入金归到下一交易日"这个方案完全不适用。

真实条件在 `trade-review-nav.ts:454-462`：

```ts
const before = repoReasons.size ? null
  : Object.keys(positions).length === 0 && !positionReasons.size
    ? (cash === null ? null : cash + repoPrincipal()!)
    : (input.flowValuations?.[e.flowIndex] ?? null);
if (before === null || !Number.isFinite(before)) returnReason = `...缺少出入金前账户估值`;
```

**账户空仓时**内部可以直接算（现金 + 逆回购本金）；
**有持仓时**必须由调用方通过 `flowValuations` 提供。W2 的调用没传这个入参，
所以只要出入金当天有持仓就中断。**这是接口设计，不是缺陷**——
日线粒度下系统无法知道"出入金发生前那一刻"的持仓市值，它拒绝自己编一个。

## 2. 交付

### 2.1 新增可选估值模式，默认行为一行不改

`TradeReviewNavInput` 增加可选项（如 `flowValuation?: "explicit" | "previousClose"`，
默认 `"explicit"` = 现状）。

`"previousClose"` 时：当某笔出入金需要 `before` 而 `flowValuations` 未提供，
用**前一交易日收盘时的账户总估值**（现金 + 持仓市值 + 逆回购本金）补足。

- 调用方显式传了 `flowValuations[i]` 的，**优先用调用方的值**，不覆盖
- 前一交易日估值本身不可得（首日、或前一日有持仓缺行情）→ 仍然留空 + 原因，
  **不要再往前找更早的日子**——隔得越远越不是"出入金前"
- 逆回购原因集合 `repoReasons` 非空时维持现状留空，本批不动

### 2.2 口径必须标注，不能当成精确值

用前一日收盘替代"出入金前一刻"，等于把**出入金当日的市场波动整段算进了出入金前的那一期**。
这是已知近似，市面实务在日频数据下也这么做（GIPS 对大额外部现金流要求当日重估，
但日频数据下"当日重估"只能落到最近可得估值）。

因此：

- `nav` 输出里标明本次用的是哪种模式
- `"previousClose"` 下产出的 TWR 必须带一条固定说明：
  **「出入金前估值取前一交易日收盘，当日市场波动计入出入金前一期；不是精确时点估值」**
- 页面显示 TWR 时同步显示该说明，不许只显示数字

### 2.3 不做的事

- 不改 `"explicit"` 模式的任何行为
- 不引入分钟级估值
- 不改 Modified Dietz 或其他收益算法——本批只补一个缺失的输入，不换算法

## 3. 测试

- **手算**：3 个交易日、已知持仓与价格，第 2 日发生一笔转入。
  断言 `before` 等于第 1 日收盘的账户总估值，注释写出算式
- **调用方优先**：同时提供 `flowValuations[i]` 与 `"previousClose"` 模式，
  断言用的是调用方的值
- **不向前追溯**：前一交易日估值不可得时留空 + 原因，
  断言**没有**退到更早的日子取值
- **空仓路径不变**：空仓时仍走 `cash + repoPrincipal()`，与模式无关
- **默认不变**：现有 fixture 在默认模式下结果逐项相等（特征化快照）
- **逆回购**：`repoReasons` 非空时两种模式都留空

## 4. 验收

- 默认 `"explicit"` 行为零变化，有特征化断言
- `"previousClose"` 下 W2 那 70 条中断应显著减少（不要求归零：
  首日与前值不可得的情形仍会留空）
- 固定说明同时出现在数据结构与页面
- 不新增依赖、不新增迁移
- `invariants.md` 补一条：两种模式的语义与近似代价
- `pnpm typecheck` / `pnpm test` / 改动文件 prettier 通过
