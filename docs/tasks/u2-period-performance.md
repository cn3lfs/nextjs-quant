# 任务书 U2：分段表现与近 N 天收益矩阵

依赖 [U1](u1-daily-performance.md)，U1 未合入前不要开工。

来源：czscflow `czscflow-strategy/src/recent_returns.rs:show_splited_daily`
与 `czscflow-strategy/src/utils.rs:calc_periodic_returns`。

另参照 [wbt](https://github.com/zengbin93/wbt) `src/core/period_win_rates.rs`：
它按**自然周期**（ISO 周 / 月 / 季 / 年）聚合日收益，统计「区间和 > 0 的周期占比」，
产出周胜率 / 月胜率 / 季胜率 / 年胜率四个数。这四个数很便宜，
建议一并做进 U2，跟分段表现放同一张卡片——
「日胜率 52%」和「月胜率 70%」讲的是完全不同的故事。
注意 ISO 周的跨年归属：`iso_week().year()` 不等于 `year()`。

**（2026-09-12 修订）不要为此新增依赖。** 初稿写「用日期库实现，不要自己数天」，
但仓库里根本没有日期库，这条把执行者逼进了死角。

事实：仓库既有做法就是纯字符串日期运算（`trade-review-nav.ts:658`
用 `d.slice(0, 7)` 做月度分组）。月/季/年都能从 `YYYY-MM-DD` 直接切，
只有 ISO 周需要真算术，而它是 6 行标准算法，为它引一个依赖不成立
（`conventions.md §1`：优先复用已有依赖）。

按 ISO 8601 的规范定义实现：**一周归属于包含它星期四的那一年**。

```ts
// 返回 [isoYear, isoWeek]。入参为 YYYY-MM-DD。
const [y, m, d] = date.split("-").map(Number);
const t = new Date(Date.UTC(y!, m! - 1, d!));
const dayNum = t.getUTCDay() || 7; // 周一=1 … 周日=7
t.setUTCDate(t.getUTCDate() + 4 - dayNum); // 移到本周星期四
const isoYear = t.getUTCFullYear();
const week = Math.ceil(
  ((t.getTime() - Date.UTC(isoYear, 0, 1)) / 86400000 + 1) / 7,
);
```

**必测向量**（手算可复核，写死进测试）：

| 日期         | 星期 | 期望         | 说明                                          |
| ------------ | ---- | ------------ | --------------------------------------------- |
| `2021-01-01` | 五   | `[2020, 53]` | 跨年归属：本周四是 2020-12-31，归 **2020** 年 |
| `2026-01-01` | 四   | `[2026, 1]`  | 本周四就是自己                                |
| `2026-12-31` | 四   | `[2026, 53]` | 年末仍归本年                                  |

第一条尤其重要——真实账户数据正是从 2021-01 开始的，
按自然年归属会把这一周错算进 2021。

## 1. 问题

我们的复盘只有「整段」和「R7/R9 的连续段」两种时间切法。
连续段是被资金流水和持仓中断被动切出来的，回答不了
「最近一个月怎么样」「今年以来怎么样」这类主动提问。

czscflow 有两个我们完全没有的视图：

- **分段表现**：过去 1 周 / 2 周 / 1 月 / 3 月 / 6 月 / 1 年 / 今年以来 / 全部，
  **每段跑同一套 15 指标**
- **近 N 天矩阵**：近 1/3/5/10/20/30/60/90/120/180/240/360 天 × 标的 的透视表，
  末尾附「盈利标的数量」「盈利标的比例」两行

第二个尤其实用——一屏扫出哪些标的最近在赚钱、有多大比例在赚。

## 2. 交付

新建 `src/lib/period-performance.ts`（纯函数）。

### 2.1 分段表现

```ts
export const periodWindows = [
  "past1w",
  "past2w",
  "past1m",
  "past3m",
  "past6m",
  "past1y",
  "ytd",
  "all",
] as const;
```

每段调用 U1 的 `dailyPerformance`，返回 `{ window, startDate, endDate, ...15项 }`。

**与 czscflow 的关键差异——回溯用交易日，不用自然日。**
它用 `Days::new(7)` 做自然日减法，落在周末就少算一天。
我们已经有 R2c 的全量本地指数交易日历，必须用它：
「过去 1 周」= 从末日往回数 5 个交易日，2 周 = 10，1 月 = 20，
3 月 = 60，6 月 = 120，1 年 = 250。`ytd` 用自然年首日再对齐到日历上的首个交易日。

这条口径差异写进 `invariants.md`，注明「czscflow 用自然日，我们用交易日，
故同名分段的数值不可与其输出直接比对」。

**5/10/20/60/120/250 这组映射是 A 股日历特有的**（BTC 24/7，一周是 7）。
把它定义成一个具名常量表，不要把数字散在各处 `slice` 调用里；
日历入口也保持可替换。本批**只实现 A 股一套**，不建市场切换机制——
只是别让以后换市场变成全文搜数字。

窗口长度超过可得数据时，**不静默截断**——返回实际起止日期和实际交易日数，
并在结果里标 `truncated: true`。样本不足 5 个交易日的段，
15 项指标照算但整段标 `insufficientSample: true`，页面必须显示这个标记。

### 2.2 近 N 天收益矩阵

```ts
export const periodicWindows = [
  1, 3, 5, 10, 20, 30, 60, 90, 120, 180, 240, 360,
] as const;
```

输入是 `Record<string, readonly (number | null)[]>`（标的 → 日收益序列）
加共享的日期轴。输出透视表：行 = 标的，列 = 12 个窗口，值 = 该窗口累计收益
（口径跟随 U1 的 `basis`，默认 compound 用累乘）。

外加两行汇总：

- **盈利标的数量** = 该列 `> 0` 的标的个数
- **盈利标的比例** = 数量 / 标的总数

czscflow 用 `> 0` 判盈利（注意它的日胜率却用 `>= 0`，自身不一致）。
我们统一用 `> 0`，并在注释里标明这与 U1 日胜率的 `>= 0` 口径不同、原因是
「标的层面零收益等同于没赚到，不算盈利标的」。

窗口内某标的存在 null 日收益时，该标的该窗口返回 `null` + reason，
**不当作 0 参与累计**，也不计入盈利/亏损分母。分母要按列单独算可得标的数。

### 2.3 接入

- `/trade-review`：账户净值下方加「分段表现」表；
  近 N 天矩阵按**持仓标的**展开（标的日收益来自复盘专用日线）。
- `/research`：策略样本结果页加「分段表现」；
  近 N 天矩阵按**策略/参数组**展开。

两处都走 tRPC，服务端算好再传。表格用 `DataTable`，
分段表 8 行不必分页，近 N 天矩阵标的可能上百，**必须服务端分页**
（`conventions.md §4`，R13 已立的规矩）。

## 3. 测试

`tests/period-performance.test.ts`：

- 构造 300 个交易日的合成序列，手算校验每个分段的起止日期落在正确的交易日上，
  尤其检查跨周末、跨长假、跨年这三种情况。
- `ytd` 在 1 月初（可得交易日 < 5）时返回 `insufficientSample: true`。
- 数据不足 360 天时，长窗口返回 `truncated: true` 和实际交易日数。
- 近 N 天矩阵含 null 的标的返回 `null` + reason，且不进入盈利比例的分子分母。
- 分段的 15 项与直接对同一子序列调 U1 的结果**逐项相等**（不允许 U2 自己算指标）。

## 4. 验收

- 8 个分段 + 12 个窗口全部出数，起止日期可用交易日历人工核对。
- 分段指标全部来自 U1，`grep` 不到 U2 里有第二份指标实现（`invariants.md §1`）。
- null 不被 0 顶替，盈利比例的分母是可得标的数而非标的总数。
- 近 N 天矩阵走服务端分页，页面无障碍树不因标的数增长而爆炸。
- `invariants.md` 补上「交易日回溯」这条口径差异。
- `pnpm check` 通过；浏览器验收由管理者用真实账户执行。
