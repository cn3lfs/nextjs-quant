# 任务书 W8：逆回购方向以金额符号为准

依据：[逆回购核对](../review/w6-repo-gap-2026-09-13.md)（读它的「更正」节，前半部分已作废）。

## 1. 根因（已核实到行）

成交明细里逆回购的**操作列不可靠**：

```
204001 卖出 数量8 价1.370 金额8000  发生 +8000.900   ← 购回
204001 卖出 数量8 价1.370 金额8000  发生 −8000.080   ← 融出
```

同样标「卖出」，方向相反，**区别只在发生金额的符号**。逐笔统计：
204001 有 **29 笔**、131810 有 **1 笔**标记为"卖出"但金额为正（实为购回），合计 +866,046 元。

现有实现有两处按 `kind` 判方向：

| 位置 | 代码 | 后果 |
| --- | --- | --- |
| `trade-review.ts:30` | `f.instrument === "reverseRepo" ? f.kind === "sell" : f.kind === "buy"` | 费用推断的方向可能反 |
| `trade-review.ts:181` | `x.fill.kind === "sell" ? x.fill.quantity : -x.fill.quantity` | **数量净额永不为零 → `interestIncome` 永远是 null** |

204001 按 kind 算是 112 − 54 = **58 ≠ 0**，于是系统永远报
「逆回购尚未全部购回或缺实际资金发生额」。而按金额符号算，
**融出 83 笔对购回 83 笔，正好平衡**。

注意 `capitalCommitted`（`:170`）用的是 `repoCash.filter(n => n < 0)`，
**已经是按金额符号**——所以同一个文件里两种口径并存。本批统一为金额符号。

## 2. 交付

### 2.1 逆回购方向一律以 `netAmount` 符号判定

- `netAmount < 0` → **融出**（现金流出）
- `netAmount > 0` → **购回**（现金流入）
- `netAmount === null` 或非有限 → **不猜方向**，该笔计入"方向不可判"并计数；
  若某品种存在不可判的笔，该品种的 `interestIncome` 留空 + 原因

**仅对 `instrument === "reverseRepo"` 生效**，普通证券的 `kind` 判定一行不改。

### 2.2 数量净额同步改口径

`:181` 的配平判定改为按金额符号累计数量：融出记正、购回记负。
净额为 0 才算全部购回。

### 2.3 `kind` 与金额符号冲突时要留痕

那 30 笔标「卖出」实为购回的记录，**在 `anomalies` 或 warnings 里留一条**，
说明"操作列与资金方向不一致，以资金方向为准"。**不要静默修正**——
这是数据源的已知特征，将来换券商导出格式时需要能发现。

## 3. 测试

- **手算配平**：构造一个品种 3 笔融出（负）+ 3 笔购回（正，其中 1 笔 kind 为 sell），
  断言配平成立、`interestIncome` 等于净额之和
- **不配平**：去掉一笔购回，断言 `interestIncome` 留空 + 原因
- **方向不可判**：`netAmount` 为 null 的一笔 → 该品种留空并计数
- **冲突留痕**：kind=sell 但金额为正的一笔，断言 warnings 里有对应说明
- **普通证券不受影响**：股票的 `kind` 判定与改动前逐项相等（特征化快照）
- **既有数值护栏**：现有复盘 fixture 的非逆回购字段全部保持不变
