# 任务书 R7：净值连续性（最后一批功能修复）

R6 后真实账户净值可得率从 0% 升到 **42.2%（534/1265 天）**，
残差从 17554 降到 **295.90**，缺行情标的从几十个降到 **2 个**。
但净值仍有 58% 不可得、**TWR 依然算不出来**。管理者已定位到根因，都不是数据缺陷。

## 1. 中签缴款不应使持仓「未知」

首个断点：

```
2023-04-11 subscription 流水缺少可确认的股份变动，后续持仓未知
```

那笔是 `370409 道氏发债 / -1000 / 摘要「买入」`——**新股（可转债）中签缴款**。

缴款时股份**还没到账**（T+2 才上市，且上市后代码变成 `123190 道氏转02`，
与申购代码 `370409` 不同）。所以缴款这一笔只是**现金流出**，
对持仓没有任何影响，不该触发「持仓未知」。

### 要求

- `subscription` 类现金流**只影响现金，不影响持仓推演**。
- 中签得来的持仓由 R3 既有的 `openingUnknown` 机制处理
  （真实账户里这样的标的只有 1 个：`123190`，卖出 10 张、无买入记录），
  **不要**去猜「申购代码 → 上市代码」的映射，那不可靠。

## 2. 「持仓未知」必须可恢复

即使某个标的的持仓一度未知，**它被完全卖出清零后，后续持仓就重新确定了**。
真实账户里 `123190` 在 2023-04-25 全部卖出，但引擎让 2023-04-11 之后
**一直到 2026 年**的净值全部不可得——这是把局部、临时的不确定，
放大成了永久性的全局失效。

### 要求

- 持仓不确定应当**按标的、按时间段**局部生效，不是全局永久开关。
- 该标的持仓归零（后续卖出量与已知量对齐、或有明确清仓证据）之后，
  后续日期的持仓恢复确定，净值恢复可得。
- 仍然不确定的期间照旧留空并给出原因——**不要为了让曲线好看而假设数量**。

## 3. 最低现金为负是柜台事实，要说明而不是当成错误

`最低现金 -165805.96（2022-11-10）` 经核对**与柜台资金余额列完全一致**：
2022-11-09 收盘余额 `1288.42`，次日买入 `-167094.38`，恰好得到 `-165805.96`。
说明当日存在交割单未记录的资金流入（下单时资金可用）。

### 要求

- 保持「采用柜台余额」的既有行为，不要改成推算值。
- 但要在诊断里说明：该负值来自柜台余额序列，
  通常意味着当日有交割单之外的资金流入未被记录，**不是账户透支**。
  否则用户会以为算错了。

## 4. 验收目标

真实账户（管理者复验，你无法自证）：

- 净值可得率**显著高于 42.2%**；`123190` 持有期（2023-04 的约两周）
  仍可以不可得，但**不得让其后三年全部失效**；
- TWR 能算出来（哪怕分段），且分段依据可见；
- 残差保持 `295.90` 量级，不因本次修改而变化。

## 5. 测试

- 中签缴款：构造「subscription 负金额 + 该标的无买入却有卖出」的账户，
  断言缴款不使持仓未知、净值在该标的清仓后恢复可得。
- 恢复语义：构造「某标的持仓一度未知 → 后续清零」的账户，
  断言清零后的日期净值可得，未知期间仍留空。
- 真正未知且未清零：断言持续留空（这条不能被顺手放宽）。
- 负现金说明：断言诊断文案存在。
- 既有用例全部继续通过。
