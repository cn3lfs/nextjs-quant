## 1. 真实文件暴露的问题（管理者已诊断，均已复现）

### 1.1 业务类型藏在「备注」列，不在「操作」列

该券商的「操作」列只有三个值：`买入`(1491) / `卖出`(1310) / `其他`(70)。
真正的业务名称在**备注**列，格式为 `[证券名]业务名，[业务代码]业务名`：

| 备注实例                                              | 真实业务       | 现状                                                |
| ----------------------------------------------------- | -------------- | --------------------------------------------------- |
| `证券买入` / `证券卖出`                               | 普通成交       | 正确                                                |
| `道氏转02证券卖出，4001证券卖出`                      | 可转债成交     | 正确                                                |
| `股息入账:运达股份300772;股东账号：***`               | 现金分红入账   | **错判**：操作列写「卖出」，被当成交后因数量 0 拒绝 |
| `300398｜股息红利扣税，4665股息红利扣税`              | 红利税扣款     | **错判**：同上，操作列写「买入」                    |
| `股息红利税差异化处理资金下账 …`                      | 红利税补扣     | **错判**                                            |
| `起始配号:8376472712.00`                              | 新股/配债配号  | **错判**：操作列写「其他」，无法归类                |
| `道氏发债,申购中签(转非流通)，4616申购中签(转非流通)` | 中签确认       | **错判**                                            |
| `新股中签资金扣款，1483新股中签资金扣款`              | 中签缴款       | **错判**                                            |
| `融券回购购回日:20260410,预计利息:0.90,…`             | 国债逆回购融出 | 归 buy/sell，可接受                                 |
| `融券购回:0.90实际占款天数：3-…`                      | 逆回购到期收回 | 同上                                                |

**要求**：把备注纳入业务判定链，**优先级高于「操作」列**
（备注更具体：`股息入账` 必须压过操作列的 `卖出`）。
逆回购那两条备注不匹配任何业务词，会自然回退到操作列的买卖，这是预期行为。
`classifyRow` 的签名可以改，但**不得删除既有的「未知不猜」语义**。

注意词表顺序陷阱：`股息红利扣税` 同时包含 `股息红利`。
**扣税必须判为 `fee`（资金流出），不能判成 `dividend`。**

### 1.2 国债逆回购不适用股票的金额核对

`204001 GC001`：**「成交数量」是张数（8 张 = 8000 元），「成交均价」是年化利率（1.37%）**。
所以 `价×量` 毫无意义；且融出资金时「发生金额」为负、到期收回为正，
与股票买卖的符号规则相反。真实文件里这产生了 **300 笔「价格×数量不符」
和 202 笔「符号矛盾」的假警报**，把真正的异常淹没了。

**要求**：`instrument === "reverseRepo"` 时**不产生**「成交金额 vs 价×量」
与「发生金额符号」这两类 anomaly。费用核对仍照常。
在 `diagnostics` 里说明本次有多少笔逆回购按此豁免——豁免必须可见，不能静默。

### 1.3 费用列漏映射且只取一列

真实表头含 `手续费`、`印花税`、`其他杂费`、`结算费`。
现状：`其他杂费` 未匹配任何别名（`otherFee` 有 `其他费` 但没有 `其他杂费`），
而 `结算费` 占走了 `otherFee`，于是 `其他杂费` 被整列丢弃。
本文件这两列恰好全为 0，但换一家券商就会**少算费用**。

**要求**：

- 别名补齐：`其他杂费`、`杂费` → `otherFee`；`后证余额` → `balanceShares`。
- **所有归入 `otherFee` 的列必须累加**，而不是第一列生效、其余进 `duplicates` 被丢。
  在 `ColumnMapping` 里显式暴露这些列（例如 `otherFeeColumns: number[]`），
  不要靠隐式行为。

### 1.4 备注里有股东账号，现有脱敏漏掉

`股息入账:运达股份300772;股东账号：0305531054`。
`redactRow` 只替换被识别为账号的**整列**，自由文本里的账号不受影响。

**要求**：`redactRow` 额外对自由文本（至少 `note` 列）做账号模式脱敏，
形如 `(股东账号|资金账号|股东代码|账号|帐号)[：:]\s*[0-9A-Za-z]+` → 标签 + `：***`。
fixture 已脱敏，你要保证**代码本身**也能脱敏。

### 1.5 纯资金流水文件（新增支持）

用户另有两份银证转账流水导出，同为 GBK + 制表符。合成样本：
`tests/fixtures/delivery/ths-bank-flow.txt`（8 行）。表头：

```
资金帐号  日期  币种代码  银行代码  变动资金  流水号  银行名称
转帐类别名称  发生时间  备注  转账类别  币种  委托时间  摘要
```

特点与现状：

- **没有价格、数量、证券代码列** → 现在直接抛「交割单缺少必要列：成交数量、成交价格」，整份文件无法导入。
- `变动资金` **恒为正数**，方向完全由 `转帐类别名称`（`银行转存` / `银行转取`）决定。
- 资金流水正是资金曲线的前提：没有它就无法重建每日现金，
  按既定口径就不能出夏普与最大回撤。所以这份文件必须能导入。

**要求**：

- 识别**两种文件形态**。判定依据要显式、可解释，不要靠猜：
  有价格/数量列 → 成交明细；无价格/数量但有金额列与业务类别列 → 纯资金流水。
  两者都不满足才报「缺少必要列」，错误信息仍要列出已识别列。
- 纯资金流水模式下**全部行进 `cashFlows`**，`fills` 必为空。
  `变动资金` 按 `转帐类别名称` 定号：`银行转存` 为正、`银行转取` 为负。
- 列别名补齐：`变动资金` → `netAmount`；`转帐类别名称`、`转账类别` → `summary`。
  `资金帐号` 已在 `account` 别名内，必须被 `redactRow` 脱敏。
- 不要为此新建第二套解析器或第二个入口函数。沿用 `importDeliveryTable`，
  以模式分支实现，并在 `diagnostics` 里说明本次按哪种形态解析。
