# 任务书 R2c：复盘需要完整历史交易日历

管理者用真实数据做浏览器验收，导入 2776 笔成交后点「查看复盘」，
页面报「交易日历未覆盖账户流水区间」，复盘无法生成。

## 1. 根因

`localCalendarReference`（`src/server/data-health.ts`）只从
`vipdoc/sh/lday/sh000001.day` **末尾读 400 根**：

```ts
const size = Math.min(before.size, 400 * 32);
```

它的用途是「最近数据健康检查」，source 也自述为
「本地上证指数最近 400 根已有交易日期（非完整官方日历）」。
400 个交易日约合 2024-09 至今，而用户账户从 **2021-01** 开始，
持有交易日数与每日净值都算不出来。

`src/server/api/root.ts` 的复盘过程（约 241–266 行）用的正是这个函数。

## 2. 要求

- **新增**读取完整交易日期序列的函数（放 `data-health.ts` 或相邻新文件均可），
  从 `sh000001.day` 读**全部**记录的日期（真实文件 279168 字节 / 8724 根，全读无压力）。
  返回 `days` / `source` / `hash`，与既有返回形状一致。
- **不要修改 `localCalendarReference` 的现有行为**——它被其他模块用于近端健康检查，
  改成全量会影响那些调用点。新增函数，各司其职。
- 沿用既有的**读取期间文件未变化**校验（`before` / `after` / `current` 三次 stat 比对），
  这是既有不变量，不得省略。
- `api/root.ts` 的复盘过程改用新函数。
- 日历仍不覆盖账户区间时，错误信息要**说清缺口**：
  日历实际覆盖的起止日期、账户流水的起止日期，而不是只说「未覆盖」。

## 3. 测试

- 用合成的 `.day` 字节构造指数文件（32 字节一条记录，参考 `tests/` 下既有
  tdx 解析测试的构造方式），断言：
  - 全量读取返回全部日期，不是只有末尾 400 条；
  - 截断/非 32 倍数长度的文件按既有语义报错；
  - 文件在读取期间被改动时报错（沿用既有校验）。
- 断言 `localCalendarReference` 的行为**未改变**（仍只返回末尾 400 根）。
- 不连生产库，不依赖用户真实文件。
