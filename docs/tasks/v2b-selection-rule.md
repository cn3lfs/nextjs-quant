# 任务书 V2b：让 PBO 检验真正在用的那条选参规则

补 [V2](v2-backtest-overfit.md) 的口径缺陷。由管理者在 V2 验收时判定，不是执行者的实现问题——
V2 任务书把 metric 默认写成夏普，执行者照做并如实指出了不等价。

## 1. 问题

`walk-forward.ts:83` 起，`walkForward` 选参用的排序是：

```
净收益 desc → 最大回撤 asc → fast asc → slow asc
```

V2 的 CSCV 在训练集上选优用的是 `sharpeDaily`。于是现在页面上那句
「选参规则在样本外不优于随机」**说的是一条本系统并不使用的规则**。

PBO 的全部意义在于检验「按训练期表现挑参数」这个**具体动作**在样本外还站不站得住。
换一个指标去挑，检验的就是另一个动作。夏普版 PBO 不是错的数，它只是在回答别的问题。

## 2. 交付

### 2.1 选参指标成为显式参数

`combinatoriallySymmetricCv` 的 `metric` 支持两种，**默认改为 `"selection"`**：

| 取值 | 含义 |
| --- | --- |
| `"selection"`（默认） | 复刻 `walkForward` 的实际排序：净收益 desc → 最大回撤 asc → fast asc → slow asc |
| `"sharpe"` | V2 现有口径，保留作对照 |

`"selection"` 的实现要求：

- 段内净收益由该候选在该段的日收益**按顺序复利**得到：`Π(1 + r) − 1`。
  这与 `backtest` 的 `totalReturn` 在同一段上等价（都是净值比值），**不要重跑 backtest**
- 段内最大回撤由同段日收益重建净值曲线后求；**基线含期初本金**
  （U1 已裁定过这条：`trade-review-nav.ts` 每段都 push 期初点，
  `daily-performance.ts:61` 的 `peak` 初值就是 1）
- fast / slow 作为并列打破项，需要候选参数，因此函数签名要能接到
  `candidates: Strategy[]`；**顺序必须与 `returns` 行一一对应**，
  错位会让并列打破打到别的候选身上，要有测试
- 样本外排名同样用所选 metric 的**主指标**（净收益）排名。
  回撤与参数只用于打破训练集的并列，不参与样本外排名——
  样本外排名需要一个全序的标量，混入回撤会让「排名」失去单一含义

### 2.2 两个 PBO 并列输出，不合成

`overfit` 下同时给 `bySelectionRule` 与 `bySharpe` 两份结果（复用同一份矩阵与组合枚举，
只换打分函数，成本几乎为零）。

**不要合成单一 PBO，也不要只留一个。** 两者差距本身是信息：
如果按净收益挑的 PBO 明显高于按夏普挑的，说明现有排序规则比夏普更容易过拟合，
那是关于 `walkForward` 本身的、可行动的发现。

### 2.3 页面

`multiple-testing-panel.tsx` 把 PBO 一行改为两行：

- 「**本系统选参规则**（净收益→回撤→参数）：PBO = x%」——**结论文案只挂在这一行**
- 「夏普口径对照：PBO = y%」——不给结论文案，只给数字

结论三档沿用 V2。`assumptions` 里 V2 那条「不等价」的说明改写为
两个口径各自的含义，不再是免责声明。

## 3. 测试（追加到 `tests/backtest-overfit.test.ts`）

- **等价锚点**：给定一段日收益，断言 `"selection"` 的段内净收益与用
  `backtest` 在同段上算出的 `totalReturn` 一致（1e-12）。
  **这条是防第二套收益口径的锚点，必须有**
- **回撤基线含本金**：构造首日即下跌的段，断言回撤从期初本金起算
  （与 U1 口径一致），注释写明为什么不是从首日收盘起算
- **排序差异可见**：构造一组候选，使「净收益最高」与「夏普最高」是不同候选，
  断言两个 PBO 不相等——证明两条路径真的分开了
- **并列打破对齐**：净收益与回撤都并列时按 fast/slow 打破；
  另一条用**故意打乱的 candidates 顺序**断言会被检出（或断言函数拒绝长度不匹配的输入）
- **样本外排名单指标**：断言样本外排名只由净收益决定，回撤不参与
- V2 既有用例全部保持通过；默认值改变导致期望值变化的用例，
  **逐条在注释里写明是默认口径变更而非算法变更**

## 4. 验收

- 默认口径是 `"selection"`，页面结论文案只挂在它上面
- 两个 PBO 并列且未合成
- 不重跑 `backtest`，不新增第二套收益/回撤实现
- 不新增依赖、不新增迁移
- `decisions.md` 记一条：为什么 PBO 必须绑定实际选参规则
- `invariants.md` 的 V2 条目补充：默认 metric 与样本外排名的单指标约束
- `pnpm typecheck` / `pnpm test` / 改动文件 prettier 通过
