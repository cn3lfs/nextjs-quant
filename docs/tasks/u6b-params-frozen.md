# 任务书 U6b：证明参数在跟踪期开始前已冻结

依赖 [U6](u6-three-segment-sample.md)（已合入）。小批，只补一个判定。

## 1. 问题

U6 的执行者在交付时如实指出了一个洞，页面上也写了：

> 不是前向成交业绩，**不证明持有期、费用、证券池等参数在上线前已冻结**

这句话是对的，而且它几乎抵消了 U6 的价值。`trackingStart` 从
`strategyVersion` 的最早前向观察推导，只能证明**信号规则**那个版本当时在跑；
持有期、入场等待、最大持仓、成本、证券池这些**研究参数**完全可以是昨天调的。
调完再看跟踪段，和调完再看保留验证期没有本质区别——
而消除这种「事后可调」正是 U6 立项的唯一理由。

好消息是这个洞可以堵上：`ResearchStore` 的 `research-task` 记录里
同时存了 `spec` 和 `createdAt`（见 `src/server/research-store.ts`）。
「这组参数在某个时间点之前就存在」是可以查证的事实。

## 2. 比较口径：只比参数，不比日期窗口

**不要拿整个 spec 做比较。** `researchSpecSchema` 里 `start` / `end` /
`validationStart` 是日期窗口，随着时间推移自然会变——
今天把 `end` 往后延一天再跑一次，整个 spec 就不同了，
但持有期、成本这些真正的调参旋钮一个都没动。
按整个 spec 比会让冻结判定几乎永远为假，那等于没做。

要比的是**参数指纹**：spec 去掉 `start` / `end` / `validationStart` 之后的稳定哈希。
其余字段全部参与（`strategy`、`symbols`、`czscConfig`、`pool`、`holdingDays`、
`entryMaxWait`、`initialCapital`、`maxPositions`、`costs`、`annualRiskFreeRate`）。

哈希要对**键序不敏感**（同样的参数不同键序必须同指纹），
并且对 `costs` 这类嵌套对象递归稳定。用现有手段实现，不新增依赖。

## 3. 交付

### 3.1 `paramsFrozenAt`

新增查询：在 `kind='research-task'` 记录中，找出参数指纹与当前结果相同的记录里
**最早的 `createdAt`**。

注意 `research-store.ts:80` 现有的列表查询带 `LIMIT 100`，
**不要复用它**——最早的那条任务很可能不在最近 100 条里。
写一条针对性的查询，不要为了省事把判定建立在一个会漏的窗口上。

### 3.2 判定与三种状态

第三段结果增加 `paramsFrozenBeforeTracking: boolean | null`：

| 值      | 条件                                             | 页面措辞                                                     |
| ------- | ------------------------------------------------ | ------------------------------------------------------------ |
| `true`  | `paramsFrozenAt` 存在且 **早于** `trackingStart` | 「参数在跟踪期开始前已存在（最早记录 YYYY-MM-DD）」          |
| `false` | `paramsFrozenAt` 存在但不早于 `trackingStart`    | 「参数最早记录 YYYY-MM-DD 晚于跟踪起点，本段不是参数外样本」 |
| `null`  | 查不到同指纹任务                                 | 「无法确认参数冻结时间」                                     |

**`false` 和 `null` 都必须保留 U6 现有的那句免责**，
只有 `true` 才能去掉「不证明参数已冻结」这半句——
但「不是前向成交业绩、收益仍为模拟」那半句**任何情况下都不能去掉**，
因为跟踪段的收益始终来自 E3 模拟，不是真实成交。

### 3.3 预期结果可能大多是 `false` / `null`，这是对的

如果日常习惯是每次研究都新建一份参数，那冻结判定会经常不成立。
**这不是缺陷，是这个功能的作用**：它如实告诉你当前工作流产不出
参数外样本的跟踪段。不要为了让判定好看而放宽比较口径。

## 4. 测试

补进 `tests/three-segment-sample.test.ts`：

- **指纹稳定性**：仅 `start`/`end`/`validationStart` 不同的两份 spec 必须同指纹；
  改 `holdingDays` 或 `costs` 里任一字段必须换指纹；键序不同必须同指纹。
- **三种状态**各一个用例，断言页面措辞对应正确。
- **不走 LIMIT 100**：构造超过 100 条 `research-task` 记录、
  且最早的同指纹任务排在最后，断言仍能查到它。这条是本批的关键护栏。
- `true` 时免责文案只去掉参数那半句，**「收益仍为模拟」必须还在**。

## 5. 验收

- 参数指纹排除日期窗口，其余字段全参与，键序无关。
- 冻结查询不受 `LIMIT 100` 影响，有对应测试。
- 三种状态措辞正确；`false`/`null` 保留完整免责。
- **任何情况下页面都不声称跟踪段是真实成交业绩。**
- 不新增迁移、不新增依赖。现有 U6 行为在冻结不可判定时保持不变。
- `pnpm typecheck` / `pnpm test` / `pnpm format:check` 通过。
