# 任务书 W7：双突破历史信号的信息含量

W 系列。目的：**第一次把 V3 的尺子用在真实信号上**，回答一个从未被回答的问题——
现有的双突破评分到底有没有信息。

## 1. 背景与边界

- 信号台账（`signal_ledger`）**至今 0 条**：`runSignalLedger` 要求「交易日 15:05 之后」，
  应用从未在那个时点运行过。所以 V3 交付至今没有任何数据可量
- `invariants` 明确**台账不做历史回放**。因此本批**绝不写入 `signal_ledger` 相关表**，
  只产出一次性的研究报告
- 这是**回溯研究**：信号规则、参数、阈值都是今天的版本，存在事后视角。
  **产出的任何结论都必须带这条限定**，不能与前向台账的结果混为一谈

## 2. 交付

### 2.1 回溯信号生成

对给定证券池与区间，用**现有** `breakout.ts` / `breakout-batch.ts` 逐交易日判定，
收集每个「标的 × 日期」的信号：方向、评分（x/5）、结构依据。

**不要新写一套判定逻辑**——本批的价值在于检验现有实现，另写一套就什么都没检验到。

### 2.2 前向收益

复用 `signal-ledger.ts` 的 `ledgerOutcome` 口径计算 T+5/10/20：
次日开盘进、第 N 个交易日收盘出，除权区间标记不可比，停牌不顺延。
**不要另写一套收益计算。**

### 2.3 信息含量

把上述结果喂给 V3 的 `signalInformation`（`src/lib/signal-information.ts`），
产出 RankIC / ICIR / t 值、评分分层、持有期衰减，按 `strategy × direction × horizon` 分组。

**红线照旧**：空头信号的 `returnPct` 绝不取反。

### 2.4 规模控制

**先做可行性评估再跑全量**：在报告里给出单只标的单年的实测耗时，
据此推算证券池规模与区间的上限。

默认规模：**中证 A500 成分 × 最近 3 年**。若实测耗时不可接受，
按「先缩区间、再缩池子」的顺序降级，并在报告里说明实际用了什么规模。
**不要为了跑得快而跳过任何标的且不记录。**

### 2.5 生存者偏差必须同时输出

调用 V4 的 `universe-audit` 对同一池子同一区间做审计，
把「区间起点未上市」「区间内退市（下界）」「无证据」的计数与信息含量结果**放在一起**。

A500 用的是当前成分，**结果必然带生存者偏差**，不能只报 IC 不报这个。

### 2.6 记账

经 V5 的 `recordResearchUsage` 记一条，`kind` 用 `sample-research`，
`candidateCount` 为实际评估的「标的 × 时点」组合数的合理代理（在报告里说明怎么算的）。

## 3. 产出形式

一份 JSON + 一份 Markdown 报告写到**仓库外**或 `.test-data/`（不进版本库），
路径在最终报告里说明。**不要新建页面**——本批是一次性研究，不是常驻功能。

报告必须包含：

- 实际规模（标的数、交易日数、信号数）与耗时
- IC 汇总表、分层表、衰减三点表
- V4 池审计结果
- 排除计数（未结算、除权不可比、停牌、重复）
- 固定限定：**「回溯研究，信号规则与参数为当前版本，存在事后视角；
  非前向台账结果，不构成可交易结论」**

## 4. 测试

本批以研究为主，但以下必须有测试：

- **回溯生成与现有实现一致**：同一标的同一日期，回溯路径产出的信号
  与直接调用 `breakout` 的结果**逐字段相等**
- **前向收益口径一致**：与 `ledgerOutcome` 在同一输入上结果相等
- **不写台账**：断言运行后 `signal_ledger` 相关表零新增
- 现有测试全部保持通过

## 5. 验收

- 没有第二套信号判定或收益计算实现
- 报告含实际规模、耗时、池审计与固定限定
- 不写 `signal_ledger`
- 不新增依赖、不新增迁移、不新建页面
- `pnpm typecheck` / `pnpm test` / 改动文件 prettier 通过

## 6. 最重要的一条

**如果结果显示评分没有信息（IC 接近 0、分层不单调），如实报告。**
这批的价值在于"知道"，不在于"证明有效"。
一个诚实的否定结论，比一个勉强凑出来的正向结论有用得多——
前者能让我们停止在这个方向上投入。
