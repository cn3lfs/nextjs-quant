# 任务书 R2d：日历提取只校验日期，不做行情校验

承接 R2c。管理者用真实通达信目录（`E:/new_tdx64`）做浏览器验收，
全量读取上证指数日线时报错：

```
完整交易日期参考读取失败：行情记录非法：1991-05-09
```

## 1. 根因

新函数复用了 `parseBars`，而 `parseBars` 会对 OHLC 做严格校验
（拒绝非法价格、非法时序等）。上证指数 **1991 年的早期记录不符合这些校验**——
这是真实历史数据的固有状况，不是文件损坏。

但**交易日历只需要日期**：某天有没有指数记录，与那天的 OHLC 是否合规无关。
拿行情校验去卡日历，等于让 1991 年的脏数据阻断整个复盘。

## 2. 要求

- 全量日历提取**只解析日期字段并校验日期本身**（32 字节记录的日期字段，
  合法公历日期、严格递增、无重复）。**不要**对 OHLC 做校验，
  也**不要**因为 OHLC 异常就丢弃该日期。
- 仍要拒绝**真正损坏**的文件：长度非 32 倍数、日期非法、日期倒序或重复、短读、
  读取期间文件变化（三次 stat 校验保留）。
- **不要修改 `parseBars`**——它服务于行情解析，严格校验是既有不变量。
  也**不要修改 `localCalendarReference`**。
- 返回值里带上实际覆盖范围（最早、最晚日期与条数），
  便于错误信息说清缺口，也便于页面展示日历来源。

## 3. 测试

- 构造一个包含「日期合法但 OHLC 异常」记录的合成 `.day` 字节，
  断言该日期**仍被纳入日历**（这正是真实文件 1991 年的情形）。
- 构造日期倒序、重复、非法日期、长度非 32 倍数的字节，断言各自报错。
- 断言 `parseBars` 与 `localCalendarReference` 行为未变。
