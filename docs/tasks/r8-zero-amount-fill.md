# 任务书 R8：金额为 0 的「成交」不是市场成交

R7 修好了持仓未知的传播，但真实账户净值可得率几乎没变（42.2% → 42.3%），
断点原因换成了：

```
2023-04-12：370409 缺少有效唯一收盘价
```

## 1. 根因

交割单（`jiaoge.xls`）里这一行被当成了买入成交：

```
370409  道氏发债  买入  数量 10  价格 100  成交金额 0  发生金额 0
```

它实际是**可转债中签确认**——成交明细（`lishichengjiao.xls`）里同一笔的备注写着
`道氏发债,申购中签(转非流通)，4616申购中签(转非流通)`，
解析器据此正确归为 `subscription`。

但**交割单没有备注列**，只有「操作」列写着「买入」，于是被判为真实成交，
引擎认为账户持有 10 股 `370409`。而 `370409` 是**申购代码**、没有日线，
市值永远算不出来，净值从此断裂。库内两种记录并存（交割单的 fill +
成交明细的 cashFlow），指纹不同故不会互相去重。

## 2. 判据

**真实市场成交不可能成交金额为 0。** 价格与数量都为正、成交金额却是 0，
本身就是自相矛盾——这类行是中签确认、非交易过户等**非市场成交事件**。

## 3. 要求

- 价格 > 0、数量 > 0，但**成交金额与发生金额均为 0** 的行，
  **不得归为 `buy` / `sell` 成交**。
- 归类要遵循既有原则：
  - 备注/摘要能判定业务类型的（如「中签」「转非流通」），按该类型归入现金流；
  - **判定不出来的进 `unresolved`**，写清原因（例如「价量为正但成交金额为 0，
    不是市场成交」），保留原始行。**不要猜成某种业务，也不要丢弃。**
- 只在**三者同时满足**时生效（价>0、量>0、金额与发生额均为 0）。
  金额为 0 但数量也为 0 的行（分红、配号）走既有路径，不要改动。
  真实成交里存在的其他零值组合不得被误伤。
- 不要为此去猜「申购代码 → 上市代码」的映射。

## 4. 验收目标（管理者用真实账户复验，你无法自证）

- `370409` 不再计入持仓；
- 净值可得率**显著高于 42.3%**；
- 残差保持 `295.90` 量级不变。

## 5. 测试

- 构造「价 100 / 量 10 / 成交金额 0 / 发生金额 0 / 备注含中签」的行 →
  归入现金流，不进 fills。
- 同样的价量金额、但**没有备注**（模拟交割单形态）→ 进 `unresolved`，
  原因可读，不进 fills。
- 分红行（量 0、金额非 0）与配号行（量非 0、金额 0、备注含配号）
  行为**保持不变**——用既有 fixture 断言不回归。
- 正常成交不受影响。
- 既有用例全部继续通过。
