# 任务书 U9：关键交易

依赖既有 R 系列回合配对。排期第 4 位，**低成本批次**，不要做大。

来源：[wbt](https://github.com/zengbin93/wbt) `src/core/key_trades.rs`。

## 1. 问题

真实账户 785 个回合，全期净收益是一个数。但「这一年是靠哪几笔赚的、
被哪几笔拖垮的」现在只能自己翻分页表找。

这批的价值边界要说清楚：它**不产生新判断**，只是把已有回合按年排出头尾。
排期里它在 U6/U10/U11 之后正是因为这个——先做能改变判断的，再做换角度看的。
所以**不要给它加分析、加评级、加归因**，就是排序和取头尾。

## 2. 交付

新建 `src/lib/key-trades.ts`（纯函数）。

### 2.1 先核实：现有回合是否已经去重

wbt 要按 `(symbol, 开仓时间, 平仓时间)` 聚合去重，因为它的引擎按 LIFO 撮合，
一次平仓会命中多个 lot、产出多条共享同一开平时间的部分成交记录。

**我们的 `ReviewRound` 是 R 系列配对出来的，是否已经合并了部分成交，先看代码确认。**

- 已经是一回合一行 → **不要再加一层聚合**，直接用
- 仍会出现多行共享同一 `(security, openingDate, closingDate)` → 按该键聚合，
  `netProfit` 求和、`quantity` 求和、`netReturn` 按 `quantity` 加权、
  `holdingTradingDays` 取值**不求和**（同组共享），并记 `mergedCount`

结论写进 `decisions.md`，不要凭 wbt 的描述假设我们也有同样的问题。

### 2.2 分年头尾

- **分年依据是平仓年份**（`closingDate` 的年份），不是开仓年份。
  未平仓回合（`closingDate` 为 `null`）**不参与**，单独计数并显示。
- 每年取 `netProfit` 最高的 N 笔与最低的 N 笔，N 默认 3、可配。
- 同时给两个口径：按 **`netProfit` 绝对金额**、按 **`netReturn` 百分比**。
  一笔小仓位翻倍和一笔大仓位赚 5% 是完全不同的事，只给一个口径会误导。
  两个榜分开展示，各自标明排序依据。
- `netProfit` 或 `netReturn` 为 `null` 的回合不进榜，单独计数 + 原因。

### 2.3 展示

`/trade-review` 新增「关键交易」区块：按年折叠（沿用 R13 的 `ui/collapsible`），
每年内两个小表（金额榜 / 收益率榜）。

年数有限（真实账户 5 年），**这批不需要服务端分页**——
但每年的榜单固定只有 2N 行，不会膨胀。若实现时发现行数可能失控，改为分页。

## 3. 测试

`tests/key-trades.test.ts`：

- **分年依据**：跨年持仓（开仓在 A 年、平仓在 B 年）必须归入 **B 年**。
- **两个口径不同序**：构造「小仓位高收益率」与「大仓位低收益率」各一笔，
  断言两个榜的第一名不是同一笔。这条是 §2.2「只给一个口径会误导」的证明。
- **未平仓与缺失**：`closingDate` 为 `null`、`netProfit` 为 `null` 的回合
  都不进榜且分别计数。
- **不足 N 笔**：某年只有 1 笔盈利时，榜单返回 1 行而不是补空行。
- 若 §2.1 判定需要聚合，补一条聚合正确性用例（加权收益率、
  `holdingTradingDays` 不求和）。

## 4. 验收

- §2.1 的核实结论写进 `decisions.md`，且实现与结论一致。
- 分年按平仓年份，跨年用例通过。
- 两个排序口径都在，且有测试证明它们会给出不同结果。
- 未平仓/缺失不进榜、单独计数。
- 不新增迁移、不新增依赖。
- `pnpm typecheck` / `pnpm test` / `pnpm format:check` 通过。

## 5. 明确不做

- 不做归因、不做评级、不推断「为什么这笔赚了」。
- 不改既有回合配对逻辑。
