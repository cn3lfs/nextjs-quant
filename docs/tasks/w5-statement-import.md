# 任务书 W5：对账单格式导入

W 系列第 5 批。依据：[对账单核验](../review/w5-statement-source-2026-09-13.md)（先读它）。

## 1. 目标与范围

把 `duizhang20-26.xls` 这类**对账单**接进现有导入链路，**只取其中的资金流水**，
成交仍以历史成交明细（`lishi`）为准。

这么分工的理由在核验记录 §3：两个来源对逆回购的记法完全不同
（`lishi` 记「卖出 + 年化利率 6.355」，对账单记「买入 + 面值 100」），
**指纹不同 → 现有去重认不出是同一笔 → 若两边都取成交会重复计入 232 笔逆回购**。
这是本批最大的风险，必须从设计上排除，不能靠去重兜底。

## 2. 交付

### 2.1 形态识别

对账单的特征：同时具备「摘要」列与「资金余额」列，且「操作」列取值含 `其他`。
识别后走新的解析分支，**不要复用"成交明细形态"的判定**——
现有实现把它判成成交明细，导致 210 行无法解析。

### 2.2 导入范围选项

`importOptionsSchema` 增加 `scope?: "all" | "cashFlowsOnly"`，默认 `"all"`（现状不变）。
对账单导入时由调用方传 `"cashFlowsOnly"`：**只落现金流，成交一律丢弃并计数**。

**不要试图自动判断该取哪部分**——那是数据源治理决策，属于调用方。

### 2.3 业务类型识别（从「摘要」列）

| 摘要特征 | 归类 | 说明 |
| --- | --- | --- |
| 含「银行转存」 | `transferIn` | 60 条 |
| 含「银行转取」 | `transferOut` | 27 条 |
| 含「结息」或「利息结转」 | **利息** | 8 + 17 条，**其他来源都没有** |
| 含「股息入账」「红利到账」 | `dividend` | |
| 含「股息红利扣税」 | 扣税（负向） | |
| 含「新股中签资金扣款」 | `subscription` | |
| 含「银行返回码」且结果为失败 | **排除并计数** | 7 条，不计入现金流 |
| 其余无法归类 | **留在 unresolved 并计数** | 不猜 |

利息若现有 `cashFlows` 的 kind 枚举没有对应值，**新增一个**而不是塞进 `neutral`——
利息是真实收益来源，混进中性项会让它在收益归因里消失。

### 2.4 带符号的数量

对账单卖出数量为负（−300、−800）。解析时：

- 用绝对值作为数量，方向由「操作」列决定
- **符号与操作列必须一致**（卖出为负、买入为正）；不一致的行**拒绝并计数**，不猜
- 本批 `cashFlowsOnly` 下成交会被丢弃，但这条规则仍要实现并测试，
  为将来支持成交导入留出正确基础

### 2.5 期初资金确证

对账单按时间正序的**首条记录**，若「发生金额」与「资金余额」相等，
则期初资金 = 0；更一般地 `期初 = 首条资金余额 − 首条发生金额`。

输出为导入批次的 `statementOpeningCash`，供调用方使用。
**不要自动改写任何既有的 openingCash 输入**——只提供事实，由调用方决定是否采用。

## 3. 测试

- **形态识别**：对账单样本走新分支；现有三种形态的样本判定结果不变
- **cashFlowsOnly**：断言成交被丢弃且计数，现金流全部落库
- **利息独立成类**：断言利息不被归入 `neutral`，且能在汇总中单独取出
- **失败流水**：「银行返回码…失败」不进现金流，计入排除数
- **符号一致性**：卖出为正、买入为负的行各一条 → 拒绝并计数
- **期初资金**：构造首条「发生 +10000 / 余额 10000」→ 断言 `statementOpeningCash = 0`；
  另构造「发生 +5000 / 余额 8000」→ 断言 = 3000
- **无法归类**：构造一条摘要无法匹配的行 → 留在 unresolved，**断言没有被猜成某一类**
- 现有导入测试全部保持通过

## 4. 验收

- 默认 `scope: "all"` 行为零变化
- 对账单在 `cashFlowsOnly` 下零未解析（或未解析项全部有明确原因与计数）
- 利息为独立类别
- 不新增依赖、不新增迁移（现金流表若缺字段，先报告再定）
- `decisions.md` 记一条：为什么成交与资金流水分属不同权威来源
- `pnpm typecheck` / `pnpm test` / 改动文件 prettier 通过

## 6. 管理者裁定（2026-09-13，回应执行者的停止报告）

执行者按"不成立就停"拒绝实现，**两条指控全部成立，都是管理者核验记录写错**。

### 裁定一：7 条「银行返回码」是成功转账，不是失败

逐条核实：返回码全是 `000000000000`、返回信息「交易成功」、摘要含「转账成功」，
发生金额非零（+10000、+30000、−17258.55、−130428.07、−30000 等）。

**按发生金额符号定方向**：正 → `transferIn`，负 → `transferOut`。
核验记录里「银行返回码（失败）7」是我按关键词猜的，**作废**。

### 裁定二：结息成对出现，只计余额实际变化的那条

每次结息有**两行**：同批次号、同金额、余额不同。例：

```
2026-06-18  发生 0.08  余额 0        ← 计算/结算，余额未变
2026-06-18  发生 0.08  余额 0.08     ← 实际入账，余额 = 前行余额 + 金额
```

**只取后者**（满足「余额 = 前一条余额 + 发生金额」的那条），否则利息翻倍。
判定用这个恒等式，不要靠摘要里的「结算 / 归本」字样——不同柜台措辞可能不同。

### 裁定三：「融券回购购回日」类记录是逆回购成交，不是利息现金流

那 17 条摘要形如 `"融券回购购回日:20260410,预计利息:0.90,..."`，
操作列是**卖出**、发生金额是负的大额（−8000.08、−17000.17），
**这是逆回购融出资金的成交记录**，只是摘要里提到了预计利息。

核验记录把它们算进「利息结转 17 条」是错的，**作废**。
`cashFlowsOnly` 下它们属于成交，应被丢弃并计数。

### 裁定四：一个必须同步更正的结论

按上述，真正的利息收入只有 **4 笔、合计约 0.82 元**。

**因此利息不可能是那 12.6 万余额残差的来源**——
[核验记录](../review/w5-statement-source-2026-09-13.md) §2 里「它们很可能就是
56 条柜台余额残差的一部分来源」这个推测**不成立**，一并作废。

残差的真实来源仍未知。**但本批不去追它**：对账单带 2759 个资金余额锚点，
W5 交付后可以逐日核对定位差异日，那是下一批的事。
