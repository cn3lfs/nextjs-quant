# 任务书 U1：统一日收益指标核

## 0. 口径来源（2026-09-12 更正）

**权威来源是 [wbt](https://github.com/zengbin93/wbt)（MIT，v0.9.1，commit `39bb1e8`），
不是 czsc 也不是 czscflow。**

链路已核实：`waditu/czsc` 现已 Rust 化，其 `pyproject.toml` 把
`daily_performance` / `top_drawdowns` / `WeightBacktest` 全部改为从**硬依赖 `wbt`** 导入
（`czsc/__init__.py:24`），czsc 自身的 crates 里已无这些实现；
czscflow 调用的私有 submodule `rs_czsc` 是同一引擎的另一分发。
**wbt 仓库是公开的、有完整 Rust 源码和手算验收表**，直接读它。

以下两处初稿引用 czsc Python `v0.9.69-a` 的口径**已被 wbt 明确修正，不要照抄旧版**：

1. **新高间隔**：老版 `Counter(np.maximum.accumulate(cum)).most_common(1)` 是缺陷，
   wbt 源码注释直接称其为「czsc 漏洞」。正确定义见 §2.3。
2. **回撤基线**：wbt D01/SKZ-724 把 running peak 改为 `max(0, cum)`，
   **t=0 的本金也是峰值**，首日亏损即计入回撤。见 §2.6。

另需知悉：wbt 在 v0.5.0（SKZ-195）**主动把全框架从复利改成单利** `Σr`，
理由是与绝对收益、净值曲线口径统一。这不影响我们的选择——
我们的复盘基于真实账户 TWR，必须复利——但它解释了为什么 wbt 的
最大回撤是**收益空间的绝对值**而非比例，两者数值不可直接比对。

U1 是 U2 / U3 / U4 / U8 的公共依赖，**必须先落地**。

## 0.1 年化天数必须是参数，不得内联

用户 2026-09-12 明确方向：**当前只做 A 股，后续要做 BTC、黄金白银、外汇**。
本批**不建任何多市场机制**，但有一处内联会让以后很贵，现在顺手避开：

A 股 252 交易日/年，BTC 是 365。czscflow 的 `calculate_statistics` 里
就留着一行 `// TODO BTC 不应该是 252天`——这个坑别人已经踩过了。

要求：

- 实现里**禁止出现内联的 `252` 或 `Math.sqrt(252)`**，一律走
  §2.1 的 `yearlyDays` 参数，默认 252。
- 结果对象里**回显 `yearlyDays`**——沿用 `strategy-research.ts:161`
  与 `trade-review-nav.ts:647` 已有的 `annualization: 252` 做法，
  这两处已经把它当显式契约字段，不是藏起来的常量。
- **不做**从日期序列自动推断（wbt 有 `cal_yearly_days.rs` 干这个）。
  现在只保证「换市场是改一个入参」，不预建推断逻辑。

其余 A 股特有语义（T+1、涨跌停、逆回购、转债面值）本批不涉及，
遇到时继续走 `delivery-import.ts` 已有的 `InstrumentKind` 隔离，
不要写进通用计算路径。

## 1. 问题

我们现在的净值指标只有 6 项，散落在 `trade-review-nav.ts` 的 `statistics()` 里：
`totalReturn` / `maxDrawdown` / `sharpe` / `sortino` / `annualReturn` / `calmar`。

wbt 把 17 项指标收敛成**一个计算核**（`src/core/daily_performance.rs`），
再复用到回测总览、多空拆分、分段统计、滚动指标、年度收益、策略准入判定——
所有场景同一口径，天然可比。这正是 `invariants.md §1「指标只有一个实现入口」`
的要求，而我们只在净值这一处做到了，且指标不全。

缺的里面有 4 项真正有用：

- **日赢面** —— 一个数判断是否有正期望，比单看胜率或盈亏比都可靠
- **盈亏平衡点** —— 衡量「业绩是不是靠少数几天撑起来的」
- **新高间隔** —— 最长连续水下天数，比最大回撤更贴近持有体验
- **回归年度回报率** —— 对累计收益序列做 OLS 取斜率再年化，
  衡量净值曲线「有多直」。两条年化相同的曲线，一条稳步上行、
  一条靠单月暴涨，这个指标能区分开，最大回撤不能

## 2. 交付

新建 `src/lib/daily-performance.ts`（纯函数，无 IO，符合 `conventions.md §3`）。

### 2.1 签名

```ts
export const performanceBases = ["compound", "simple"] as const;
export type PerformanceBasis = (typeof performanceBases)[number];

export type DailyPerformanceInput = {
  /** 按日期升序。null = 当日收益不可得，不参与计算，计入 coverage。 */
  returns: readonly (number | null)[];
  basis?: PerformanceBasis; // 默认 "compound"
  yearlyDays?: number; // 默认 252
  annualRiskFreeRate?: number; // 默认 0.02，与 reviewTradeNav 一致
};
```

返回全部 17 项，**每项都是 `ReviewValue`**（`{ value, reason }`，
复用 `src/lib/trade-review.ts` 已有类型），外加 `coverage` 元信息：
观察日数、可得日数、null 日数、零收益日数。

### 2.2 两套口径

用户已定：**复利为主，单利仅作对照**。

|          | `compound`（默认）      | `simple`（对照）              |
| -------- | ----------------------- | ----------------------------- |
| 累计     | `∏(1+r) − 1`            | `Σr`                          |
| 净值序列 | 累乘                    | 累加                          |
| 最大回撤 | `1 − v/peak`，**比例**  | `max(peak − cum)`，**绝对值** |
| 年化     | `(1+total)^(252/n) − 1` | `Σr / n × 252`                |

**两套口径的最大回撤和年化数值不可比**，返回结果里必须带上 `basis` 字段，
页面展示时必须标明。`simple` 只用于跟 czsc / czscflow 的输出做交叉验证，
不进入任何业务判断。

### 2.3 17 项定义

以下为 wbt `src/core/daily_performance.rs` 原文口径。
`r` = 日收益序列（已剔除 null），`n = r.length`，`cum[i] = Σr[0..=i]`。

| 指标             | 定义                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| 绝对收益         | 见 §2.2 累计                                                                                                |
| 年化             | 见 §2.2                                                                                                     |
| 夏普             | `mean(r − rf) / std(r) × √252`                                                                              |
| 最大回撤         | 见 §2.2 与 §2.6                                                                                             |
| 卡玛             | `年化 / 最大回撤`                                                                                           |
| 日胜率           | `count(r >= 0) / n`                                                                                         |
| 日盈亏比         | `mean(r[r >= 0]) / abs(mean(r[r < 0]))`                                                                     |
| 日赢面           | `日胜率 × 日盈亏比 − (1 − 日胜率)`                                                                          |
| 年化波动率       | `std(r) × √252`，**总体标准差 ddof=0**                                                                      |
| 下行波动率       | `std(r[r < 0]) × √252`，分母是**负收益个数**，总体口径                                                      |
| 非零覆盖         | `count(r != 0) / n`                                                                                         |
| 盈亏平衡点       | 升序排序后取累计和，返回首次 **严格 > 0** 的位置 `(idx + 1) / n`；始终不为正时取 `1.0`                      |
| 新高间隔         | **最长连续严格水下 bar 数**（`cum < running_max` 的最长连续段）。创新高当日和起始 bar 都不计入              |
| 新高占比         | `count(cum >= running_max) / n`，**含持平前高的日子**                                                       |
| 回撤风险         | `最大回撤 / 年化波动率`（用**未舍入**的波动率相除，再舍入结果）。1 以下低风险，1–2 中，2 以上高             |
| 回归年度回报率   | 对 `cum` 序列以 `i` 为自变量做 OLS，取斜率 × 252。`n < 2` 时为 `null`                                       |
| 长度调整平均回撤 | 迭代剥离 Top-5 回撤，累加每段 `peak → valley` 的 bar 数，`总和 / 5 / 252`。衡量「平均而言一年有多久在水下」 |

**新高间隔的定义已更正。** 初稿写的
「running max 中出现次数最多的值的出现次数」来自 czsc Python 老版，
wbt 源码注释明确称其为漏洞并改为「只数水下天数本身」。
按上表实现，**不要实现成 `Counter().most_common()`**。

**注意日胜率用 `>= 0`**（零收益算胜），这是 wbt 的口径，
与我们 E3 的「零收益单列」不同。U1 按 wbt 口径实现，
但**必须额外返回一个 `零收益日数`**，让页面能自行区分。

**夏普的无风险利率是我们的扩展。** wbt 的 `sharpe = mean / std × √252`，
`rf = 0`。我们沿用 `reviewTradeNav` 已有的 `annualRiskFreeRate`（默认 0.02），
所以两边夏普数值不同。这条差异写进 `invariants.md`，
`simple` 口径的交叉验证测试里必须把 `rf` 显式设为 0 才能对上。

### 2.4 四条不照抄

wbt 已经修掉了老版 czsc 最严重的 0 填充问题——它的
`docs/daily_performance_degenerate.md` 明确写「累计收益为零不代表没有波动或回撤」，
现在**只有空输入和真·全零输入**才返回默认值。但为了保持数值 API 契约，
它仍然用「约定值」顶替无定义的量。这几条我们不跟：

1. **不用 0 顶替无定义。** wbt 在 `std < f64::EPSILON` 时约定夏普 = 0、
   回撤风险 = 0——它自己的文档都要专门写一句「此时比率 0 不表示没有回撤」。
   我们一律返回 `{ value: null, reason: "..." }`，reason 写清具体原因。
2. **不做 clamp。** wbt 把夏普夹到 `[-5, 10]`、卡玛夹到 `[-10, 20]`。
   我们保留真值；异常值是信息，不是要藏起来的东西。
3. **无回撤时卡玛不填 ±10。** wbt 取 `10 × sign(年化)`。
   我们返回 `null` + 「最大回撤为零，卡玛无定义」。
4. **无亏损日时日盈亏比不填 5。** wbt 硬编码 5.0，还会连累日赢面
   （手算表里 `[0.01, 0.01, 0.01]` 的日赢面是 **5**，一个没有意义的数）。
   我们返回 `null` + 「无亏损日，盈亏比不可估」，日赢面随之 `null`。
   这与 E3 已定的「无亏损时不可估，不填无穷」一致。

**不做 4 位小数舍入。** wbt 每一项都 `round_to_4_digit()`，
那是为了展示稳定。我们在数据层保留全精度，舍入交给展示层——
否则 §2.5 的护栏测试会因为舍入而对不上。

### 2.5 接入 `trade-review-nav.ts`

`statistics()` 改为调用新核，返回类型**扩展**而非替换——
现有 6 项字段名与语义一字不改，R4–R13 的验收结论不能被推翻。

**护栏测试（必须有）**：用真实账户 fixture 跑一遍，
断言新核在 `compound` 口径下算出的
`totalReturn` / `maxDrawdown` / `sharpe` / `sortino` / `annualReturn` / `calmar`
与改造前 `statistics()` 的输出**逐项相等**。
不相等就是回归，不是「新算法更好」。

`sortino` 保留现有的下偏二阶矩口径（分母是**全部**日收益数，不只是亏损日），
不要换成 wbt 的「下行波动率」（分母是**负收益个数**）——
两者不是一回事，都保留，各叫各的名。

### 2.6 回撤基线含 t=0 本金

wbt D01/SKZ-724：running peak 的初值是 **0（初始本金），不是首个观测值**。
所以 `[-1%]` 单日序列的最大回撤是 1%，`[-1%, -1%, -1%]` 是 3%。

我们现有 `trade-review-nav.ts` 的 `drawdowns()` 从 `points[0]` 起算，
即**首日亏损不计入回撤**——这是两种口径分歧。

**本批不改现有行为**：R4–R13 的 30.16% 是在旧基线下验收的，
改基线会推翻既有结论。做法是新核**同时返回两个值**：

- `maxDrawdown` —— 沿用现有基线（首个观测值起算），保证 §2.5 护栏通过
- `maxDrawdownFromCapital` —— wbt 基线（含 t=0 本金）

两者差异只在「账户第一天就亏」时出现。页面默认展示前者，
`invariants.md` 记录两个口径的定义与适用场景，由管理者后续决定是否切换。

## 3. 测试

`tests/daily-performance.test.ts`：

- 手算 fixture，注释里写出算式（`conventions.md §6`），用计算器可复核。
  至少覆盖：全正、全负、含零、单日、两日、含 null。
- **wbt 交叉验证（现成的验收表，直接抄）**：
  wbt `docs/daily_performance_degenerate.md` 给了一张 4 列手算表，
  覆盖 `[0.10, -0.10]` / `[0.01, 0.01, 0.01]` / `[-0.01, -0.01, -0.01]` / `[0, 0, 0]`，
  17 项逐个给了期望值。在 `simple` 口径 + `rf = 0` 下逐项比对，
  数值写死在测试里。
  几个必须对上的锚点：`[0.10, -0.10]` 的最大回撤 = 0.10、新高间隔 = 1、
  回归年度回报率 = -25.2；`[-0.01, -0.01, -0.01]` 的最大回撤 = 0.03（含本金基线）、
  新高间隔 = 3、新高占比 = 0。
  **凡是我们按 §2.4 改成 `null` 的项**（该表里填 0 或 5 的那些）
  断言 `null` + reason，并在注释里写明「wbt 此处填 X，我们按 §2.4 留空」。
- 边界：空序列、全 null、全零、std 为零、无亏损日、
  盈亏平衡点始终不为正时取 1.0、`n < 2` 时回归年度回报率为 `null`。
- §2.6 双回撤：`[-0.01]` 在 `maxDrawdownFromCapital` 下为 0.01、
  在 `maxDrawdown` 下为 0。
- 护栏：§2.5 的真实账户逐项相等断言。
