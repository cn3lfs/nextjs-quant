# 任务书 W11：执行损耗的可用口径

依据：管理者在 W10 之后的诊断（本文 §1）。

## 1. 诊断结果：守卫没坏，是口径不适用

`executionQuality` 的执行损耗长期留空，原因是
`boundaries(actual) !== boundaries(counterfactual)`。W10 修好现金曲线后**仍然留空**。

实测诊断（真实账户，`flowValuation: "previousClose"`）：

```
分段数  实际 185 / 反事实 517
逐日差异 332 天，典型：
  2022-05-11  实际有收益  反事实无（期初净值非正 −4,537.86）
  2024-07-23  实际有收益  反事实无（期初净值非正 −23,305.29）
```

**反事实的净值变成了负数。** 原因是反事实把成交价全换成当日 VWAP，
而实际成交价平均优于 VWAP 约 33.88 BP——按 VWAP 成交要多花钱，
账户现金本就薄（最低 −9,007.25），于是透支。

**这不是缺陷，是真实结果**：若当初都按 VWAP 成交，这个账户周转不过来。
但它说明**分段 TWR 这个口径在薄资金账户上不可用**——
反事实一旦透支，分段边界必然与实际不同。

## 2. 交付

### 2.1 保留现有口径，增加降级口径

- 边界一致时：**沿用现有分段 TWR 对比**，行为一行不改
- 边界不一致时：不再只返回 null，改为给出**降级口径**并明确标注：
  - `terminalDifference`：实际期末总资产 − 反事实期末总资产（绝对金额）
  - 标注「分段 TWR 不可用（反事实净值出现非正值），改用期末总资产差；
    该口径含复利与路径影响，不是纯执行差异」

**不要为了让分段对齐去放宽 `boundaries` 判定**——那个守卫是对的，
分段不同就是不能逐段比。

### 2.2 反事实透支本身要成为输出

新增诊断字段，**这是本批最有价值的信息**：

- `counterfactualNonPositiveDays`：反事实净值非正的天数
- `counterfactualWorstNav`：反事实最低净值与日期

它回答的是：**这个账户的资金效率有多依赖优于 VWAP 的成交价**。
332 天透支意味着执行价格不只是"省了点钱"，而是账户能否运转的前提。

### 2.3 不做的事

- 不在反事实里加资金约束（买不起就不买）——那会改变成交集合，
  就不再是"纯执行差异"，变成另一个问题
- 不改 `boundaries` 的判定逻辑
- 不改实际路径的任何计算

## 3. 真实数据验收

## 4. 测试

- **边界一致**：构造反事实净值始终为正的 fixture，断言走原分段 TWR 路径且结果不变
- **边界不一致**：构造反事实透支的 fixture，断言返回降级口径 + 标注，
  且 `counterfactualNonPositiveDays > 0`
- **标注存在**：断言降级时输出里有那句说明
- 既有 U4 测试全部保持通过

## 6. 提醒

**这批的结论很可能是"执行优势无法用净值证实"。** 如果 `terminalDifference`
很小或方向与 BP 指标相反，如实报告——那说明 33.88 BP 这个数字虽然真实，
但没有转化成可观测的净值收益。这比强行给出一个好看的数字有用。
