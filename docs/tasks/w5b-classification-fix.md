# 任务书 W5b：对账单业务分类在真实数据上失效

打回修正 [W5](w5-statement-import.md)。W5 的合成 fixture 全绿、1956 项测试通过，
但**在真实对账单上分类严重错误**，管理者在交付后验证时发现。

## 1. 现象

按 `lishi`（成交）+ 对账单（`cashFlowsOnly`）导入真实账户后：

| 类别 | 条数 | 合计金额 | 应该是 |
| --- | ---: | ---: | --- |
| `interest` | 74 | **−5,377,900** | 4 笔、约 **+0.82 元** |
| `fee` | 36 | **−388,065** | 小额扣税 |

单笔最大的"利息"是 **−126,001.26**。复盘随之崩坏：
最低现金 −582 万（原 −12.6 万）、TWR 中断 1249 条（原 4 条）、
净值序列提前在 2023-06-30 终止（原 2026-09）。

## 2. 根因

分类按「摘要含"利息"」匹配，把**逆回购的融出资金**全抓进了 `interest`。
[W5 §6 裁定三](w5-statement-import.md)已经写明这类记录是成交不是现金流，
但实现按关键词匹配，覆盖范围远超裁定所指的那 17 条。

真实对账单里两种记录都含"利息"二字，**必须靠结构而非关键词区分**：

| 摘要形态 | 实质 | 金额量级 | 处置 |
| --- | --- | --- | --- |
| `批量客户结息处理批次:NNN， 利息结算：预计利息：0.08，利息积数：…，活期利率（年利率）：5.0E-4。` | **真利息** | 角分 | 计入 `interest` |
| `"融券回购购回日:20260410,预计利息:0.90,参…` | **逆回购成交** | 万元级负数 | `cashFlowsOnly` 下丢弃并计数 |

## 3. 交付

### 3.1 分类靠结构，不靠关键词

- **利息**：只认「批量客户结息处理」这一类结息记录，且沿用 W5 §6 裁定二——
  成对出现时只取满足 `余额 = 前一条余额 + 发生金额` 的那条
- **逆回购**：摘要含「融券回购购回日」的，一律归成交（`cashFlowsOnly` 下丢弃并计数），
  **不论摘要里是否出现"利息"**
- **其余含"利息"字样但不属于上述两类的**：留在 `unresolved` 并计数，**不猜**

`fee` 同样处理：**核实那 36 条 −38.8 万的真实构成**，
凡不能明确归类的一律 `unresolved`，不要用一个宽泛关键词兜底。

### 3.2 fixture 必须覆盖真实形态

W5 的 fixture 之所以全绿，是因为它只构造了预期形态。本批的 fixture
**必须同时包含上表两种含"利息"的摘要**（数值虚构、结构照搬），
并断言它们被分到不同去向。**这是本批的核心测试。**

### 3.3 量级护栏

`cashFlowsOnly` 导入完成后，输出各类现金流的条数与合计供调用方核对。
**不要在代码里写死任何金额阈值**——那是账户特定的，属于管理者验收环节。

## 4. 验收

- 真实对账单导入后：`interest` 条数为个位数、合计为正的小额；
  逆回购不出现在任何现金流类别里
- fixture 同时覆盖两种含"利息"摘要并断言去向不同
- 无法归类的一律 `unresolved` 且可计数，没有关键词兜底
- 默认 `scope: "all"` 行为零变化
- 不新增依赖、不新增迁移
- `decisions.md` 记一条：为什么业务分类不能靠关键词匹配
- `pnpm typecheck` / `pnpm test` / 改动文件 prettier 通过

## 5. 这批的教训要写进 decisions

**合成 fixture 全绿不等于实现正确。** fixture 由实现者按自己的理解构造，
它检验的是"实现是否符合实现者的理解"，而不是"实现是否符合真实数据"。
真实数据里那些预期之外的形态，fixture 天然不会覆盖。
凡涉及外部数据格式的批次，交付后必须在真实样本上验证量级与分布。
