# 任务书 W10：同日内资金顺序

依据：[资金对账诊断](../review/w9-cash-reconciliation-2026-09-14.md) 的「补充」节。

## 1. 问题

账户实际一直有正余额，但复盘算出的最低现金是 **−126,036.55**。
原因是对账单/成交明细里同日内的记录顺序是「先融出、后购回」：

```
2024-01-12  19:54:09  逆回购融出 −126,001.26   余额 −125,887.88
            19:54:11  逆回购购回 +126,022.32   余额      134.44   ← 当日末，正的
```

业务上是先收回昨天到期的钱，才能再借出。全区间统计：

| | 天数 | 最低值 |
| --- | ---: | ---: |
| **日末**余额为负 | 3 / 710 | −64,892.91 |
| **日内**出现负余额 | **164 / 710** | −165,805.96 |

**164 天的日内负余额是记录顺序造成的假象。**

## 2. 范围限定（本批最容易做错的地方）

**只重排逆回购与现金管理类的资金流入，普通证券买卖的顺序一行不动。**

理由：同一标的当日既有买又有卖时，**顺序决定移动加权成本与回合配对**。
动了普通证券的顺序，785 个回合、胜率 50.892857%、盈亏比 0.891201 就会漂移。
而逆回购与 `cashManagement` 不参与回合配对（`trade-review.ts` 已把
`instrument === "reverseRepo"` 排除在回合之外），重排它们是安全的。

具体规则：同一交易日内，把 **`reverseRepo` / `cashManagement` 的现金流入
（金额为正）**提前到该日所有资金流出之前；其余记录保持原相对顺序。

## 3. 交付

- 在净值/现金曲线计算路径上应用上述排序
- **日末余额不得改变**（排序不改变当日净额，只改变路径）
- 排序作为显式步骤，在输出里标注「同日内逆回购与现金管理流入已提前」，
  不要静默重排——将来换数据源时要能发现

## 4. 真实数据验收（硬标准）

| 指标 | 目标 |
| --- | --- |
| 回合统计 | 785 个 / 50.892857% / 0.891201 **一个都不许变** |
| 日末余额序列 | 与排序前**逐日相等** |
| 最低现金 | 应显著改善（预期接近日末口径的 −64,892.91 量级）；**报告实测值与日期** |
| `transferIn` / `transferOut` / `cashManagement` | 条数与金额均不变 |

**不要为了让最低现金变正而扩大重排范围。** 剩余 3 天日末为负是另一回事，
本批不处理，如实报告即可。

## 5. 测试

- **手算**：构造同日「融出 −100 / 购回 +100 / 买入 −50」三笔，
  断言重排后中间现金不为负、日末现金与重排前相等
- **普通证券不动**：同日同标的先买后卖与先卖后买两种 fixture，
  断言重排前后回合配对与成本**逐项相等**
- **跨日不影响**：不同日期的记录相对顺序不变
- **标注**：断言输出里有重排说明
- 既有复盘测试全部保持通过（含 W8 的非逆回购哈希护栏）
