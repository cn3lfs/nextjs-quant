# 2026-11-19 交易参考单点优化计划

本批唯一计划。基线 `68716a8`。从九篇第三方参考中取工作流，在观澜现有设计内做三轮单点优化，不重建已具备的市场总览、持仓和情报能力。

## 共用边界

沿用现有数据源、读取流程和存储结构。验证使用隔离数据或模拟接口。视觉沿用 `DESIGN.md` 的浅色规范与现有导航。每轮按「产品定义 → 独立 Claude UI 审阅 → 另一 Claude 开发 → 管理者复核 → 本地提交」推进，提交后再以新 HEAD 细化下一轮。

## R1 今日自选卡片排序

已实施。现有排序状态仅作用于当前面板。行情刷新失败时保留保存顺序并提示。

市场与数据总览的自选面板增加「保存顺序」「涨幅优先」「跌幅优先」，默认保存顺序。涨幅从高到低，跌幅从低到高。并列和未知各自保持保存顺序，未知排在最后。卡片沿用同一批报价和原图表链接。

排序测试 3 项、类型检查、变动源码 ESLint 与格式检查通过。交互复用已有可换行的分段控件，本轮以代码和排序测试验收，未实机核对窗口尺寸。

## R2 统一持仓直达图表

已实施。A 股行的「图表」链接在本标签打开该标的。统一持仓的地址保存当前筛选、分组和页码，默认入口仍采用默认筛选。

四项契约测试与类型检查通过。隔离构建和 Playwright 新场景通过，确认图表显示 `sh600019`，浏览器返回一步恢复 A 股筛选、分仓分组和第 2 页，持仓详情的返回链接也保留这些条件。浏览器场景没有外部请求，数字货币和非法代码由契约测试覆盖。

## R3 情报匹配标的

已实施。展开持仓与计划情报后，「匹配标的」显示命中的名称或代码，并标注「持仓」和「未完成计划」。同一条新闻可列出多个标的，同一标的可显示两个来源。归属为空时保留新闻，省略标签。

命中来自现有 SQLite 查询所用的完整标题和正文。原排序、100 条上限和原文入口沿用既有行为。匹配说明保留在面板内。

隔离 SQLite 验证了多标的、同标的双来源、预览截断后命中、原文链接选词顺序和 100 条上限。情报定向测试 7 项、类型检查和变动文件检查通过。界面接线通过源码和类型复核，未在浏览器实测。仅大小写不同的英文词仍可能命中情报却因原文筛选规则无法打开详情。
