工作区之间最常见的交接有三条。**扫描与图表**把公式候选和对应快照交给图表。**今日**把后台扫描候选交给人确认，形成计划，**账户与复盘**再关联实际成交。**策略实验室**把策略版本和验证证据交给纸面账户及资格评估。三个页面上都有“候选”或“策略”时，沿着各自的来源看。 [工作区导航](../../src/components/workbench/navigation.ts#L48) · [系统架构](../architecture.md#总体结构与数据流)

## 今日

```text
今日
├─ 汇总：行情就绪、市场状态、风险持仓、分仓与提醒
├─ 候选：读取后台扫描产物，按市场和标的合并策略来源
└─ 确认：预览数量，由你调整入场、保护位、理由和到期日
```

**走一遍「把收盘候选加入计划」**。后台调度先检查交易日、下载回执和当前窗口，再用已完成行情评估策略。扫描会留下进度标记，命中才写候选事件。页面读取这些事件，合并同一标的的多个策略来源，预览可买数量。你点击「加入计划」后，服务端按最新持仓、分仓资金、费用和风险重新核算，校验重复项，再把未完成计划写入 SQLite。 [后台扫描](../../src/server/alerts/engine.ts#L82) · [候选汇总](../../src/server/alerts/workspace.ts#L123) · [保存计划](../../src/server/alerts/plans.ts#L51)

**使用时留意候选时点。** 候选查询用最近一次扫描进度标记来选记录。若当日扫描跳过、进度仍停在上个交易日，列表可能继续返回上一批候选。判断当天是否扫过，应该同时看数据就绪状态和候选显示的时间。 [候选读取](../../src/server/db/alert-repository.ts#L257) · [今日界面](../../src/components/overview/today-workspace.tsx#L202)

## 扫描与图表

```text
扫描与图表
├─ 图表：读取行情，按周期和复权口径成图，按需计算缠论
├─ 证券池与 RPS：读取池成员和排名，提供按名单翻股
├─ 条件选股：校验公式，后台扫描，保存候选和输入快照
└─ 页面状态：保留图表与公式面板，支持候选来回看
```

**走一遍「跑公式，再点候选看图」**。服务端先检查公式输出与未来函数，再交后台按固定时点读取本地日线。扫描用完成的行情确定基准日，落后的标的会列入隔离，命中结果与对应快照分别保存。页面查询的是该任务的结果并分页展示。点「个股研究」时，图表入口接收候选的快照身份与任务身份，按当前图表周期和复权口径出图，原生缠论另行计算。 [公式服务](../../src/server/screening/formula-screen-service.ts#L99) · [候选跳转](../../src/components/workbench/screen-view.tsx#L451) · [图表入口](../../src/components/market/market-page.tsx#L21)

**可追溯的依据是公式任务的输入快照。** 图表切换周期、来源或复权后会重算显示。当你想核对“公式为什么命中”，先看任务基准日和快照。图表侧同时可能展示统一提醒引擎的候选，那是另一条来源。 [图表聚合](../../src/server/charts/chart-bars.ts#L68) · [保留路由](../../src/components/workbench/retained-routes.tsx#L7)

## 策略实验室

```text
策略实验室
├─ 策略中心：列出已登记规则、版本和观察状态
├─ 策略实验：输入证券池、窗口、本金、费用，提交组合回测
├─ 任务证据：记录输入口径、成交、拒单与权益，可导出重放
└─ 研究资格：读取成绩单、同版本前推结果与人工晋级操作
```

**走一遍「提交一次页面回测」**。页面提交策略对象、日期和成本情景，路由创建后台任务。Worker 读取行情，将信号使用的复权价、成交使用的原价和公司行动等输入冻结，组装撮合请求。组合引擎处理成交、拒单和权益，评价模块生成绩效概览。应用保存任务结果，冻结证据可交给 CLI 复现同一请求。 [实验路由](../../src/server/api/routers/strategy-lab.ts#L52) · [回测执行](../../src/server/research/lab-backtest.ts#L93) · [CLI 重放](../../scripts/research-lab-replay.ts#L119)

**策略中心展示的是三种不同进度。** 规则可以登记，回测可以完成，策略也可以通过资格评估。一次页面回测只产生该次任务证据。晋级还取决于研究成绩单、同版本纸面前推及人工确认。 [策略状态](../../src/server/db/strategy-lab.ts#L90) · [前推评估](../../src/server/paper/assessment.ts#L437)

## 账户与复盘

```text
账户与复盘
├─ 券商交割单：导入成交与资金流水
├─ 手工账本：独立录入成交并核对持仓成本
├─ 纸面账户：用本地策略和行情推进模拟状态
├─ 模拟交易所：读取 demo 账户的成交、余额或持仓快照
└─ 统一复盘：把成交关联到来源计划、日志、保护及执行质量
```

**走一遍「导入交割单并做复盘」**。交割单文件先解析并预览，区分新行、重复行和冲突。确认时检查文件哈希和预览令牌，在同一事务写入批次、成交和现金流水。统一账户页面读取这些记录，再用本地原价行情补估值。复盘关联另存计划或提醒与成交的关系，保留原始成交。 [交割单存储](../../src/server/db/delivery-store.ts#L153) · [统一账户读取](../../src/server/db/account-workspace-repository.ts#L32) · [复盘服务](../../src/server/portfolio/account-workspace-service.ts#L392)

**统一页面仍保留账本各自的来源。** 同一笔交易既导入交割单又手工录入，两个来源仍会各自保留事实。缺可靠价格、公司行动或成本依据时，相关结果可能留空。纸面账户和交易所模拟各自单列，复盘时先确认当前看的来源。 [账户接口](../../src/server/api/routers/accounts.ts#L40) · [持仓汇总](../../src/server/portfolio/account-workspace-service.ts#L184)

## 情报

```text
情报
├─ 新闻检索：从配置的本地资讯库读取原文
├─ 相关资讯：用持仓和未完成计划找相关新闻
├─ 模型解读：对新闻做行业分类、主题归纳和引用校验
└─ 财联社复盘：导入报告、盘前固定样本、收盘后核对价格
```

**走一遍「复盘一份盘前报告」**。先预览报告并检查文件身份，确认后保存报告版本。样本须在交易日北京时间 09:30 前固定，结合报告提及标的、上一交易日 RPS 和板块成员记录选择依据。收盘后读取本地行情，检查样本相对报告方向的表现。原始报告、固定样本、事实摘录和后续核对分别保存，页面可以逐项回看。 [报告文件读取](../../src/server/news/cls-report-files.ts#L24) · [固定样本](../../src/server/news/cls-review-service.ts#L72) · [价格核对](../../src/server/news/cls-outcomes.ts#L19)

**方向观察和实盘成交有不同口径。** 当前价格核对从样本日开盘价比较若干期限的收盘价，缺数据、停牌或尚未到期需要保留状态。模式是否能自动运行，还取决于调度设置、完成标记和本机数据是否齐备。 [结果统计](../../src/server/news/cls-outcomes.ts#L100) · [复盘调度](../../src/server/news/cls-review-scheduler.ts#L47)

## 系统

```text
系统
├─ 设置与连接：保存本机数据源和各项运行配置
├─ 任务中心：查看任务、进度、完成结果和失败原因
├─ 通知：管理渠道和订阅，展示出站状态
└─ 数据库备份：输出数据库快照，按保留份数轮换
```

**走一遍「查看一条通知为何没发到」**。事件经授权决定是否进入出站队列。调度器领取待发记录，发送前再核对渠道与授权，之后回写发送状态、失败或重试。通知页面查询这条投递记录。策略扫描有结果时仍可能处于影子模式，默认会记录观察结果，只有满足投递设置才进入队列。 [运行时调度](../../src/server/runtime.ts#L19) · [通知服务](../../src/server/infra/notifications.ts#L650) · [提醒模式说明](../strategy-signals/2026-11-14-r2b-alerts.md#L7)

**备份范围是应用数据库。** 通达信原始文件和 Windows 凭证有自己的位置，恢复时要分别考虑。通知标记为 sent 表示渠道接受了请求，应用内状态只记录到这一环。 [数据库备份](../../src/server/db/backups.ts#L67) · [本机凭证](../../src/server/vault.ts#L23)

## 共用工程底座

```text
共用工程底座
├─ 宿主：Electron 管窗口与本机服务进程
├─ 接口：Next.js 路由和 tRPC 把请求交给对应模块
├─ 计算：后台任务进入 Worker，原生 CZSC 另走串行子进程
├─ 数据：原始源文件只读，SQLite 存业务事实，行情与页面各有缓存
└─ 六个包
   ├─ tstdx                通达信协议与本地文件格式
   ├─ quant-rps            相对强度排名
   ├─ trading-strategies   策略、公式及信号规则
   ├─ trading-strategy-core 共享指标及计算规则
   ├─ quant-backtest       组合撮合
   └─ quant-performance    绩效评价
```

**走一遍「打开一只股票」**。Electron 启动本机 Node 服务。图表请求由 tRPC 交给行情与任务模块，Worker 读取并校验行情快照。底层优先使用有效的解析缓存，需要时由 `tstdx` 只读解析原始通达信文件。页面用快照生成图表，对可用周期再请求原生缠论。缓存能让画面更快恢复，源文件、服务端快照和当前完成行情时点决定这次看到的数据口径。 [Electron 启动](../../electron/main.ts#L54) · [业务路由](../../src/server/api/root.ts#L20) · [行情读取](../../src/server/market/bar-store/local-source.ts#L66) · [CZSC 子进程](../../src/server/strategies/chan/czsc.ts#L73)

**串行范围在原生缠论通道内。** 它与一般后台任务、行情文件读取分开。桌面正式包又有自己的构建和部署时点，这份导览用源码解释当前结构。 [共享包与数据层](../architecture.md#六个计算与数据包)

## 用这棵树核对产品预期

可以顺着你最常做的一次操作读完相关分支。看盘选股走「扫描与图表 → 今日 → 账户与复盘」，调研新方法走「策略实验室 → 纸面账户 → 策略资格」。发现偏离时，记下具体的一步、你预期的结果和当前结果。例如「今日未完成收盘扫描时，候选页应如何标识上一批结果」，这比笼统地说“改候选模块”更容易决定改哪里的规则。当前实施优先级仍以项目计划为准。 [当前实施计划](../next-plan.md)
