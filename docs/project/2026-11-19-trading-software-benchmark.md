# 主流交易软件与量化工作台对标分析

日期：2026-11-19　范围：观澜个人量化工作台（A 股 + BTC/ETH 现货）　性质：竞品研究与 Wave 2/3 设计输入，不是已实现能力

## 一页结论

1. 标杆产品的差距不在功能数量，而在**操作路径长度**与**状态可解释性**：TradingView/通达信把「找标的 → 看图 → 设提醒」压到 1–3 次击键；QuantConnect 把「研究 → 回测 → 模拟 → 实盘」压到同一条证据链。
2. 观澜的工程与研究严谨度已高于多数个人工作台，但前端仍偏「页面集合」：顶栏只有标题和页面搜索，侧栏只露每组首项，今日页缺少一屏结论，冻结图表的复权价与计划原价未在同一视觉层解释。
3. 本轮最高投资回报率的不是新数据源，而是七个「解释层」：顶栏状态条、侧栏双层折叠、今日 Executive Summary Ribbon、冻结图表双价锁、策略 6 阶段流水线、双账重叠净敞口、提醒 6 阶段诊断仪。
4. 键盘流应复用通达信肌肉记忆（F5/F8/F10、翻股）与 TradingView 命令面板（Ctrl+K、Shift+F、Alt+A），但必须做作用域隔离和输入法保护，不能劫持浏览器/系统保留键。
5. 信息密度应提供「舒适 / 专业紧凑」两档，共用一套 token，只切换字号、行高、行距与留白；数字统一等宽对齐，任何汇总必须带口径与时点。

## 1. 标杆产品核心体验拆解矩阵

### 1.1 全局导航与键盘流

| 产品                   | 可核实的最佳模式       | 关键细节                                                                                                                                                       | 可迁移原则                                                           |
| ---------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| TradingView            | 单键 + 作用域          | `Ctrl+K` 快速搜索；任意字母键换标的、任意数字键换周期；`/` 打开指标；`Alt+A` 建提醒；`Shift+F` 专注全屏；Pine 编辑器 `F1`/`Ctrl+Shift+P` 命令面板              | 高频动作给单键；单键只在明确上下文生效；界面持续显示 `kbd` 提示      |
| 通达信                 | 键盘精灵 + 功能键      | 输入代码/拼音首字母直达；`F5` 分时/分析、`F8` 周期、`F10` 个股资料、`F3/F4` 指数、`F6` 自选；`Ctrl+M` 多股同列；数字系列 `91/92/96` 直达分钟/日线；`PgUp` 翻页 | 让老用户不离开键盘；数字/字母有稳定语义；翻股与翻页分开              |
| 同花顺/东财            | 搜索 + 场景入口        | 顶部搜索支持代码/名称/拼音；行情、板块、资金、ETF 各有稳定入口；快捷键弱于通达信，但入口命名稳定                                                               | 搜索是兜底，不是唯一路径；入口命名要能形成肌肉记忆                   |
| 富途/老虎              | 搜索 + 自选/持仓双入口 | 自选与持仓相邻；个股详情以右侧/浮层承接；下单与条件单从持仓行直达（产品观察）                                                                                  | 列表不跳页也能看详情；「看」与「做」在同一上下文                     |
| Koyfin                 | 命令栏语法             | `/` 唤起；`/MOV`、`/MYW`、`/MP` 两三个字母直达功能；`AAPL <Enter> G` 表示「标的 → 功能」两步语法；支持自定义快捷键                                             | 命令面板要支持「对象 + 动作」两段式；自定义别名比堆快捷键更可扩展    |
| Bloomberg              | 命令行 + Panel         | 顶部命令行输入功能码后 `Enter/GO`；`PANEL` 键切换面板；功能键有颜色语义；所有操作可键盘完成                                                                    | 命令行是最高密度入口；面板化布局让多任务并行；颜色只辅助、不替代文字 |
| QuantConnect/聚宽/米筐 | 项目/终端隐喻          | 以 Project/Terminal 组织研究、回测、优化、模拟、实盘；键盘流弱，但生命周期阶段清晰                                                                             | 导航不仅回答「去哪」，还要回答「现在处于哪一步」                     |

**共识**：全局入口应有三件套——命令面板、标的直达、快捷键帮助。命令面板负责「找不到的功能」，标的直达负责「看得见的对象」，帮助层负责「可发现」。

### 1.2 看盘与图表工作区

| 产品             | 可核实的最佳模式       | 关键细节                                                                                                                 | 可迁移原则                                                   |
| ---------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| TradingView      | Supercharts 多区协同   | 多图布局可同步十字线/时间；右侧自选与详情；对象树管理画线；`Alt+D` 数据窗口；Bar Replay 逐根回放；`Alt+Enter` 最大化图表 | 图表不是孤岛；右侧轨道承接「当前标的的一切」；回放是研究刚需 |
| 通达信           | 强键盘看图             | `F5` 分时/K 线、`F8` 周期循环；主图叠加 `Ctrl+O`；多股同列 `Ctrl+M`；区间统计 `Ctrl+W`；`PgUp/PgDn` 翻页                 | 周期切换必须一键；同屏对比优先于反复跳转                     |
| 同花顺           | 分时 + 盘口 + 明细同屏 | 分时左、十档右、明细下；主图指标选择在上沿，副图独立指标与参数；板块/ETF 可勾选叠加                                      | 同一标的的「价、量、盘口、明细」应在一屏内完成               |
| 富途/老虎        | 图表即交易上下文       | 图表双击设提醒/条件单；持仓成本线、订单线直接画在图上；右侧详情抽屉（产品观察）                                          | 图表上的标记要能解释「这是什么价、什么单」                   |
| Koyfin/Bloomberg | 高密度图表 + 表格切换  | 同一数据可在图/表间切换；键盘数据窗口；多面板并列                                                                        | 图与表不是两个产品，应共享筛选与标的                         |
| QuantConnect     | 结果与图表联动         | 回测报告点某笔交易，主图滚到对应 bar；月度收益、回撤、暴露同页                                                           | 任何统计数字都应能下钻到原始 bar/成交                        |

**共识**：一个标的的工作区应能回答四个问题——现在什么价、为什么涨跌、我的仓位在哪、下一步做什么。观澜目前强在 K 线与缠论，弱在「右侧上下文」和「图表与计划/持仓的同屏解释」。

### 1.3 选股与市场情绪

| 产品        | 可核实的最佳模式    | 关键细节                                                                                                                  | 可迁移原则                                                         |
| ----------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| TradingView | Screener 条件即界面 | 过滤器以 chip 呈现；`Shift+F` 加过滤、`Shift+C` 加列；保存 screen；可最大化                                               | 条件要可见、可复用、可比较；结果列由用户配置                       |

**共识**：选股页的价值不在「筛出多少只」，而在「筛完后知道下一步看谁」。条件摘要、数据时点、证券池范围必须常驻。

### 1.5 持仓风险与复盘

| 产品         | 可核实的最佳模式   | 关键细节                                                                                                 | 可迁移原则                                           |
| ------------ | ------------------ | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| TradingView  | 持仓 + 提醒 + 纸面 | 持仓/订单面板与图表联动；提醒可直接从图上创建；Paper Trading 与策略报告衔接                              | 持仓是图表上下文的一部分                             |
| 通达信       | 自选/持仓相邻      | 自选与持仓同入口；成本/现价/盈亏同表；市场指标可加入自选                                                 | 关注与持有要能一键切换                               |

| 富途/老虎    | 风险距离可视化     | 当前价相对止损/目标位的进度条；条件单与持仓绑定；当日盈亏突出（产品观察）                                | 让「离止损还有多远」一眼可见，而不是心算             |

**共识**：持仓页应按「事实 → 风险 → 动作」三层组织。观澜已有真实/纸面/模拟分账与成本/估值价，但两本真实账重叠时没有视觉解释，风险距离也未形成固定组件。

| 富途/老虎        | 到价提醒 + 持仓新闻 | 价格提醒、持仓相关新闻、社区情绪（产品观察）                                    | 提醒与持仓/计划同上下文                          |

## 2. 观澜现状 vs 标杆差距诊断

### 2.1 现状基线（只列与本报告相关的已实现能力）

- 六个工作区：今日、扫描与图表、策略实验室、账户与复盘、情报、系统；导航 `navigation.ts` 已按工作流程分组。
- `Ctrl+K` 已存在，但只搜索页面名称；顶栏只有标题与页面搜索，无全局状态。
- 侧栏 `sidebar.tsx` 当前每组只显示首项，其余页面收进「全部页面」对话框；没有双层折叠，也没有图标栏。
- 图表已支持分时/日 K/周 K/月 K 快捷切换、`F5`/`F8`、冻结快照、A 股叠加对比；冻结图与计划价格的口径差异在源码与模块边界文档中已明确存在。
- 今日页已有指数、涨跌家数、ETF 净申赎、自选排序、候选与计划入口；但没有一屏 Executive Summary。
- 策略中心已有定义/版本、回测、同口径比较、纸面、影子、晋级、live 开关；状态推导在 `strategy-lab.ts`，但没有六阶段可视化。
- 账户页已有真实/纸面/模拟分账、成本与估值价、行业/分仓敞口；两本真实账重叠时全来源合计可能重复，页面已有提示但无结构化解释。
- 提醒已有事件、订阅、渠道、投递记录、运行时模式与授权；「已启用但未发」需要跨页排查。

| 情报       | 秒级时间、匹配标的、加红档案、财联社复盘      | 情报与持仓/计划/提醒未形成统一收件箱；重要性不可筛                   | 统一情报/提醒收件箱；上下文直连                                     | P1/P2  |
| 系统       | 数据健康、任务中心、投递记录、授权            | 「已启用未发」跨四五个概念；状态条缺失；失败原因不收敛               | 顶栏状态条 + 提醒 6 阶段诊断仪                                      | P0/P1  |
| 共用底座   | Electron/本机服务/隔离数据/测试               | 导航只到页面级；无密度切换；快捷键不可发现                           | 侧栏双层折叠、两档密度、快捷键帮助层                                | P0     |

### 2.3 七个最痛断层（按用户损失排序）

1. **不知道现在能不能信**：数据基准日、行情源健康、扫描是否完成分散在系统页与各工作区，顶栏没有统一状态。
2. **找不到功能**：导航只露每组首项，二级页面靠对话框；新用户与老用户都难以形成路径记忆。
3. **今天要做什么不收敛**：今日页信息齐全但没有「结论行」，开盘前需要人工汇总。
4. **同一根 K 线有两个价**：冻结图显示前复权，计划用原价；没有双价锁时，用户会误以为其中一个错了。
5. **策略为什么没晋级说不清**：纸面、影子、前推、晋级、live 是五个概念，页面没有一条流水线和一个主阻断原因。
6. **两本真实账合计可能重复**：全来源合计可能把同一笔成交算两次；现有提示是文字，不是结构化区间。
7. **提醒为什么没发要跨页拼**：模式、订阅、渠道、投递、任务各有一套状态；缺一个诊断仪。

## 3. Wave 2 / Wave 3 可直接吸收的高杠杆设计规范

> 本节所有参数均为**实现建议**，不是已实现事实。落地时沿用 `DESIGN.md` 的浅色语义与现有组件，不引入第二套样式系统；新增 token 只做扩展，不改现有语义。

### 3.1 快捷键与命令面板

#### 3.1.1 设计原则

- **作用域优先**：同一键在不同上下文可有不同行为，但必须由焦点区域决定，且界面可见当前作用域。
- **输入法保护**：`event.isComposing` 或焦点在 `input/textarea/contenteditable` 时，除 `Esc`、`Ctrl+Enter` 外不触发单键快捷键。
- **不劫持保留键**：`Ctrl+W/T/N`、`Ctrl+P`、`Ctrl+S`、`Ctrl+R`、`F12`、`Ctrl+Shift+I`、`Alt+F4` 不注册；`F5` 仅在图表工作区拦截。
- **可发现**：所有快捷键出现在命令面板、按钮 tooltip、`?` 帮助层三处；`kbd` 样式统一 11px/18px、圆角 4px、边框 `--nc-border`。
- **可关闭**：设置中提供「启用单键快捷键」开关，默认开启；专业用户可关掉单键、只留组合键。

#### 3.1.3 命令面板规格

- 尺寸：宽 560px（≥1280），`max-height: 60vh`，距顶 15vh；移动端全宽。
- 结构：输入 44px → 分组结果 → 底部提示条（`↑↓` 选择、`Enter` 打开、`Esc` 关闭）。
- 分组与排序：`最近`（最多 3）→`页面`（最多 6）→`动作`（最多 6）→`本机标的`（有目录时最多 6）。
- 语法：
  - 默认：模糊匹配页面名、动作名、标的名/代码。
  - `>` 前缀：只搜动作（如 `>新建计划`、`>切换紧凑`）。
  - `@` 前缀：只搜本机标的；无目录时显示「本机证券目录未就绪」，不假装可搜。
- 动作注册：每个动作声明 `id`、`label`、`group`、`when`（当前工作区/是否有选中标的）、`run`。不可用动作显示但置灰，并给出原因（如「先选择一只标的」）。
- 不做：全文检索新闻正文、跨报告语义搜索、远程证券搜索。这些会违反 `DESIGN.md` 的「页面搜索」边界，需另行授权。

### 3.2 顶栏状态条

**目标**：让用户在任意页面 3 秒内回答「数据能不能信、后台有没有事、我有没有漏掉的提醒」。

| 区域 | 内容                       | 规格                                                                       |
| ---- | -------------------------- | -------------------------------------------------------------------------- |
| 左   | 面包屑（工作区）+ 页面标题 | 标题 15px/22px 600；面包屑 11px/16px `--nc-text-4`；总高 56px（紧凑 48px） |
| 中   | 命令入口（`Ctrl+K`）       | 宽 280–360px，高 32px；占位「搜索页面或输入命令」；右侧 `kbd`              |
| 右   | 状态 chips                 | 最多 5 个，溢出收入「更多」；每个高 28px、圆角 999px、1px 边框、左圆点 6px |

**状态 chip 定义**（全部复用现有接口，不新增数据源）：

| Chip       | 正常           | 警告                       | 未知/未就绪 | 点击                |
| ---------- | -------------- | -------------------------- | ----------- | ------------------- |
| 数据基准日 | `11-17 收盘`   | `11-17 盘中` / `滞后 1 日` | `未核验`    | 今日/市场与数据总览 |
| 行情源     | `正常 · 09:41` | `降级 · 09:41`             | `未连接`    | 系统/数据与连接     |
| 后台任务   | `0 运行`       | `2 失败`                   | `未启动`    | 系统/任务中心       |
| 提醒       | `0 未读`       | `1 投递失败`               | `未启用`    | 系统/信号与通知     |
| 模式       | `影子`         | `live · 已订阅`            | `未授权`    | 策略中心/提醒诊断   |

**视觉规则**：

- 正常用 `--nc-ok` 圆点 + 中性文字；警告用 `--nc-warn`；错误用 `--nc-bad`；未知用 `--nc-text-4` 空心圆。**不用整块红/绿底**。
- 每个 chip 的 tooltip 必须写明：来源、统计口径、截至时刻、下一步。例：「上涨/下跌家数来自本机 `SC31`，截至 2026-11-17 收盘，未含平盘」。
- 数值为 0 与「未知」必须区分：未知显示 `—`，不显示 `0`。
- 状态变化用 160ms 淡入，遵循 `prefers-reduced-motion`。

**响应式**：≥1280 显示 5 chips + 搜索；1025–1279 显示 3 chips + 「更多」；≤1024 只显示「数据基准日 + 异常计数」两个图标 chip，搜索收为图标。

**验收**：任取一个异常（任务失败/提醒失败/数据滞后），顶栏在 1 次点击内到达对应页面；截图与接口返回值一致；无任何前端推算的「健康」状态。

### 3.3 侧栏双层折叠

**现状问题**：`sidebar.tsx` 把每组压成首项，二级页面进入对话框；用户必须记住「全部页面」里有什么。

**结构**：品牌区 56px → 工作区组（现有 6 组）→ 每组可展开子页（最多 10 项，超出「更多」）→ 底部系统状态。只做两层，不做第三层。

| 元素 | 展开态（216px）                                                       | 图标栏（56px）                     |
| ---- | --------------------------------------------------------------------- | ---------------------------------- |
| 组头 | 高 28px；11px/16px 大写/加宽 0.04em；`--nc-text-4`；右侧 chevron 12px | 不显示文字；组间 8px 分隔          |
| 子项 | 高 32px；13px/20px；左内边距 28px；图标 16px + 文字 8px 间距          | 只显示图标；tooltip 显示名称       |
| 选中 | 背景 `--nc-accent-900`；文字 `--nc-text`；左侧 2px `--nc-accent`      | 图标变 `--nc-accent`；左侧 2px     |
| 徽标 | 右侧 18px 高 pill；11px；错误态 `--nc-bad`                            | 右上角 6px 圆点                    |
| 折叠 | 组头点击切换；chevron 旋转 120ms                                      | 组头变为分隔线；hover 弹出子项浮层 |

**行为**：

- 默认展开当前工作区组，其余组折叠；用户手动展开的状态持久化到本地设置。
- 切换页面时，若目标组折叠则自动展开，但不强制收起其他组（最多允许同时展开 3 组，超出时收起最久未用的组）。
- `Ctrl+B` 在展开/图标栏之间切换；1024px 以下自动进入图标栏；768px 以下改为抽屉。
- 保留「全部页面」作为发现入口，但不再作为唯一二级入口；命令面板与侧栏共享同一份 `navGroups`，避免两套菜单漂移。
- 子项顺序与 `navigation.ts` 一致；不在前端重排。

**验收**：1440 宽度下 6 个工作区组全部可见；1024 下自动图标栏且 tooltip 可读；刷新后展开状态保持；键盘 `Tab` 可遍历组头与子项，`Enter` 展开/进入。

### 3.4 今日 Executive Summary Ribbon

**目标**：把今日页从「卡片集合」变成「一屏结论」。位置在顶栏下方、页面内容上方，宽度随内容区，不固定居中。

**结构**：6 个信息格 + 1 条结论行；桌面单行 64px（紧凑 52px），1024 以下 3×2，768 以下纵向 2 列。

| 格     | 标签（11px） | 主值（20px/28px 600） | 次值（12px）                       | 数据来源（现有）  | 点击              |
| ------ | ------------ | --------------------- | ---------------------------------- | ----------------- | ----------------- |
| 1 数据 | 数据基准日   | `11-17`               | `收盘 · 已核验` 或 `盘中 · 未核验` | 行情就绪/扫描回执 | 市场与数据总览    |
| 2 宽度 | 市场宽度     | `1325 / 4119`         | `涨停 42 · 跌停 40`                | `SC31`、`SC3/SC4` | 打板情绪/今日概况 |
| 3 持仓 | 持仓风险     | `3 只 · 62%`          | `最近止损 -4.8%`                   | 统一持仓/计划     | 统一持仓          |
| 4 待办 | 今日待办     | `2 个候选`            | `1 份计划待确认`                   | 今日候选/计划     | 今日候选          |
| 5 异常 | 异常         | `1`                   | `提醒投递失败`                     | 任务中心/投递记录 | 信号与通知        |
| 6 模式 | 运行模式     | `影子`                | `订阅 2 · 未发 0`                  | 运行时/订阅       | 策略中心          |

**结论行**（可选，规则生成，不调用 LLM）：

> 数据截至 11-17 收盘｜上涨 1325 / 下跌 4119｜持仓 3 只，1 只距止损不足 1%｜今日 2 个候选待确认｜1 条提醒投递失败

规则：按「数据 → 市场 → 持仓 → 待办 → 异常」固定顺序；每段只在有值时出现；总长不超过 80 个汉字；每个数字继承对应格的口径与时点。

**视觉**：

- 容器：白底、1px `--nc-border`、圆角 8px、内边距 16px；格间 1px 竖分隔；不加阴影。
- 标签 11px/16px `--nc-text-4`，字重 500；主值 20px/28px 600 `--nc-text`，数字 `tabular-nums`；次值 12px/18px `--nc-text-3`。
- 只在「涨跌/盈亏」使用 `--nc-up/--nc-down`；其余中性。异常格用 `--nc-warn` 圆点 + 文字，不用红底。
- 空态：`未就绪` + 下一步链接；错误：`读取失败` + 重试；旧数据：`截至 11-16` + 琥珀色圆点。
- 骨架屏按格占位，避免整页跳动；数据到达后 120ms 淡入。

**交互**：格 hover 显示来源与口径；点击进入对应工作区并保留当前日期；`Alt+点击` 新标签打开（现有路由能力允许时）。右侧提供「收起为一行」按钮，状态持久化。

**验收**：六个格均有来源与时点；任取一个数字与源页面一致；未知不显示 0；1024/1440 两宽度不溢出；键盘可逐格聚焦并读出完整标签。

### 3.5 冻结图表双价锁

**问题定义**（来自模块边界文档）：公式候选的日线与分析使用任务快照，准备交易计划时取冻结序列末根的**原价**，而图上可能显示**前复权价**。两个价都正确，但用途不同；没有同屏解释就会误判。

**设计目标**：同一根 K 线，同时看见「快照价（前复权）」与「原价（计划用）」，并明确哪个用于复核、哪个用于下单/计划。

| 元素       | 规格                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| 锁定 chip  | 图表工具栏左侧：锁图标 + `快照 #id · 2026-11-14 · 前复权`；高 28px；圆角 6px；点击打开快照说明 popover                     |
| 主价格轴   | 默认前复权（冻结口径）；轴标签 11px `--nc-text-4`                                                                          |
| 副价格轴   | 开启「原价」后，右侧显示虚线刻度，颜色 `--nc-text-4`；不改变主图 K 线                                                      |
| 十字光标卡 | 两行：`快照价 12.34（前复权）` / `原价 12.81（计划用）`；第三行 `复权因子 1.0381`；第四行 `计划价 12.81`                   |
| 计划表单   | 默认填入原价；字段标签「计划价（原价）」；旁注「图上为前复权快照价，差异 3.8%」                                            |
| 不一致提示 | 当计划价与原价偏离 > 0.5% 时，琥珀色 inline 提示：「计划价 13.20 与原价 12.81 不一致，请确认」；不阻断保存，但要求勾选确认 |
| 缺失处理   | 快照无原价/因子时显示 `不可用`，不推算、不回退到前复权价冒充原价                                                           |

**视觉**：

- 双价锁 chip 使用 `--nc-accent-900` 底 + `--nc-accent` 文字；未锁定的普通图表显示「实时行情」灰 chip，二者视觉必须不同。
- 十字光标卡宽 220px，白底、1px 边框、圆角 6px、内边距 8px；数字右对齐、等宽；标签 11px、数值 13px。
- 不一致提示用 `--nc-warn` 左边框 2px + `--nc-warn-edge` 底，不使用红色（红色留给亏损/错误）。

**交互**：

- `P` 键（图表焦点）切换原价轴；工具栏也有开关；状态写入图表视图，随快照保存。
- 从图表点「建计划」时，表单顶部固定显示双价对照，用户不需要回看图表。
- 切换周期不改变锁定状态；冻结证据始终按快照口径显示，不因原价轴开启而改变缠论/指标计算。

**验收**：同一根 bar 的两种价格同时可见；计划保存使用原价；缠论与指标仍用快照价；无原价时显示不可用；截图与 `chart-bars` 返回值一致。

### 3.6 策略 6 阶段晋级流水线

**目标**：把散落在策略中心、回测、方法目录、纸面、影子、晋级的证据压成一条可读流水线，并始终只显示**一个主阻断原因**。

**六阶段**（严格映射现有能力，不新增状态机）：

| 阶段 | 名称       | 进入条件（现有事实）                         | 通过标记                | 失败/未开始                         |
| ---- | ---------- | -------------------------------------------- | ----------------------- | ----------------------------------- |
| 1    | 定义冻结   | 策略定义 + 版本 + 输入哈希                   | `v3 · 输入已冻结`       | `无版本` / `输入未冻结`             |
| 2    | 回测证据   | 该版本组合回测完成，权益/成交/诊断已写回     | `2026-11-14 · 781 bars` | `未运行` / `运行中` / `失败`        |
| 3    | 同口径对比 | 方法目录中同市场、同口径、已完成任务         | `12 组同口径`           | `未进入比较`                        |
| 4    | 纸面前推   | 纸面账户同版本信号/交易日                    | `18/30 信号 · 12/60 日` | `未开始` / `证据不足`               |
| 5    | 影子前推   | `shadow` 注册且 active                       | `已登记 · 第 9 日`      | `未登记` / `已暂停`                 |
| 6    | 晋级观察   | `eligible && promotion`；live 为独立人工开关 | `已晋级 · live 未开`    | `门槛未通过` / `已晋级 · live 已开` |

> 30 信号 / 60 交易日沿用现有前推门槛；不在本轮调整。live 不是第 7 阶段，而是第 6 阶段旁的独立授权开关，避免把「晋级」误读为「自动实盘」。

**视觉**：

- 横向 stepper：节点 20px 圆 + 标题 13px/20px + 状态 12px/18px；连接线 2px；总高 88px。
- 完成：实心 `--nc-accent` 圆 + 白勾；当前：白底 + 2px `--nc-accent` 环；阻断：`--nc-warn` 圆 + 感叹号；未开始：虚线灰圆。
- 节点下方一行证据 chip（最多 2 个），超出显示 `+N`；点击节点在下方展开证据表，不跳页。
- 右侧固定「当前结论」卡：`可晋级` / `卡在第 4 阶段：纸面前推 18/30`；下方列出最多 3 条次要原因，按现有 `reasons` 排序。
- 主操作按钮只在第 6 阶段且 `eligible` 时可用；不可用时按钮旁直接写原因，不用 tooltip 隐藏。

**响应式**：≥1280 横向 6 节点；1024–1279 两行 3+3；<1024 纵向列表，节点高 56px。

**验收**：六个阶段全部来自现有字段；缺证据显示「未开始」而非「通过」；主阻断原因唯一且可点击到证据；晋级按钮的可用性与服务端资格一致；不把 live 开关画成自动阶段。

### 3.7 双账重叠净敞口

**问题定义**（来自模块边界文档）：券商账本与手工账本都算真实账户；同一实际成交在两处登记时，全来源合计可能重复。

**设计原则**：不自动去重、不猜哪本账为准；先显示**区间**与**重叠明细**，把口径决定交给用户。

| 区域       | 内容                                                       | 规格                                                                                  |
| ---------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 汇总三格   | 毛合计 / 去重区间 / 行业集中度                             | 毛合计 = 券商 + 手工；去重区间 = `[max(券商, 手工), 券商 + 手工]`；每格标注「含重叠」 |
| 重叠提示   | `2 只标的两账均有，毛合计可能重复`                         | 琥珀色 inline banner；点击筛选重叠行                                                  |
| 明细表     | 标的、券商市值、手工市值、毛合计、去重区间、行业、重叠标记 | 数字右对齐、等宽；重叠行左侧 2px `--nc-warn`                                          |
| 行内区间条 | 64px 宽 mini bar：实心段 = 下限，斜纹段 = 可能重复         | 斜纹用 CSS repeating-linear-gradient；不只靠颜色                                      |
| 行业限额   | 现有 30% 行业限额按**上限**检查                            | 超限时提示「按上限口径超限；若两账为同一持仓，实际未超」                              |

**净敞口定义**：A 股与现货均无杠杆、无融券，净敞口 = 多头市值合计。加密按 USDT 单独汇总，不与 A 股相加；跨市场只显示分币种小计。

**交互**：

- 默认按「含重叠上限」显示，并在标题旁标 `含重叠`；用户可切换「券商为准 / 手工为准」查看下限，但**不持久化去重结论**。
- 点击重叠行展开两本账的成交/持仓来源与更新时间；若已有「关联成交」记录，显示 `已关联` 并给出关联回执入口。
- 不提供「一键删除手工账」；任何账本变更走现有导入/编辑流程。

**视觉**：汇总三格沿用 Ribbon 的标签/主值规格；banner 不使用红色；区间条高 8px、圆角 4px；表头 sticky；行高 44/36 随密度。

**验收**：存在重叠时绝不显示单一合计；区间下限/上限计算可手算复核；行业限额使用上限；切换「券商/手工」不改变底层数据；空账本显示 `—` 而非 `0`。

### 3.8 提醒 6 阶段诊断仪

**目标**：把「已启用但未发」收敛为一个可诊断的漏斗，而不是四五个页面的状态拼图。

**六阶段**（映射现有事件/订阅/渠道/投递/授权）：

| 阶段   | 检查                                 | 通过            | 阻断示例                     | 数据来源      |
| ------ | ------------------------------------ | --------------- | ---------------------------- | ------------- |
| 1 触发 | 是否有符合条件的信号/事件            | `今日 3 条事件` | `未到触发条件`               | 扫描/事件记录 |
| 2 入队 | 事件是否写入待投递                   | `已入队 3`      | `事件被去重/抑制`            | 通知队列      |
| 3 订阅 | 是否有启用订阅匹配该事件             | `2 个订阅命中`  | `无启用订阅`                 | 订阅配置      |
| 4 资格 | 运行模式、策略状态、渠道是否允许出站 | `shadow 允许`   | `live 未开启` / `渠道未配置` | 运行时/授权   |
| 5 投递 | 是否认领并发出                       | `已发出 2`      | `认领失败` / `重试中`        | 投递记录      |
| 6 回执 | 渠道是否确认                         | `2 成功`        | `1 失败：webhook 404`        | 投递结果      |

**视觉**：

- 右侧抽屉 480px（<1024 全屏）；顶部结论条 56px：`未发出：卡在第 4 步 资格`；下方 6 行，每行 56px。
- 每行：状态图标 16px + 阶段名 13px + 一行原因 12px + 时刻 11px + 「查看记录」链接。
- 状态：通过 `--nc-ok` 勾；阻断 `--nc-warn` 感叹号；等待 `--nc-text-4` 时钟；不适用 空心圆；未知 `?`。
- 颜色不单独表意：每行必须有文字结论；阻断行左侧 2px `--nc-warn`。
- 顶部提供时间范围（本次/最近 24h/自定义）与策略筛选；不新增渠道类型。

**交互**：从顶栏提醒 chip、系统页、策略中心三处可打开；打开时定位到主阻断阶段；点击「查看记录」打开现有投递/事件详情；支持 `Esc` 关闭、`↑↓` 切换行。

**验收**：任选一条「已启用未发」记录，诊断仪给出唯一主阻断阶段；六阶段均有数据来源或明确「不适用」；不把任务失败与投递失败混为一谈；不触发真实外发。

### 3.9 「舒适 / 专业紧凑」两档信息密度

**实现方式**：根节点 `data-density="comfort" | "compact"`，CSS 变量在同一 `tokens.css` 内扩展；组件只引用变量，不写死像素。切换入口在设置与命令面板，持久化到本地；默认 `comfort`，首次进入不强制。

| 参数          | 舒适（默认，对齐 `DESIGN.md`） | 专业紧凑 | 说明                      |
| ------------- | ------------------------------ | -------- | ------------------------- |
| 正文字号/行高 | 14 / 22                        | 13 / 19  | 不低于 13；表格内可 13/18 |
| 辅助文字      | 13 / 20                        | 12 / 17  | 最小 11px 仅用于标签/轴   |
| 页面标题      | 24 / 32                        | 20 / 28  | 页面内 h1                 |
| 章节标题      | 18 / 26                        | 16 / 23  | h2                        |
| 关键数值      | 28 / 36                        | 24 / 30  | Ribbon/汇总卡             |
| 表格行高      | 44                             | 36       | 表头 40/32                |
| 单元格内边距  | 10px 12px                      | 6px 10px | 数字列右对齐              |
| 卡片内边距    | 16                             | 12       | 圆角 8/6                  |
| 分区间距      | 24                             | 16       | 8px 网格                  |
| 侧栏宽度      | 216 / 56                       | 200 / 52 | 图标栏                    |
| 顶栏高度      | 56                             | 48       | 状态条同缩                |
| Ribbon 高度   | 64                             | 52       | 6 格                      |
| 控件高度      | 40 主 / 32 次                  | 36 / 28  | 点击目标不小于 24         |
| 图表工具栏    | 40                             | 34       | 按钮 32/28                |
| 图表轴标签    | 12                             | 11       | 缩放后不重叠              |
| 圆角          | 8                              | 6        | 按钮/卡片/输入一致        |
| 最大阅读列    | 840                            | 840      | 长文不随密度变宽          |

**数字排版规范**（两档共用）：

- `font-variant-numeric: tabular-nums lining-nums; font-feature-settings: "tnum" 1, "lnum" 1;` 数字列右对齐；单位放表头，不重复放单元格。
- 价格：A 股/ETF 2 位小数（ETF 按现有精度），加密 2–4 位按交易对现有精度；涨跌幅 2 位并带 `+/-`；金额 2 位 + `万/亿`，超 1 亿用 `亿`，超 1 万用 `万`。
- 同一列小数位一致；缺失显示 `—`；真实 0 显示 `0.00`；未知与 0 不混用。
- 负数用 ASCII `-`，不用全角；百分比与数字之间不加空格；`%` 紧贴数字。
- 代码/日志用 `ui-monospace, "Cascadia Mono", Consolas, monospace`；正文数字不用等宽字体，避免中英文基线跳动。

**视觉层级**：

- 同一屏最多 2 个强调色：`--nc-accent` 用于主操作/选中，`--nc-up/down` 仅用于涨跌与盈亏；警告/错误只在异常处出现。
- 表格不使用斑马纹；hover 用 `--nc-inset`；选中用 `--nc-accent-900`；分组行用 11px 大写标签 + 上边框。
- 焦点环 2px `--nc-accent`、偏移 2px；不用 `outline: none`。
- 动效 120–160ms `ease-out`；`prefers-reduced-motion` 下改为 0ms。

**验收**：两档切换后无布局错位/文字截断；表格行高与字号同步；1024 宽度下紧凑档仍可读；所有数字列等宽对齐；切回舒适档完全恢复 `DESIGN.md` 参数。
