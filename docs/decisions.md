## 2026-09-23：`src/components` 按业务域归档，保留 UI 与 workbench 基础层

组件不再堆在 `src/components` 根目录：行情、筛选、研究、回测、组合复盘、新闻、信号、盘中与公共业务组件分别归档，workbench 壳层集中在 `components/workbench`。所有仓内引用和结构型测试同步迁移，不保留旧路径兼容 re-export；`components/ui` 继续只承载薄 UI 原语。

用户在计划确认后明确授权“执行 plan”，覆盖 C1—C4 与 S0—S5，取代此前本轮仅规划的状态。代表 package 采用 `methodId` / `presetId` 和证据联合类型；根构建、开发与检查先生成 package dist，根测试显式追加 package 测试。研究页展示九方向，仅六个已有预设可填入原研究表单，不自动创建任务；三个仅有 method 的条目保留不可选择原因。

## 2026-09-22：纯策略基础能力下沉到独立核心包

交易策略服务实际需要复用 `src/lib` 的 K 线类型、完成时点和精确金额运算，但代表目录 package 的职责仍是证据元数据，不应承载运行时引擎。决定新增 `trading-strategy-core`，只放无数据库、文件系统、环境变量、Next.js、数据源和 DLL 依赖的纯能力；应用 `src/lib` 保留兼容转发，服务端策略直接依赖核心包。

| 操作 | 改前 | 改后 |
|---|---|---|
| 画线工具切换 | 16–21ms，每次重建 | 4–5ms，不重建 |
| 画线起点落下 | 14–22ms，每次重建 | 1.0–1.2ms |

## 2026-09-27：行情页新增分时图（F5）

**决策**：A 股证券可在 K 线与分时之间切换（按钮或 F5，跨证券保持模式）。分时按通达信样式：价格/均价线、昨收中轴、两轴对称、240 分钟固定横轴、分钟量着色、1–5 日（Alt+数字）。实时分时所属交易日由"实时昨收 = 前一交易日日线收盘"推出，不用时段时钟。

**依据**：通达信 F5 为分时/K 线切换、Alt+数字切换多日分时（通达信快捷键汇总）。实测：2026-09-27（周日，09-25 中秋休市）实时分时与 `historyMinutes(20260924)` 逐条一致、昨收 1251.24 等于 09-23 收盘，而 `historyMinutes(20260925)` 为空——若按"工作日即交易日"标注会把 24 日误标为 25 日或当天。

## 2026-09-30：一句话选股真实模型验收与三处修正（F1 收尾）

**事实**：用 DeepSeek（deepseek-v4-flash）跑 30 句验收，每轮约 3.3 万 token、35–45 s。第一轮门禁 30/30，粗语义检查 30/30，但逐条核对发现三类问题：
1. 面对资金流、市盈率、概念板块这类无法表达的需求，模型一边列入 unsupported，一边用成交量、收盘价拼近似公式；有一次甚至用"均线 + RPS + 放量"替代概念板块。
2. "创 20 日新低"写成 `L<LLV(L,20)`，由于 LLV 含当日，永不成立。
3. unsupported 被"未提及放量……"之类无关说明填满。

另外还有一个健壮性缺陷：模型对完全无法表达的需求可能返回空公式，结构校验连续两次失败后，整次生成直接报错。

**决策**：
- 提示词明确 HHV/LLV 含当日，给出创新高、新低的正确写法；
- 禁止用任何行情字段或技术条件近似、替代资金流、财务、估值、题材板块条件；
- unsupported 只列需求中提到的条件，默认假设写进解释；全都无法表达时输出 `0;`；
- 草稿允许空公式，服务端规范为 `0;`；
- 验收标准同步收紧：可表达的句子要求 unsupported 为空；无法表达的句子要求公式不引用任何行情或 RPS 字段；单句出错只记为失败，不中断整轮。

**结果**：修正后连续三轮，门禁 30/30，严格语义 27/30、29/30、30/30（验收线 80%）。剩余失败都是模糊说法（"回踩""底部平台""附近"）把定义上的保留意见写入 unsupported，属于如实说明；"今天涨停"统一按 10% 判定，模型也如实说明了无法区分 ST 和创业板/科创板的涨跌幅。

- 基线（真实数据：275 条新闻，46 份复盘报告，单份最大 97KB）：
  - 切到 `/news`：341 个节点，脚本 38–46 ms；切到 `/cls-review`：152 个节点，脚本 37–41 ms。
  - 打开报告 115 ms，报告列表翻页 91 ms（7KB），新闻翻页 55 ms，关键词检索 55–77 ms。
  - 隐藏时，这两个页面零请求。
- 结论：没有可复现的性能瓶颈。按计划“查不到问题就不做”，没有新增分页或高亮改动。新闻列表较长（7.6k px），属于阅读习惯问题，不是性能问题，暂不处理。
- 体检中顺带发现：`/market` 等 RPS 面板在任务已经完成后仍每 2 秒轮询一次 `rpsStatus`，65 秒内发出 32 次请求。改为任务运行时 2 秒一次、空闲时 30 秒一次（`rpsPollInterval`）；从页面发起的任务会立即 invalidate，因此进度显示不受影响。改后同一窗口只有 2 次请求。

## 2026-09-30：行情图可加一个联动周期，十字光标双向按时间对齐（第四轮 G4）

- 行情图下方新增“联动周期”选择（默认关闭），可以选同一快照的另一个周期（日/周/月/5/15/30/60 分钟）。副图固定 320px 高，不带缠论和突破标注。本次会话内记住上次的选择，与“分时 / K 线”的记忆方式一致。
- 对齐口径（`src/lib/chart/crosshair-link.ts`）：每根 K 线换算为结束时刻——分钟线用自带的 +08:00 时间戳，日/周/月线取当日 15:00 收盘；在对方图中找第一根结束时刻不早于该时刻的 K 线。分钟线与日线只在同一交易日内匹配，周/月线要求落在所属周期内；对方没有对应数据（如分钟数据较短，或超出已加载的历史）时清除光标，不会指到别的日子。目标 K 线不在可见区时，保持缩放不变，把它平移进视野。
- 性能：联动每一步脚本耗时 2.6–2.9 ms（上限 8 ms，写入 `perf-budgets.json` 的 `linkedCrosshairScriptMsPerStep`）。单图时不订阅联动，现有 e2e 和性能上限都不变。
- 验收：`tests/market-chart/chart/crosshair-link.test.ts`（30 分钟↔日、周归属、跨日不匹配）；`tests/e2e/chart-link.spec.ts`（日→周、周→日双向，以及每步耗时）。
