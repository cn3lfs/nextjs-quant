## 1. 目标与完成定义

用户要求：把 Codex 全局交易 skills 中每个有思路的方法做成策略，分批执行，效果交给后续回测判断。**不以主观评价、历史收益不佳或“这是分析 skill”为理由遗漏方法。**

本计划采用“一个独立思路一条记录”，不是“一个 skill 一个策略”。同一方法可以被多个 skills 引用；共享计算、保留全部来源，不重复造实现。一个 skill 有多个入场、退出或仓位思路时必须拆开登记。

最终每个思路须落入以下之一，并能说明去向：

- **完整策略**：证券池、信号、入场、退出、仓位、成交规则齐全，可以运行与回测。
- **可组合组件**：选股条件、市场过滤、退出、仓位或组合控制；必须有具名组合预设，可与相同基线做对照回测。只有函数或文字说明不算完成。
- **待数据策略**：规则和可执行适配完成，固定输入可验证；真实运行明确列出缺失数据和补齐任务。不能冒充已完成真实回测，也不能据此删除策略。
- **非策略资料**：纯查询、分类、术语、工具调用或教学解释，没有交易判断；记录服务哪些策略。若其中示例包含可执行选股条件，继续拆出模板，不能按工具类整体跳过。
- **超出当前交易品种的变体**：完整保留方法与依赖，单列后续市场批次。当前先落实沪深股票和相关境内股票 ETF；期权、期货、港美股等不伪装成 A 股交易。

交付分为“实现完成 / 数据可用 / 真实回测完成 / 效果结论”四列。亏损策略保留版本和结果，不从完成清单消失；缺失数据不填零，不以 LLM 想象补足。

### 3.2 量价：volume-price-analysis

- TM01：五维拥挤度上限过滤；TM02：拥挤后降仓；TM03：拥挤消退后恢复；TM04：各维度单独对照。仅电子、计算机、传媒、通信，融资项市场代理身份不变。
- GF01：gf-windmill 指数低估进入/高估退出；GF02：指数估值分位分档仓位；GF03：关联境内股票ETF组合。指数估值计算日期、历史窗口、ETF映射有效期缺失时不可回测。

MS/TM 可先附加在已有双突破或均线基线上；ETF 版在身份、上市时点与执行规则支持后接入。不把无法直接买卖的指数当成股票撮合。

### 3.11 新闻、消息、产业链与预期差

- EV01–EV08：swing-trader 的 expectation-gap 八象限，每格独立入场/持有/减仓/禁入规则，并保留个股、板块、市场作用范围。
- EV09：利好兑现后回撤；EV10：利空不跌的反转；EV11：消息与价格“钝化”；EV12：板块扩散和跨板块共振；EV13：退出后的价格确认回补。
- NW01：news-industry-analyst / news-sector-analyzer 的新闻密度热点；NW02：方向+可验证催化；NW03：新闻方向与估值分位组合；NW04：板块主线轮动。共用同一八象限实现，行业版阈值差异作为命名参数。
- ME01：message-analyst 真实性过滤；ME02：六类影响及供需/盈利传导事件；ME03：事件后价格确认；ME04：证伪/过期退出。
- IC01：industry-chain-analyst 五维景气排名；IC02：瓶颈环节；IC03：催化落地；IC04：长期逻辑/中期政策/短期催化组合；IC05：直接受益与间接受益对照。

news-industry-classifier 是这些策略的输入组件，不是独立买卖策略。原文的“temperature=0 可重现”不能作为工程保证：固定原始输入、prompt/模型版本和首次结构化结果，回放使用保存结果，不重新调用模型冒充同一次计算。

冻结消息发布时间、首次采集时间、公司/行业映射、模型处理时间。历史旧新闻可以做回溯性文本实验，但若使用今天模型、今天行业映射或缺首次可用时点，结果必须显式标注限制；可同步从未来前向积累，不能用当前搜索结果补写过去。

## 4. 实现方案：扩展现有链路

### 4.1 最小策略契约

以现有 Zod、纯函数和 worker 为基础，新增或扩展以下语义，不预建插件平台：

1. 策略身份：ID、中文名、家族、规则版本、来源文件hash、参数schema、所需数据、可运行周期/品种。
2. 判定结果：通过/不通过/数据不足/不适用，逐条件证据；事件时间、最早可知时间、确认时间分开。
3. 组合配置：基础信号 + 过滤 + 入场 + 退出 + 仓位 + 组合规则；每个具名预设冻结配置。
4. 持仓状态：等待入场、持仓、可卖份额、分批数量、保护价、加仓次数、退出等待和账户暂停。
5. 执行结果：交易意图、成交/拒绝原因、实际成交时间与价格、费用、现金、权益、未平仓、数据缺口。

指标继续共用 [indicators.ts](../src/lib/indicators.ts)，研究仍走 research-signals → research-portfolio / research-execution → research-run/store/worker。新策略统一注册供 API、选股、研究和页面使用，避免各处复制名字和分支；旧配置及存量结果可读，变更行为的新策略使用新版本。

### 4.2 时间与成交

- 日线收盘确认的事件，最早下一合法可成交时点成交；“信号收盘价买入”不得与当日最终数据同时使用。
- 结构极值需右侧确认的，事件时间使用确认点；追加未来行情不能修改已经输出的当时决策。
- 买卖/止盈止损同一根K线同时命中且无更细数据时，采用显式保守顺序或标记路径不确定，不能取最有利路径。
- 跳空止损按实际可成交价、停牌/涨跌停按可成交规则；连续无法卖出保留持仓与尝试记录。
- 仓位、整手、费用、资金不足、排序、同日多信号、部分卖出均为确定性规则。加仓后分别追踪可卖日期。
- 信号复权、成交原始价、公司行动继续遵循已有 W1 研究口径与拒绝范围；图表口径不直接代替研究口径。
- 实施交易规则变更时核对当期官方规则及历史生效日；本计划不新增未经验证的具体交易法规参数。

### 4.3 数据与版本

行情、财务、行业、机构、事件、估值均带 source / effectiveAt / availableAt / capturedAt；报告期不是披露日，今天修订的财务值不冒充过去值。首次采集与市场公开可知时间分别保留。当前池回溯与历史成分池研究明确区分。

缺数据的策略允许代码先交付、固定fixture验证、前向观察开始；真实历史回测保持不可用和原因。付费数据不能静默采购。现有数据源适配优先复用，不让一个外部数据缺口阻塞全部价量批次。

LLM仅提取预定义结构，不执行生成代码；JSON结构、枚举、数值范围、证据定位均校验。主观命题拆成可冻结的观察量、触发条件、失效条件与最长等待期；不能把“看好”“逻辑强”直接当无条件买入。

### 4.4 产品入口

扩展现有工作台，提供策略家族、具体预设、参数、数据要求和状态。每个已实现预设至少能：选范围 → 扫描 → 查看逐条件证据 → 创建回测任务 → 查看/导出结果。缺数据提示具体字段和覆盖区间。

结果同时显示固定持有期事件研究与完整交易策略回测，二者不同标题；过滤/风控组件显示与同一入场基线的配对比较。任务中心复用进度、取消与保存结果入口；不为每种策略新建独立页面，不增加无必要轮询。旧报告入口保留，不能把报告中的 BUY 直接送到执行器。

## 7. 回测设计与判断方式

### 7.1 先检验实现，再判断效果

第一轮固定原文参数或已登记工程默认，不为了好看边跑边改。先做小样本逐笔核对，再用有覆盖的历史区间运行；完整记录规则失败、零交易、亏损、无法成交与缺失。测试通过只是程序证据，不是盈利证据。

### 7.2 公平对照

- 同一证券池、可知时点、区间、公司行动口径、成本、现金和成交规则；保留现金基线、买入持有基线及现有双突破/均线基线。
- 信号本身用固定持有期收益/超额/MAE/MFE观察；交易策略另看净值、回撤、换手、费用、仓位、胜率、盈亏比、持有期和未平仓。
- 风控/过滤组件共用相同入场事件。增加过滤减少样本或延迟成交时如实展示；统计比较提供原始与共同可用样本两种口径。
- 信号相同但退出/仓位不同仍是不同候选试验；不能只登记最佳那一个。

### 7.3 训练、验证和前向

复用现有 research-governance、research-usage、walk-forward、multiple-testing 和三段样本能力，按输入适配性接入，不盲目给所有策略套同一统计量。开发段定规则/参数，保留验证段评估，前向记录使用真实观察时点。长持有、重叠交易、稀疏信号的限制单列。

参数敏感性采用预先登记的小网格；先单因子/单组件，再少量原文组合。原文胜率、凯利映射和目标价不是经验证的概率。指标不可计算时返回 null 和原因，不选择性删除负面结果。

### 7.4 最终结果标签

结果可为“当前样本表现较好 / 表现较差 / 不稳定 / 样本不足 / 数据不足 / 无交易 / 规则实现失败”。这些标签不删除策略。是否实用由回测证据和用户判断决定；本计划不设收益及夏普的开发准入门槛。

## 8. 工程验收与交付纪律

> **2026-09-16 更新**：验证节奏改为[优化方案](2026-09-16/07-trading-skills-execution-optimization.md) §5 的三层规则——L1 改动级只跑定向测试与契约套件，L2 子任务级加 typecheck 与家族测试，**全量测试、完整 build 与 Playwright 每批各一次**（触及共享执行引擎、注册聚合器、indicators 或数据库迁移时批内追加一次全量）。下列测试重点、隔离与授权约束全部保持不变。

- 每个小改动：相关 Vitest、typecheck；每批：pnpm test；有意义的应用交付：pnpm build；runtime改动重建worker；桌面交付前 desktop:prepare。依赖实际脚本核对执行。
- 测试重点：条件边界、未知传播、追加未来数据不改过去、财报晚披露/修订、新闻去重/时间、停牌/涨跌停、跳空、同K线冲突、T+1分批仓、资金守恒、排序稳定、取消与保存。
- 真实浏览器检查新增策略选择、证据、参数、任务进度/取消、结果和导出；环境失败记录具体原因，不把固定fixture界面检查说成真实策略数据验收。
- 所有可能打开数据库的验证先设隔离 QUANT_DATA_DIR；行情/Blocks只读。临时数据位于具名隔离目录并说明清理，不重建 output。
- 新增迁移确需时再实施，说明旧exe兼容影响；不预先为清单设计复杂数据库平台。
- 不修改用户维护的 src/server/mcp.ts 及其UI文案；需要数据工具时复用既有调用边界，若必须交接再明确列出。
- 各批报告：完成ID、仍缺ID及原因、真实测试数量、代码/数据/回测状态、下一批。未授权不提交、推送、打包或发送消息。
